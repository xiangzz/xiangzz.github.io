LoRA 参数高效微调

阶段 5 · 只训练不到 1% 的参数，就能获得接近全量微调的效果

微调太贵了

你花了两周在 8 张 GPU 上完成了 SFT 微调。现在想针对医疗领域再微调一次。

但全量微调意味着 64M 个参数全部要重新训练。每个新领域都重来一遍？

LoRA（Low-Rank Adaptation）就是为此而生的：在原始权重旁加一条"小路"，训练参数不到原始的 1%，效果几乎不输全量微调。

全量 vs LoRA

Part 1：核心思想

低秩分解——用两个小矩阵近似一个大矩阵的变化量。

全量微调需要更新模型的所有参数，代价高昂。LoRA 的洞察是：大模型在微调时，参数的变化量其实是"低秩"的——不需要那么多自由度。用两个小矩阵在旁边搭一条"旁路"，就能以极少的参数量达到接近全量微调的效果。

  • 低秩分解旁路原理——不改动原始权重 W，在旁边加 B·A，等效变化为 W' = W + B·A
  • 参数量对比——rank=16 时，LoRA 只需要全量微调约 4.2% 的参数量

低秩分解旁路

不修改原始权重，而是在旁边加一条"小路"

定义：LoRA 在原始权重矩阵 W 旁添加低秩分解矩阵 B·A，等效权重变为 W' = W + B·A。

说白了，原始权重像一条主路，LoRA 像一条绕行的辅路。两条路的输出加在一起就是最终结果。训练时只修辅路，主路不动。

这个比喻只是为了帮你建立直观感受。在计算机内部，LoRA 实际上是两个线性变换的串联——先把维度从 d 压缩到 r（A 矩阵），再从 r 还原到 d（B 矩阵），没有真正的"路"。

Part 2：65 行代码的秘密

整个 LoRA 实现只有 65 行代码——一个类加四个函数。我们逐一理解它们各自解决什么问题。

LoRA 的原理很简单，但工程实现里有不少巧妙的细节——比如为什么要故意把 B 初始化为零、怎么用 monkey-patch 把 LoRA 注入到已有模型里、训练完怎么把旁路合并回原始权重。理解这些细节，你才能真正"用"好 LoRA。

  • LoRA 类定义——两个无偏置的线性层串联，结构极简
  • 初始化策略——B 矩阵初始化为零，保证训练起点和原始模型完全一致
  • apply_lora 注入——用 monkey-patch 把 LoRA 层替换到模型中
  • 保存与加载——save_lora / load_lora 只处理 LoRA 部分，体积极小
  • merge_lora 合并——训练结束后把 B·A 加回原始权重，推理零开销

LoRA 类定义

两个无偏置的线性层串联，仅此而已

class LoRA(nn.Module):
    def __init__(self, in_features, out_features, rank):
        super().__init__()
        self.rank = rank  # 秩，控制低秩矩阵大小
        self.A = nn.Linear(in_features, rank, bias=False)  # (d, r) 降维
        self.B = nn.Linear(rank, out_features, bias=False)  # (r, d) 升维
        # A 高斯初始化
        self.A.weight.data.normal_(mean=0.0, std=0.02)
        # B 全零初始化
        self.B.weight.data.zero_()

    def forward(self, x):
        return self.B(self.A(x))  # x → A(x) → B(A(x))

为什么 A 用高斯初始化、B 用零初始化？B=0 所以训练开始时 LoRA(x) = B(A(x)) = 0。模型从"不加任何修改"的状态起步，训练初期行为与原始模型完全一致。

注入 LoRA

遍历所有方形 Linear 层，逐个注入旁路

def apply_lora(model, rank=16):
    for name, module in model.named_modules():
        # 只对方形线性层注入（Q/K/V/O 投影、FFN 层）
        if isinstance(module, nn.Linear) and \
           module.weight.shape[0] == module.weight.shape[1]:
            lora = LoRA(module.weight.shape[0],
                        module.weight.shape[1],
                        rank=rank).to(model.device)
            setattr(module, "lora", lora)
            original_forward = module.forward

            def forward_with_lora(x, layer1=original_forward, layer2=lora):
                return layer1(x) + layer2(x)

            module.forward = forward_with_lora  # monkey-patch

为什么只选方形层？因为 Q/K/V/O 投影和 FFN 层是 (d, d) 的方形矩阵。Embedding 和 lm_head 不是方形，不注入。

保存与加载

只保存 LoRA 参数，文件极小（~50KB）

# 保存——只提取 lora 参数
def save_lora(model, path):
    raw_model = getattr(model, '_orig_mod', model)
    state_dict = {}
    for name, module in raw_model.named_modules():
        if hasattr(module, 'lora'):
            lora_state = {
                f'{name}.lora.{k}': v.cpu().half()
                for k, v in module.lora.state_dict().items()
            }
            state_dict.update(lora_state)
    torch.save(state_dict, path)

# 加载——找到对应 LoRA 恢复权重
def load_lora(model, path):
    state_dict = torch.load(path, map_location=model.device)
    for name, module in model.named_modules():
        if hasattr(module, 'lora'):
            lora_state = {
                k.replace(f'{name}.lora.', ''): v
                for k, v in state_dict.items()
                if f'{name}.lora.' in k
            }
            module.lora.load_state_dict(lora_state)

合并权重

推理时把 LoRA 溶入原始权重，零额外开销

def merge_lora(model, lora_path, save_path):
    load_lora(model, lora_path)
    raw_model = getattr(model, '_orig_mod', model)
    state_dict = {}
    for name, module in raw_model.named_modules():
        if isinstance(module, nn.Linear) and '.lora.' not in name:
            state_dict[f'{name}.weight'] = module.weight.data.clone().cpu().half()
            if hasattr(module, 'lora'):
                # W' = W + B @ A
                state_dict[f'{name}.weight'] += \
                    (module.lora.B.weight.data @ module.lora.A.weight.data).cpu().half()
    torch.save(state_dict, save_path)

与全量 SFT 的差异

① 冻结原始参数

非 LoRA 参数的 requires_grad 设为 False，反向传播时不计算梯度。

② 优化器只含 LoRA

③ 保存仅 LoRA 权重

文件极小（~50KB vs 全量 ~100MB+），方便分发和切换。

训练循环精讲

与全量 SFT 几乎相同，只改了两处

def train_epoch(epoch, loader, iters, lora_params, start_step=0):
    for step, (input_ids, labels) in enumerate(loader, start=start_step + 1):
        # 学习率调度、前向、loss 计算与全量 SFT 一致
        with autocast_ctx:
            res = model(input_ids, labels=labels)
            loss = (res.loss + res.aux_loss) / args.accumulation_steps

        scaler.scale(loss).backward()

        if step % args.accumulation_steps == 0:
            scaler.unscale_(optimizer)
            # ⬇️ 区别 1：梯度裁剪只作用于 LoRA 参数
            torch.nn.utils.clip_grad_norm_(lora_params, args.grad_clip)
            scaler.step(optimizer)
            scaler.update()
            optimizer.zero_grad(set_to_none=True)

        if step % args.save_interval == 0 and is_main_process():
            # ⬇️ 区别 2：只保存 LoRA 权重
            save_lora(model, lora_save_path)

Part 4：使用场景

什么时候用 LoRA，什么时候全量微调？

LoRA 不是万能药，全量微调也不是银弹。选择哪种方式取决于你的场景——数据量多大、显存多少、是否需要同时服务多个领域。这一节帮你做决策，并给出可以直接跑的训练命令。

  • LoRA 适用场景——多领域适配、资源受限、快速实验迭代
  • 数据格式——和全量 SFT 完全相同的 JSONL 格式，零迁移成本
  • 完整训练命令——一行命令跑通 LoRA 微调

LoRA 适用场景

多领域适配

一个基础模型 + 多个 LoRA 权重（医疗、法律、客服），按需切换。

资源受限

只有消费级 GPU（如 RTX 3090），全量微调放不下。

快速实验

验证数据集或超参数是否有效，LoRA 训练更快。

何时不用 LoRA？基础模型能力不足时（预训练不充分），LoRA 改进空间有限，应先全量 SFT。

LoRA 训练中你可能遇到的坑。

LoRA 看起来简单，但实际跑起来可能遇到各种奇怪的问题——LoRA 好像没生效？Loss 死活不下降？合并后效果反而变差了？别慌，这些问题都有套路可解。最后再通过练习巩固理解，把知识变成自己的。

  • 常见错误诊断——LoRA 没生效、Loss 不下降、合并后效果差、compile 报错的排查思路
  • 动手练习——手工计算 LoRA 参数量、理解初始化为什么这样设计

常见错误诊断

LoRA 没生效

症状：loss 曲线与全量 SFT 一致

原因：apply_lora() 没调用，或优化器用了 model.parameters()

修复：检查第 129 行和第 151 行

Loss 不下降

症状：10 轮 loss 没变化

排查：① 确认 requires_grad 正确；② 学习率 1e-4 是否合适；③ 数据格式是否正确

合并后效果差

症状：merge_lora 后推理结果不对

原因：设备不一致（GPU 权重 vs CPU 保存）

修复：确保 merge 时张量在同一设备

compile 报错

症状：RuntimeError: mutated variable

修复：代码已自动关闭 compile（163-165 行），手动改过则确保为 0
