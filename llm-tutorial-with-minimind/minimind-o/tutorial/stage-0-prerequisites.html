Part 1：Python

读懂模型代码，比语法更重要的是这三件事。

MiniMind-O 的代码大量使用了 Python 的三个特性：类的继承、生成器 yield、上下文管理器 with。它们不是炫技，而是模型代码能写得这么简洁的关键。

  • 类与继承 —— 为什么模型类能「自动」拥有保存、加载、生成的能力
  • yield 生成器 —— 流式输出（打字机效果、实时语音）的全部秘密
  • with 上下文管理器 —— 一行代码切换「要不要算梯度」「要不要用半精度」

类与继承

在 PyTorch 里，所有模型都继承自 nn.Module。这意味着你只要写一个 forward 方法，就白捡了一整套能力：参数管理、移动到 GPU、保存加载、梯度追踪。

import torch.nn as nn

class RMSNorm(nn.Module):           # 继承 nn.Module
    def __init__(self, dim):
        super().__init__()          # 调用父类初始化，激活那套白捡的能力
        self.weight = nn.Parameter(torch.ones(dim))

    def forward(self, x):           # 只定义「前向怎么算」
        return self.weight * x / torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + 1e-5)

norm = RMSNorm(768)
norm = norm.to("cuda")              # 这行能跑，全靠继承来的 .to() 方法

super().__init__() 这一行的意义：它「唤醒」了父类 nn.Module 的初始化逻辑（建立参数容器、注册子模块）。漏写它，.to()、.parameters() 全都会失效。

MiniMind-O 继承链

全模态模型 MiniMindOmni 之所以能调用 generate() 生成文本，不是因为它自己写了这个方法，而是因为它继承自 MiniMindForCausalLM，后者又混入了 HuggingFace 的 GenerationMixin。

记住这条规律：看到一个陌生方法，先去父类里找——它多半是继承来的，而不是这段代码新写的。

yield 生成器

普通函数 return 一次就结束。把 return 换成 yield，函数就变成了一个生成器：每次吐出一个值，然后暂停，等下一次被调用时再从暂停处继续。

def simple_generate():
    for token in ["你", "好", "，", "世", "界"]:
        yield token            # 吐出一个，暂停在这里

# 像拧水龙头一样，一次接一点
for token in simple_generate():
    print(token, end="")       # 逐字打印：你好，世界

这正是流式输出的原理：模型每算出一个 token 就 yield 出去，调用方立刻能打印或播放，不必等整句话算完。MiniMind-O 的 stream_generate() 就是这样一个生成器——它同时 yield 文本 token 和音频帧。

with 上下文管理器

with 块会在进入时做一件事，离开时自动做相反的事。在模型代码里，它最常用来切换运行模式。

# 推理时：进入 with 关掉梯度计算（省内存、加速），离开时自动恢复
with torch.no_grad():
    output = model(input_ids)   # 这里面不算梯度

# 训练时：进入 with 切到半精度，离开时自动恢复全精度
with torch.cuda.amp.autocast(dtype=torch.bfloat16):
    output = model(input_ids)
    loss = criterion(output, labels)

为什么推理要用 no_grad？ 训练时 PyTorch 会默默记录每一步运算，用于反向传播算梯度——这套记录很占内存。推理不需要梯度，关掉它能让显存占用直接砍半。

读代码，指认特性

class TinyChat(MiniMindOmni):          # ？
    def stream_chat(self, prompt):

            for t, audio in self.stream_generate(prompt):  # ？
                yield t, audio          # ？

参考答案

Part 2：训练四动作

把所有花哨的术语剥掉，训练一个模型就是在反复做这四件事。

不管模型多复杂——Transformer 也好、全模态也好——它的训练循环永远是同一个套路：把数据喂进去算预测（前向）→ 比一比差多少（损失）→ 倒推该往哪调（反向）→ 真的调一下（更新）。MiniMind-O 的训练脚本，本质就是这个循环跑了成千上万次。

训练循环：四拍子

图：深度学习训练循环的四个动作

【AI 生图提示词】请生成一张中文技术示意图，风格简洁、配色柔和、适合教学： - 画面主体：一个顺时针循环的环形流程图，由四个圆角矩形节点组成，箭头首尾相连形成闭环 - 四个节点依次为：① 前向传播 Forward（模型根据输入算出预测）② 计算损失 Loss（比较预测和真实答案的差距）③ 反向传播 Backward（从损失倒推每个参数的梯度）④ 更新参数 Step（沿梯度反方向微调参数） - 关键标注：环中央写「每个 batch 重复一次」；①号节点旁标 input_ids 输入；②号节点用红色强调「损失值 loss 越小越好」；③号节点旁画一个小箭头表示「梯度反向流动」；④号节点旁标 optimizer.step() - 配色建议：浅灰背景，四个节点分别用浅蓝、浅红、浅紫、浅绿，箭头深灰色，中央文字橙色 - 画面比例：1:1（正方形）或 16:9 

for step, batch in enumerate(loader):
    output = model(batch.input_ids)          # ① 前向
    loss = criterion(output, batch.labels)   # ② 损失
    loss.backward()                          # ③ 反向（自动算梯度）
    optimizer.step()                         # ④ 更新
    optimizer.zero_grad()                    # 清空梯度，为下一轮做准备

注意顺序：backward 一定要在 step 之前。先算出「该往哪走」（梯度），再「迈出这一步」（更新参数）。

损失：把「差多少」变成一个数

模型预测的是「6400 个词各自的可能性」（一组概率），真实答案是「正确的那个词」（一个 ID）。损失函数的工作，就是把这二者的差距压成一个标量数字——模型接下来所有努力，都是为了让这个数字变小。

MiniMind-O 用的是交叉熵损失 CrossEntropyLoss，专门处理「从一堆选项里挑正确那个」的分类问题。

# 模型在每个位置预测 6400 个词的概率
predicted = torch.randn(2, 10, 6400)   # 2 个样本，每个 10 个位置，每个 6400 个候选词

# 真实答案：每个位置的正确词 ID
true_ids = torch.tensor([[5, 12, 8, ...], [3, 9, 1, ...]])  # 形状 (2, 10)

# 交叉熵：自动比较「预测的概率分布」和「正确答案」
loss = torch.nn.functional.cross_entropy(predicted.view(-1, 6400), true_ids.view(-1))
# loss 是一个标量，比如 5.37，越小越准

梯度下降：蒙眼下山

训练模型的本质，是在一个巨大的「损失地形」上找最低点。你看不见全貌（地形太复杂），只能用脚感受当前的坡度（梯度），然后朝最陡的下坡方向迈一小步——如此反复，直到走到谷底。

图：梯度下降「蒙眼下山」的直觉

【AI 生图提示词】请生成一张中文技术示意图，风格简洁、配色柔和、适合教学： - 画面主体：一个二维的「损失地形」截面图，横轴为某个参数值，纵轴为损失值，地形呈波浪起伏的曲线，有一个明显的谷底 - 在曲线左侧较高处画一个小人（蒙眼），表示当前参数位置；从该点画一系列小箭头，沿曲线逐步指向谷底，每个箭头标注「一步」 - 关键标注：曲线纵轴标注「损失 Loss（越低越好）」；小人旁边标注「当前位置，用脚感受坡度=梯度」；箭头方向标注「朝梯度反方向走」；谷底标注「目标：损失最小」 - 在右上角小框补充：步子大小 = 学习率 learning rate，太大跨过谷底，太小走得太慢 - 配色建议：浅灰背景，损失曲线用深蓝色，小人用橙色，箭头用绿色，谷底用浅绿色高亮 - 画面比例：16:9

学习率就是「每步迈多大」。MiniMind-O 训练时学习率从 5e-4 开始，太大模型会震荡发散，太小训练到天荒地老。

卸掉这个比喻：下山只是为了帮你建立直觉。真实的损失地形不是二维曲线，而是几千万维空间里的曲面（每个可训练参数是一维）；「坡度」就是损失对这些参数的偏导数组成的向量（梯度）；「迈一步」就是 参数 = 参数 - 学习率 × 梯度。而且真实曲面通常非凸、有多个局部谷底，梯度也只是当前点的局部近似——所以训练才需要学习率调度、动量这些技巧来避免卡在半山腰。

Part 3：张量形状

读模型代码时，比公式更重要的是盯住每个张量的形状。

深度学习里所有数据都是张量（Tensor）——就是多维数组。读懂模型的关键技能不是懂微积分，而是能在脑子里追踪「数据流经每一层时，形状怎么变」。MiniMind-O 的代码里几乎每一步都隐含着形状约定，看懂形状，就懂了一半。

从标量到张量：维度就是含义

名字维度例子含义
标量0 维5一个数（如损失值）
向量1 维[1, 2, 3]一串数（如一个词的向量）
矩阵2 维(10, 768)10 个词，每个 768 维
张量3 维+(2, 10, 768)2 个句子，每句 10 词，每词 768 维

每一维都不是随便定的，它编码了某种含义。看到 (B, T, 768)，你不应该只看到三个数字，而要看到「B 个样本、每个 T 个位置、每个位置 768 维特征」。

常见张量形状

张量形状每一维的含义
input_ids(B, T)B 个样本，每个 T 个 token
hidden_states(B, T, 768)每个 token 被表示成 768 维向量
text_logits(B, T, 6400)每个位置对 6400 个词的打分
audio_logits(B, T, 2112)每个位置对 2112 个音频码的打分
audio_codes(8, T)8 层码本，每层 T 个整数

B = batch size（一次处理几个样本），T = sequence length（序列有几个 token）。这两个字母会贯穿全书，记住它们。

调试模型时，最高效的手段是在关键位置 print(x.shape)——形状对了，逻辑通常就对了一大半。

Part 4：PyTorch

整个 MiniMind-O，就是这三类积木搭起来的。

PyTorch 有几百个 API，但搭出一个现代模型，反复用到的核心积木就那么几个。nn.Module（积木的基类）、nn.Linear（做线性变换的全连接层）、nn.Embedding（把整数变成向量的查表）。认清这三张面孔，模型代码就从天书变成乐高说明书。

nn.Linear 线性变换

nn.Linear(in, out) 做的事极其朴素：把一个 in 维向量，通过一个可学习的矩阵，变换成 out 维向量。整个 Transformer 里的 Q/K/V 投影、输出头，本质都是它。

proj = nn.Linear(768, 6400)     # 把 768 维 → 6400 维
x = torch.randn(1, 10, 768)     # 1 个句子，10 个词，每词 768 维
y = proj(x)                     # 形状变成 (1, 10, 6400)
# 参数量 = 768 × 6400 + 6400 ≈ 4.9M

「768 → 6400」这样的注释在模型代码里随处可见——它永远在告诉你「这一层把几维变成几维」。

nn.Embedding查表

模型不认识汉字，只认数字。但光有数字 ID（比如「你」=47）还不够——47 这个数本身没有意义。 nn.Embedding 就是一张大表：用 ID 当行号，取出对应的那一行向量。

embed = nn.Embedding(6400, 768)  # 6400 行（词表大小），每行 768 维
ids = torch.tensor([47, 892, 15])  # 三个 token 的 ID
vectors = embed(ids)             # 取出 3 个 768 维向量，形状 (3, 768)

图：Embedding 查表——用 ID 当行号取向量

输入侧与输出侧

Linear 与 Embedding

nn.Embedding(6400, 768)

输入是整数 ID，输出是向量。

实现就是「按行号取一行」，本质是查表。

用在「输入侧」：把 token 变成向量。

nn.Linear(768, 6400)

输入是向量，输出是向量（这里 6400 维打分）。

实现是矩阵乘法 x @ W + b。

用在「输出侧」：把向量变成对每个词的打分。

一个有趣的细节：MiniMind-O 让输入侧的 Embedding 和输出侧的 Linear 共享同一份权重（这叫 tied weights）。既然都是「768 维 ↔ 6400 个词」的映射，用一张表就够了，省下一半参数。

nn.Module 基类

无论是 Linear、Embedding，还是整个 Transformer，都继承自 nn.Module。一个 Module 可以包含别的 Module，层层嵌套——这就是模型代码的组织方式。

class MiniMindBlock(nn.Module):
    def __init__(self):
        super().__init__()
        self.attention = Attention()      # 子模块
        self.feed_forward = FeedForward() # 子模块
        self.norm = RMSNorm(768)          # 子模块

    def forward(self, x):
        x = x + self.attention(self.norm(x))   # 残差连接
        x = x + self.feed_forward(self.norm(x))
        return x

调用 model.parameters() 时，PyTorch 会自动递归收集所有嵌套子模块的参数——你不需要手动维护参数列表。

Part 5：三种模态

全模态模型的第一道难关：文本、音频、图像怎么都变成模型能消化的数字？

MiniMind-O 叫「全模态」，因为它同时处理三种截然不同的输入。但模型底层只认向量——所以三种模态都得先经过一道「翻译」，变成同一空间的向量，才能拼到一起。这一节建立这个核心直觉，它是阶段 3 全模态模型的前置知识。

文本切 token

文本的翻译你已经熟悉了（详见 Tokenizer 章节）：先用分词器把句子切成 token，每个 token 是一个整数 ID，再用 Embedding 查表变成向量。

"你好，世界"  ──分词──▶  [47, 892, 15, 1024, 2]  ──查表──▶  (5, 768) 向量

文本是离散的、有清晰边界的——一个词就是一个 token，干净利落。

音频：先采样，再切成码本

声音本质是连续的空气振动。计算机没法存「连续」，只能每隔极短的时间测一次振幅——这就是采样。每秒测 16000 次，就是 16kHz 采样率，一秒音频变成 16000 个数字。

import soundfile as sf
waveform, sr = sf.read("hello.wav")   # waveform: 一串振幅值，sr: 采样率(如 16000)
# 1 秒音频 ≈ 16000 个浮点数，形状约 (16000,)

但 16000 个数太长了。MiniMind-O 用一个叫 Mimi 的音频编解码器，把长长的一串振幅压缩成少数几个离散码——而且是 8 层叠加的码本。

图：音频从波形到 8 层码本的压缩过程

为什么音频要 8 层码本？

这是 MiniMind-O 最容易让新手困惑的点。答案是分层表达：

码本层承载的信息类比
第 0 层（最底层）基本音高、能量句子的「骨架」
中间层音色、共振句子的「血肉」
第 7 层（最高层）细微的语义细节句子的「表情」

8 层叠在一起，才能高保真地还原一段语音。少了高层，声音还能听但细节糊；少了底层，连基本音高都对不上。这正是 Talker 要同时预测 8 层码本的原因。

图像切 patch

图像是像素的二维网格。MiniMind-O 用 SigLIP2 这个视觉编码器：先把一张 256×256 的图切成 8×8 = 64 个小方块（patch），每个 patch 被编码成一个向量。

256×256 图像  ──切 64 个 patch──▶  64 个向量  ──SigLIP2 编码──▶  (64, 768) 向量

于是，一张图也变成了一串向量——和文本、音频统一了形式。64 个 patch token，就像 64 个「视觉词汇」。

练习一：追踪一个形状

形状推理

一段文本经过 Embedding 后形状是 (1, 12, 768)，再经过一个 nn.Linear(768, 6400)，输出形状是什么？每个维度代表什么？

参考答案

输出形状是 (1, 12, 6400)。1 = 一个样本（batch size=1）；12 = 12 个 token（序列长度）；6400 = 每个位置对词表 6400 个词的打分（logits）。Linear 只改变最后一维，把 768 维特征「翻译」成 6400 个打分。

练习二：补全训练四拍子

填空

下面这段训练循环缺了关键步骤，请按正确顺序补上 loss.backward() 和 optimizer.step()。

output = model(batch.input_ids)
loss = criterion(output, batch.labels)
# ???
# ???

参考答案

先 loss.backward()（反向传播算梯度），再 optimizer.step()（用梯度更新参数）。顺序反了就错——必须先知道「往哪调」，才能「真的调」。最后通常还跟一句 optimizer.zero_grad() 清空梯度。

练习三：模态匹配

把左边的模态和右边「把它变成向量的方式」连起来。

模态翻译方式
文本「你好」?
一段语音?
一张图片?

候选：① SigLIP2 编码成 64 个 patch 向量　② Tokenizer 分词 + Embedding 查表　③ Mimi 压缩成 8 层码本再投影

答案：文本→②，语音→③，图像→①。三者最终都变成 768 维向量，才能进入同一个 Transformer。

关键要点回顾

三个 Python 武器

继承（白捡能力）、yield（流式输出）、with（自动切换模式）。读懂模型代码的钥匙。

训练四拍子

前向 → 损失 → 反向 → 更新。所有深度学习训练都是这个循环的重复。

盯住形状

(B, T, 768) 不是三个数，是「B 个样本、T 个位置、768 维特征」。形状对，逻辑就对一半。

三张积木面孔

nn.Module（基类）、nn.Linear（线性变换）、nn.Embedding（ID 查表）。整个模型就是它们的嵌套。

模态统一的戏法

文本、音频、图像最终都被翻译成 768 维向量，送进同一个 Transformer。

音频的特殊性

语音被 Mimi 压缩成 8 层码本——从音调到细节分层表达，这是 Talker 同时预测 8 层的根源。
