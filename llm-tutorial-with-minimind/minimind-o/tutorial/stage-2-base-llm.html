一个 LLM 到底在做什么

阶段 2 · 拆解 Thinker 的骨架——现代 Transformer 的全部精华

LLM 只做一件事

把所有神秘感剥掉，LLM 只做一件事

大语言模型听起来玄乎，但它的核心行为简单到让人意外：根据已经出现的词，猜下一个最可能出现的词。

输入: "今天天气真"
模型预测下一个词: "好"      ← 概率最高

输入: "今天天气真好，我们去"
模型预测下一个词: "公园"    ← 概率最高

就这么一个动作，重复成千上万次，就「生成」了一段话。ChatGPT 如此，MiniMind-O 的 Thinker 也如此。所谓「理解语言」，本质就是「把下一个词猜得足够准」。

本章要回答的唯一问题：它是怎么猜的？——也就是 Transformer 架构。我们把 Thinker 拆成零件，逐个讲清楚每个零件为什么存在。

整章就在解释这条流水线上的每个环节。我们先从最关键的「注意力」讲起，它是 Transformer 的灵魂。

Part 1：注意力

这是 Transformer 区别于一切旧架构的核心发明。

如果不讲注意力，后面的位置编码、残差、归一化都无从谈起。所以把它放在第一个，而且花最多篇幅。理解了注意力，Transformer 就懂了 80%。

注意力解决的是什么问题

读这句话：「小明喜欢打篮球，他经常在周末和朋友们去球场。」

当你读到「他」时，大脑会自动把「他」和「小明」联系起来——你知道「他」指代的是小明，不是篮球。这种「根据当前内容，找到最相关的其他内容」的能力，就是注意力。

图：注意力的直觉——词与词之间的「相关性」

【AI 生图提示词】请生成一张中文技术示意图，风格简洁、配色柔和、适合教学： - 画面主体：一句话「小明喜欢打篮球，他经常去球场」横排展示，每个词是一个方块 - 在「他」这个词上画一个发散的连线，连向「小明」（粗线、橙色，标注「高注意力」），连向「球场」「篮球」（细线、灰色，标注「低注意力」） - 连线的粗细表示注意力权重的强弱 - 关键标注：在「他」下方标注「当前词，正在『看』其他词」；在连线旁标注「注意力权重 = 相关程度」 - 配色建议：浅灰背景，词方块浅蓝色，「他」用橙色高亮，强注意力连线橙色粗线，弱注意力灰色细线 - 画面比例：16:9

模型要做的，就是让每个词都学会「该关注句子里的哪些其他词」。问题来了：模型怎么量化「相关程度」？

Q/K/V 三角色

Query、Key、Value：一个图书馆的比喻

注意力机制借用了信息检索的思路。每个词同时扮演三个角色：

角色含义图书馆比喻
Query（查询）「我想找什么样的信息」你递给图书管理员的检索词
Key（键）「我能提供什么样的信息」每本书封面上的标签
Value（值）「我实际包含的内容」书里的正文

匹配过程：用每个词的 Query 去和所有词的 Key 比对，算出「相关程度」（注意力权重），再用这些权重对所有词的 Value 做加权平均——结果就是这个词「吸收」了相关信息后的新表示。

词"他"的 Query  ──比对──▶  所有词的 Key
                              │
                    ┌─────────┴─────────┐
                    ▼                   ▼
            注意力权重:           注意力权重:
            "小明" 0.7 (高)       "篮球" 0.05 (低)
                    │
                    ▼
    用权重对所有词的 Value 加权求和
                    │
                    ▼
    "他"的新向量 ≈ 0.7×小明的Value + 0.05×篮球的Value + ...

卸掉这个比喻：图书馆只是为了帮你建立直观感受。模型内部既没有「图书管理员」也没有「书」，Query/Key/Value 其实是同一个输入经过三个不同线性变换（W_Q、W_K、W_V 矩阵）得到的三个张量。所谓的「比对相关程度」就是 Q @ K^T（矩阵乘法）再 softmax，所谓的「加权求和」就是再乘一次 V。下一页你就亲手算一遍这个矩阵运算——到那时你会发现，玄乎的「注意力」其实就是三次矩阵乘法加一个 softmax。

自己动手算一次注意力

别只看公式，亲手跑一遍。下面这段代码就是一个完整的、可运行的单头注意力：

import torch
import torch.nn.functional as F

torch.manual_seed(0)
d = 8                       # 用 8 维向量举例（真实是 96 维/头）
x = torch.randn(1, 4, d)    # 1 个句子，4 个词，每词 8 维

# 三个可学习的投影矩阵，把 x 变成 Q/K/V
Wq = torch.nn.Linear(d, d)
Wk = torch.nn.Linear(d, d)
Wv = torch.nn.Linear(d, d)

Q, K, V = Wq(x), Wk(x), Wv(x)

# ① 算相关程度：Q 和 K 的点积
scores = Q @ K.transpose(-2, -1) / (d ** 0.5)   # 形状 (1, 4, 4)

# ② 归一化成权重（加起来=1）
weights = F.softmax(scores, dim=-1)

# ③ 用权重对 V 加权求和
output = weights @ V                              # 形状 (1, 4, 8)
print(output.shape)   # torch.Size([1, 4, 8])

三步：打分（点积）→ 归一化（softmax）→ 加权求和。这就是注意力的全部。剩下的工程细节（多头、掩码、KV Cache）都是在这三步上加料。

别走开——下面把刚才那个 toy 版本和 model_minimind.py 里真实的 Attention 类逐行对一遍。你会发现原理一模一样，但张量形状和工程细节差别很大。

toy ↔ 真实源码

对照：教程 toy ↔ 真实 Attention 类

教程里我们用 (B, T, d) 的三维张量手算注意力。真实代码里，张量始终是 4 维 (B, H, T, head_dim)——多了「头」这一维。下面把两边的核心步骤并排放：

教程简化版（单头，3 维）

d = 8
Wq = nn.Linear(d, d)   # 不分头
Q = Wq(x)              # (B, T, d)
scores = Q @ K.transpose(-2, -1) / sqrt(d)
weights = F.softmax(scores, dim=-1)
output  = weights @ V  # (B, T, d)

真实源码 model_minimind.py:100-133

self.q_proj = nn.Linear(hidden, n_heads*head_dim, bias=False)  # 三个投影都 bias=False
self.k_proj = nn.Linear(hidden, n_kv*head_dim,   bias=False)
self.v_proj = nn.Linear(hidden, n_kv*head_dim,   bias=False)
# ...
xq = self.q_proj(x).view(bsz, seq, n_heads, head_dim)   # 拆出「头」维
xq = xq.transpose(1, 2)                                  # → (B, H, T, head_dim)
xk = repeat_kv(xk, n_rep)                                # GQA：复制 4 头→8 头

注意三个工程差异：① q_proj/k_proj/v_proj 全部 bias=False（省参数，现代模型标配）；② 真实形状是 (B, H, T, head_dim)，.transpose(1,2) 把头维提到前面，方便并行算每个头；③ 最后多了一个 o_proj 把多头结果投影回 hidden_size，再喂给下一层。

📌 对应源码：model_minimind.py 的 class Attention（__init__ 第 91-109 行，forward 第 111-134 行）

多头注意力：多角度同时关注

一个「头」只能学到一种关注模式。把向量切成多份，每份独立做注意力，就得到多个「头」——每个头关注不同的关系（有的看语法、有的看指代、有的看语义）。

MiniMind-O 用 8 个 Query 头。但这里有个省钱的设计——

GQA

GQA：让多个查询头共享同一份钥匙

标准多头注意力里，每个 Q 头都有自己专属的 K 头和 V 头。但 MiniMind-O 用了 GQA（分组查询注意力）：8 个 Q 头，却只有 4 个 K/V 头——每两个 Q 头共享同一组 K 和 V。

标准 MHA

8 个 Q、8 个 K、8 个 V，一一对应。

问题：推理时要为每个头缓存 K/V，显存吃紧。

GQA（本项目）

8 个 Q、4 个 K、4 个 V，两两共享。

好处：KV Cache 直接减半，推理更快，效果几乎不损。

# 共享的实现：把 4 个 KV 头「复制」成 8 个，让每个 Q 头都有对应的 KV
def repeat_kv(x, n_rep):
    # x 形状 (B, 4, T, 96) → 复制成 (B, 8, T, 96)
    return x.repeat_interleave(n_rep, dim=1)

这就是为什么代码里有个 repeat_kv 函数——它把 4 份 K/V 复制成 8 份，假装每个 Q 头都有专属 KV。这是用「重复」换「省存储」的工程技巧。

因果掩码：不许偷看未来

生成文本时，模型是从左到右逐字生成的——第 3 个词只能看到第 1、2 个词，绝不能偷看第 4 个词。怎么做到？用「因果掩码」把未来位置的注意力强行压成 0。

图：因果掩码——下三角矩阵

【AI 生图提示词】请生成一张中文技术示意图，风格简洁、配色柔和、适合教学： - 画面主体：一个 4×4 的网格，表示 4 个词之间的注意力权限，行是「当前词」，列是「被看的词」 - 网格内容（下三角为 ✓ 上三角为 ✗）：第 0 行 [✓ ✗ ✗ ✗]，第 1 行 [✓ ✓ ✗ ✗]，第 2 行 [✓ ✓ ✓ ✗]，第 3 行 [✓ ✓ ✓ ✓] - ✓ 用浅绿色填充表示「可以看到」，✗ 用浅红色填充表示「禁止看到（设为 -∞，softmax 后变 0）」 - 关键标注：在网格旁标注「第 i 个词只能看到第 0~i 个词」；底部标注「这就是『自回归』的来源——生成时只能依赖过去」 - 配色建议：浅灰背景，✓ 浅绿色，✗ 浅红色，对角线用虚线标出 - 画面比例：1:1

实现上，把上三角位置的得分设成负无穷，softmax 后这些位置的权重就变成 0——相当于「看不见」。

闪算分支

真实默认走哪条路：F.scaled_dot_product_attention

教程教的三步（QK^T/√d → 因果掩码 → softmax → ×V）是原理，必须懂。但真实推理/训练时，默认根本不这么算——而是调用 PyTorch 的融合函数 F.scaled_dot_product_attention 一步完成。

真实 Attention.forward 里 self.flash 默认 True（第 109 行：hasattr(...) and config.flash_attn，而 config.flash_attn 默认也是 True）。只要满足条件，就走这条「闪算」分支：

📜 真实源码：model_minimind.py 第 125-126 行

if self.flash and (seq_len > 1) and (not self.is_causal or past_key_value is None) \
        and (attention_mask is None or torch.all(attention_mask == 1)):
    # 一步完成：QK^T/√d + 因果掩码 + softmax + ×V
    output = F.scaled_dot_product_attention(
        xq, xk, xv,
        dropout_p=self.dropout if self.training else 0.0,
        is_causal=self.is_causal,
    )

这一个函数调用等价于教程里的三步，但底层可能走 FlashAttention / memory-efficient kernel，更快、更省显存。传一个 is_causal=True，掩码也一起做了。

易错点：别在源码里找「三步法」。教程教的 QK^T/√d → 掩码 → softmax → ×V 是原理，但真实默认走闪算分支，看不到这三步。如果你直接 grep 源码找 softmax，只会找到 else 分支（第 128-131 行的手写版，用于不支持闪算的边界情况）——那是兜底，不是主路径。两条路数学等价，但默认跑的是闪算那条。

那 else 分支还在吗？在。第 128-131 行保留了手写版（scores = xq @ xk.transpose(-2,-1) / sqrt(head_dim) 再 += -inf 的 triu 掩码，最后 F.softmax(scores) @ xv），用于不支持闪算的边界情况。教程的三步法 = 这个 else 分支，是「读懂原理」用的；真实默认 = 闪算分支。

QK-Norm

QK-Norm：给 Q/K 单独再来一次 RMSNorm

教程前面讲了「每个子层之前有个 RMSNorm」（Pre-Norm）。但真实代码里，Q 和 K 在进 RoPE 之前，还会各自再做一次 RMSNorm——这叫 QK-Norm。教程完全没提，它是稳定训练的一个额外设计。

为什么需要？因为 Q·K 点积的分数对 Q、K 的尺度非常敏感——如果训练过程中 Q/K 的某个维度数值变大，scores = QK^T/√d 会跟着爆炸，softmax 就退化成 one-hot，梯度也没了。对 Q/K 各做一次归一化，把它们的尺度钉住，点积就更可控。

📜 真实源码：model_minimind.py 第 104-105、117 行

# __init__ 里（第 104-105 行）：注意归一化的维度是 head_dim，不是 hidden_size
self.q_norm = RMSNorm(self.head_dim, eps=config.rms_norm_eps)
self.k_norm = RMSNorm(self.head_dim, eps=config.rms_norm_eps)

# forward 里（第 117 行）：投影并拆头之后、RoPE 之前，对 Q/K 各归一化一次
xq = xq.view(bsz, seq_len, self.n_local_heads, self.head_dim)
xk = xk.view(bsz, seq_len, self.n_local_kv_heads, self.head_dim)
xv = xv.view(bsz, seq_len, self.n_local_kv_heads, self.head_dim)
xq, xk = self.q_norm(xq), self.k_norm(xk)   # ← QK-Norm，只动 Q/K，不碰 V
cos, sin = position_embeddings
xq, xk = apply_rotary_pos_emb(xq, xk, cos, sin)   # 然后才上 RoPE

子层前的 RMSNorm（教程讲过）

作用对象：整个 hidden_states（768 维）。位置：MiniMindBlock 里，注意力/前馈之前。

QK-Norm（本节新增）

作用对象：每个头的 head_dim 维（96 维）。位置：Attention 内部、投影之后、RoPE 之前。作用：稳住 Q·K 点积的数值。

这是两套不同位置、不同维度的归一化，别混为一谈。V 不归一化，因为 V 只是被加权求和的内容，不直接进点积。

KV Cache

KV Cache：别重复算已经算过的

生成第 100 个词时，前 99 个词的 K 和 V 其实没变（它们只是被「看」的对象）。如果每生成一个词都把前 99 个词重新算一遍 K/V，太浪费了。

KV Cache 就是把已经算过的 K/V 存起来，下一步只算新词的 K/V，拼到缓存里。这是 LLM 推理能足够快的关键。

图：KV Cache 避免重复计算

【AI 生图提示词】请生成一张中文技术示意图，风格简洁、配色柔和、适合教学： - 画面主体：三个时间步的横向对比，展示有 KV Cache 时如何增量计算 - 时间步 1：输入 [A, B, C]，计算它们的 K/V 并存入 Cache（缓存区显示 K₁K₂K₃ V₁V₂V₃） - 时间步 2：只输入新词 [D]，只计算 D 的 K/V，追加到 Cache（缓存区变成 K₁K₂K₃K₄ V₁V₂V₃V₄），D 用已有的全部 K/V 算注意力 - 时间步 3：只输入 [E]，同样只算 E 的 K/V 并追加 - 关键标注：在每个时间步下方标注「只算了 1 个新词的 K/V」；用红色叉号标出「没有重复计算 A B C 的 K/V」 - 配色建议：浅灰背景，新词橙色，缓存的 K/V 浅蓝色，注意力连线深灰色 - 画面比例：16:9

GQA 的省钱之处在这里再次体现：缓存的是 K/V，头数少一半，缓存就小一半。

Part 2：RoPE

注意力有个致命缺陷：它天生「不分先后」。

注意力的计算是对称的——「我爱你」和「你爱我」如果不加额外信息，在注意力看来几乎一样。但顺序显然重要！位置编码（RoPE）就是用来给每个词打上「你在第几个位置」的标记。

RoPE 的直觉：旋转

RoPE（旋转位置嵌入）的核心想法很优雅：用旋转角度表示位置。位置 0 旋转 0°，位置 1 旋转 θ°，位置 2 旋转 2θ°……位置越靠后，旋转角度越大。

图：RoPE 用旋转角度编码位置

【AI 生图提示词】请生成一张中文技术示意图，风格简洁、配色柔和、适合教学： - 画面主体：一个二维平面上的向量旋转示意图，展示同一个向量在不同位置被旋转不同角度 - 画三个相同的向量（用箭头表示），起点都在原点：位置 0 的向量指向右侧（0°，标注「位置 0」），位置 1 的向量旋转了一个小角度 θ（标注「位置 1，旋转 θ°」），位置 2 的向量旋转了 2θ（标注「位置 2，旋转 2θ°」） - 在三个箭头之间画弧线表示旋转角度的递增 - 关键标注：在右侧补一个小框说明「两个位置的相对夹角只取决于它们的距离（m-n）θ，与绝对位置无关——这就是 RoPE 能捕捉相对位置的原因」 - 配色建议：浅灰背景，三个向量用橙色不同深浅，角度弧线浅紫色，坐标轴浅灰色 - 画面比例：16:9

这个设计最妙的地方：两个词的相对位置关系，天然编码在它们的向量夹角里。模型只要做点积（注意力），就能感知到「这两个词隔了多远」。

RoPE 应用到 Q/K

RoPE 怎么应用到 Q 和 K

注意，RoPE 只旋转 Query 和 Key，不动 Value。因为位置信息的作用是「影响谁和谁相关」——而这正是 Q 和 K 负责的事。

def apply_rotary(q, k, cos, sin):
    def rotate_half(x):
        # 把向量切成两半，互换并取反：[a,b,c,d] → [-c,-d,a,b]
        half = x.shape[-1] // 2
        return torch.cat((-x[..., half:], x[..., :half]), dim=-1)

    # 旋转 = 原向量×cos + 旋转半向量×sin
    q_new = q * cos + rotate_half(q) * sin
    k_new = k * cos + rotate_half(k) * sin
    return q_new, k_new

cos 和 sin 是预先算好的表（不同位置不同角度）。rotate_half 那个「切开互换取反」的操作，就是二维旋转在高维上的推广。

📌 对应源码：model_minimind.py 的 apply_rotary_pos_emb(q, k, cos, sin, unsqueeze_dim=1)（第 80-84 行），和教程这段几乎一字不差。cos/sin 这张表由 precompute_freqs_cis(dim, end, rope_base, rope_scaling)（第 62-78 行）预计算，在 MiniMindModel.__init__ 里注册成 buffer。

预计算表的两个工程细节（第 76-77 行）：真实代码把 torch.cos(freqs) 和 torch.sin(freqs) 各 torch.cat 拼了一次，凑成完整的 head_dim 维——这正好配合 rotate_half 把向量「前后两半互换取反」的写法，两者维度对得上。

YaRN 长度外推藏在这里：同一个 precompute_freqs_cis 里有个 if rope_scaling is not None 分支（第 64-73 行）——当配置开 inference_rope_scaling=True 时，按 YaRN 公式 f'(i) = f(i)·((1-γ) + γ/s) 对频率做「斜坡缩放」，让模型外推到训练时没见过的更长上下文。本教程不深入，但你在源码里看到那个 rope_scaling 字典和 ramp，就是它。

深度边界：RoPE 的数学推导（复数域、欧拉公式）本章不讲。你只需要记住「用旋转角度表示位置，且只作用于 Q/K」这个直觉。想深究的话，延伸阅读里有原始论文。

Part 3：前馈网络

注意力负责词与词之间的信息交流，前馈网络负责每个词自己的「深度加工」。

注意力之后，每个词都吸收了上下文信息。但这些信息还需要被「消化」——升维、非线性变换、再降回来。这就是前馈网络（FFN）的活。它对每个位置独立做同样的处理（不同词之间不交互）。

SwiGLU

SwiGLU：带「门控」的前馈网络

MiniMind-O 用的不是普通的 FFN，而是 SwiGLU——一个带「门控」的设计。它有三条路：

output = down_proj( SiLU(gate_proj(x)) * up_proj(x) )
#                       ↑ 门控信号       ↑ 内容信号

图：SwiGLU 前馈网络的数据流

【AI 生图提示词】请生成一张中文技术示意图，风格简洁、配色柔和、适合教学： - 画面主体：从左到右的分叉-合并流程图 - 输入 x (B,T,768) 从左侧进入，分叉成上下两条路：上路是 gate_proj(x) → (B,T,2432) → SiLU 激活 → 标注「门控，决定放行多少」；下路是 up_proj(x) → (B,T,2432) → 标注「内容，实际信息」 - 两条路在右侧汇合，用一个 ⊙ 符号表示逐元素相乘（门控过滤内容），得到 (B,T,2432) - 再经过 down_proj → (B,T,768) 输出，标注「降回原维度」 - 关键标注：在 2432 维处标注「升维到 2432（≈768×π），给模型更大容量思考」；在 ⊙ 处标注「门控机制：让模型学会选择性放行信息」 - 配色建议：浅灰背景，门控路橙色，内容路浅蓝色，相乘节点绿色，down_proj 紫色 - 画面比例：16:9

为什么升到 2432？ 这是个经验值（约 768×π）。前馈网络升维给模型更大的「思考空间」，再降回来。这个中间维度越大，模型容量越大，但参数也越多。

MoE（可选）

MoE：让模型「带专家上班」（可选）

MiniMind-O 还支持一个进阶选项 MoE（混合专家）：把一个 FFN 拆成 4 个「专家」FFN，每个词由一个路由器决定送给哪个专家处理。

普通 FFN（Dense）

每个词都经过同一个 FFN。

参数少，但每次全激活。

MoE

每个词只经过一个专家。

总参数多（4 个专家），但每次只激活 1/4，计算量不变。

好处：用更少的计算量，换更大的模型容量（参数）。这是现代大模型（如 Mixtral、DeepSeek）普遍采用的技术。MiniMind-O 默认不开 MoE，但它作为可选项存在。

深度边界：MoE 还涉及「负载均衡损失」（防止所有词都挤去同一个专家）等细节，本章不展开。先记住「多专家 + 路由器」的核心即可。

Part 4：组装零件

注意力、前馈、归一化、残差——这四样拼起来，就是一个 Transformer Block。

RMSNorm

RMSNorm：更快更简的归一化

每个子层之前都要「归一化」——把向量拉回稳定的范围，防止数值爆炸或消失。MiniMind-O 用 RMSNorm，它是 LayerNorm 的简化版。

LayerNorm（传统）

减均值 → 除标准差 → 乘权重 → 加偏置

RMSNorm（本项目）

除均方根 → 乘权重

省掉了「减均值」和「偏置」，更快，效果相当。

output = x / sqrt(mean(x²) + eps) * weight

残差连接：信息的高速公路

每个子层的输出都会和它的输入相加：x + 子层(x)。这叫残差连接。

它的作用是给梯度（和信号本身）一条「绕过子层直达」的高速路。没有它，深层网络的梯度会在层层传递中消失，根本训不动。这就是为什么能堆到 8 层甚至 100 层。

class MiniMindBlock(nn.Module):
    def forward(self, x):
        # Pre-Norm：先归一化，再进子层，结果与原 x 相加
        x = x + self.attention(self.input_norm(x))      # 注意力 + 残差
        x = x + self.feed_forward(self.post_norm(x))    # 前馈   + 残差
        return x

堆叠 8 个 Block

堆叠 8 个 Block，加上头尾

把上面这个 Block 复制 8 份串起来，前面接 Embedding，后面接 lm_head，就是完整的 Thinker：

class MiniMindForCausalLM(nn.Module):
    def __init__(self, config):
        self.model = MiniMindModel(config)   # Embedding + 8 个 Block + RMSNorm
        self.lm_head = nn.Linear(768, 6400)  # 把 768 维 → 6400 个词的打分
        # 权重共享：Embedding 和 lm_head 用同一份矩阵，省一半参数
        self.model.embed_tokens.weight = self.lm_head.weight

整条链路：input_ids → Embedding → 8×Block → RMSNorm → lm_head → logits。这就是 Thinker 在「思考」时发生的全部。

训练时怎么算「猜下一个词」的损失？——关键在错位。前面为便于理解，可能有人以为就是 cross_entropy(logits, labels) 原样对齐算。但那样是错的：「用位置 i 的输出预测位置 i+1 的词」，logits 和 labels 必须错开一格。真实实现是这样的（见下方源码）。

📜 真实源码：model_minimind.py 第 245-252 行

def forward(self, input_ids, attention_mask=None, past_key_values=None,
            use_cache=False, logits_to_keep=0, labels=None, **kwargs):
    hidden_states, past_key_values, aux_loss = self.model(
        input_ids, attention_mask, past_key_values, use_cache, **kwargs)
    logits = self.lm_head(hidden_states)            # (B, T, vocab) 每个位置对每个词的打分
    loss = None
    if labels is not None:
        # ★ 错位：用位置 i 的 logits 去预测位置 i+1 的 label
        x = logits[..., :-1, :].contiguous()        # 砍掉最后一个时间步的预测（它没有下一个词可对）
        y = labels[..., 1:].contiguous()            # 砍掉第一个 label（它没有前驱来预测）
        loss = F.cross_entropy(
            x.view(-1, x.size(-1)), y.view(-1),
            ignore_index=-100)                      # -100 的位置（padding/不关心）不计入损失
    return ...

三个要点：① logits[..., :-1, :] 与 labels[..., 1:] 错开一格，这才是「猜下一个词」的真实写法；② ignore_index=-100 让 padding 等位置不干扰损失；③ .contiguous() 保证切片后内存连续，能 .view() 拍平。之前为便于理解讲成 cross_entropy(logits, labels)，真实实现是这种错位版本。

Part 5：自回归生成

架构讲完了，最后看它怎么「说话」。

生成的本质

生成的本质：反复「预测-拼接」

生成一段话，就是不断重复这个循环：

  1. 把当前序列送进模型，得到最后一个位置对 6400 个词的打分
  2. 从打分里采样出一个词，作为下一个词
  3. 把新词拼到序列末尾，回到第 1 步
  4. 直到生成结束符 <|im_end|> 或达到长度上限

采样策略：决定模型的「性格」

「从打分里采样一个词」这一步，有多种策略，它们决定了模型输出的风格：

参数作用调大的效果
temperature控制随机性越大越「奔放」有创意，越小越「保守」确定
top_k只在前 k 个候选里选k 越大候选越多，越多样
top_p只在累积概率达 p 的候选里选p 越大越包容长尾词
repetition_penalty打压已出现过的词越大越不容易复读
 
# MiniMind-O 推理时的典型参数
# temperature=0.7（适度随机）, top_p=0.85（核采样）, repetition_penalty=1.1
generated = model.generate(
    input_ids,
    max_new_tokens=512,
    temperature=0.7,
    top_p=0.85,
    repetition_penalty=1.1,
)

temperature=0 时退化成「贪心」——永远选概率最高的词，输出完全确定但容易死板重复。日常对话一般用 0.7 左右。

采样参数落地

真实 generate()：每个采样参数是怎么落到代码上的

上面那张参数表只告诉你「调大有什么效果」。现在把 generate() 主循环的真实采样段贴出来，让你看到 temperature / repetition_penalty / top_k / top_p 分别对应哪几行。每生成一个新 token 都跑一遍这段。

📜 真实源码：model_minimind.py 第 263-281 行

for _ in range(max_new_tokens):
    past_len = past_key_values[0][0].shape[1] if past_key_values else 0
    # ★ 配合 KV Cache：只把「新增的部分」 input_ids[:, past_len:] 喂进模型，旧的复用缓存
    outputs = self.forward(input_ids[:, past_len:], attention_mask,
                           past_key_values, use_cache=use_cache, **kwargs)
    logits = outputs.logits[:, -1, :] / temperature   # 取最后一位，并除以 temperature

    # ① repetition_penalty：正/负 logit 惩罚方向不同
    if repetition_penalty != 1.0:
        for i in range(input_ids.shape[0]):
            seen = torch.unique(input_ids[i])
            score = logits[i, seen]
            # 正 logit 除以 rp（压低），负 logit 乘以 rp（也算压低概率）——两边都让它「更难被采」
            logits[i, seen] = torch.where(score > 0, score / repetition_penalty,
                                                    score * repetition_penalty)

    # ② top_k：把第 k 名之后的得分全部置 -inf
    if top_k > 0:
        logits[logits < torch.topk(logits, top_k)[0][..., -1, None]] = -float('inf')

    # ③ top_p（核采样）：sort + cumsum + 边界 mask
    if top_p < 1.0:
        sorted_logits, sorted_indices = torch.sort(logits, descending=True)
        mask = torch.cumsum(torch.softmax(sorted_logits, dim=-1), dim=-1) > top_p
        mask[..., 1:] = mask[..., :-1].clone()   # 关键边界处理：右移一位
        mask[..., 0]  = 0                        # 保证概率最高的那个永远不被 mask
        logits[mask.scatter(1, sorted_indices, mask)] = -float('inf')

    # ④ 采样：do_sample 走 multinomial，否则贪心 argmax
    next_token = torch.multinomial(torch.softmax(logits, dim=-1), num_samples=1) \
                 if do_sample else torch.argmax(logits, dim=-1, keepdim=True)
    # ... eos 处理、拼回 input_ids、更新 past_key_values ...
    input_ids = torch.cat([input_ids, next_token], dim=-1)
    past_key_values = outputs.past_key_values if use_cache else None

四个容易看漏的工程细节：① repetition_penalty 用 torch.where(score>0, score/rp, score*rp)——正负 logit 方向不同，但都是「压低已出现词的概率」，这是 HuggingFace 的标准写法；② top_p 那个 mask[..., 1:] = mask[..., :-1].clone() 右移一位，是为了不误杀第一个跨过 p 的词（否则会出现「没有任何候选」的死局）；③ torch.multinomial 才是真正的「按概率掷骰子」；④ input_ids[:, past_len:] 是 KV Cache 的另一半——前面只算新 token 的 K/V，这里也只把新 token 喂进去。

练习：手算一次注意力

理解 softmax

理解 softmax 和加权求和

假设一个 3 词的句子，某个 Query 与 3 个 Key 的点积得分是 [2.0, 0.5, 0.1]。请心算（或用计算器）：

  1. 对这三个得分做 softmax，得到三个注意力权重（提示：exp(2.0)≈7.39, exp(0.5)≈1.65, exp(0.1)≈1.11）
  2. 三个权重加起来等于多少？这说明了什么？
  3. 如果三个 Value 是 [10, 20, 30]，加权求和的结果约是多少？哪个 Value 贡献最大？

参考答案

1) softmax 分母 = 7.39+1.65+1.11 ≈ 10.15，权重 ≈ [0.73, 0.16, 0.11]。2) 加起来 = 1.0，说明注意力权重是一种「概率分配」。3) 加权和 ≈ 0.73×10 + 0.16×20 + 0.11×30 ≈ 7.3 + 3.2 + 3.3 ≈ 13.8。第一个 Value（权重 0.73）贡献最大——得分最高的 Key 对应的 Value 主导了结果，这正是「注意力」的意义。

常见困惑排解

「为什么是 8 层、768 维这些数？」

这是模型规模的超参数，在配置里定死。MiniMind-O 选小一点的规模（8 层、768 维、6400 词表），是为了能在单卡上训练。GPT-4 这种规模是几百层、上万维。

「Embedding 和 lm_head 共享权重，不会冲突吗？」

实践证明不会，反而有正则化效果。它们本就是「词↔向量」这同一组关系的两个方向（输入查表、输出打分），共享一份矩阵是合理的。

「残差连接的 + 号，维度不会不匹配吗？」

不会。注意力、前馈这些子层被设计成「输入输出同维度」（都是 768），所以能直接相加。改变维度的操作只在 FFN 内部临时升维再降回。

「生成时每一步都要跑整个模型？」

是的，但有 KV Cache 兜底——每步只需对新词算一次前向，旧的 K/V 复用缓存。所以生成长文本的速度是可接受的。

关键要点回顾

LLM 的本质

根据已有词猜下一个词，反复进行。所有「智能」都来自这个动作的极致优化。

注意力三步

Q·K 打分 → softmax 归一化 → 加权求和 V。让每个词「看见」相关的其他词。

GQA + KV Cache

8 个 Q 头共享 4 组 KV，推理缓存减半。这是小模型也能快速推理的关键。

RoPE 位置编码

用旋转角度表示位置，只作用于 Q/K，让模型感知词的顺序和相对距离。

Block = 注意力+前馈+残差+归一化

Pre-Norm 风格，子层前归一化，结果与输入相加。堆 8 层就是 Thinker。

采样决定性格

temperature/top_p/top_k 控制随机性。同样的模型，参数不同「性格」不同。
