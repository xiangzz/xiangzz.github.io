实践 1：跑通六种推理

目标：亲手跑完六种模式，确认模型各项能力都正常。

python eval_omni.py --mode 0 --prompt_lang 1    # 文本对话
python eval_omni.py --mode 2 --prompt_lang 1    # 语音对话
python eval_omni.py --mode 3                    # 声音克隆
python eval_omni.py --mode 4                    # 图像理解
python eval_omni.py --mode -1                   # 全部串跑

该观察什么：每跑完一种，去 output/ 看生成的 mp3 能不能播、内容对不对。文本对话应该有连贯的回复，声音克隆应该能听出不同音色。

这一关的价值：把阶段 1 和阶段 6 的命令变成肌肉记忆。之后任何实验，你都能快速让模型跑起来看效果。

实践 2：探索分词器

拆开 Tokenizer 看个究竟

目标：亲眼看到一段文字如何被切成 token、变成数字、再还原。

from transformers import AutoTokenizer
tok = AutoTokenizer.from_pretrained("./model")

text = "你好，世界！Hello World!"
ids = tok.encode(text)
print("Token IDs:", ids)
print("切分:", tok.convert_ids_to_tokens(ids))
print("还原:", tok.decode(ids))

# 看特殊 token
print(f"BOS={tok.bos_token}({tok.bos_token_id}) EOS={tok.eos_token}({tok.eos_token_id})")

# 构造一个对话 prompt
msgs = [{"role": "user", "content": "你好"}]
print(tok.apply_chat_template(msgs, tokenize=False))

该观察什么：中文是几个字一个 token？英文呢？emoji 呢？apply_chat_template 输出里的 <|im_start|> 长什么样？

实践 3：改改配置

参数量怎么变

目标：直观感受 hidden_size、层数对模型规模的影响。

from model.model_minimind import MiniMindConfig, MiniMindForCausalLM

configs = [
    ("tiny",  MiniMindConfig(hidden_size=256, num_hidden_layers=4)),
    ("small", MiniMindConfig(hidden_size=512, num_hidden_layers=6)),
    ("base",  MiniMindConfig(hidden_size=768, num_hidden_layers=8)),
]
for name, cfg in configs:
    model = MiniMindForCausalLM(cfg)
    params = sum(p.numel() for p in model.parameters()) / 1e6
    print(f"{name}: {params:.1f}M 参数")

该观察什么：tiny/small/base 参数量差几倍？把 hidden_size 翻倍，参数量是翻倍还是翻四倍（提示：线性层参数是 in×out）？

这一关的价值：理解模型规模不是玄学。下次看到「7B 模型」「13B 模型」，你能大致推算它的 hidden_size 和层数。

实践 4：可视化注意力

目标：用热力图看到模型在读每个词时，关注了哪些其他词。

步骤：在 Attention.forward 里加一行，把注意力权重存下来；跑一次推理；用 matplotlib 画热力图。

# 1. 在 Attention.forward 里加一行（保存权重）
self.last_attn_weights = attn_weights   # (B, heads, T, T)

# 2. 推理后取出某一层某一头
attn = model.model.layers[0].self_attn.last_attn_weights[0, 0].cpu().numpy()

# 3. 画热力图
import seaborn as sns, matplotlib.pyplot as plt
sns.heatmap(attn, cmap='YlOrRd')
plt.savefig("attention.png")

该观察什么：上三角是不是空的（因果掩码）？浅层是不是更关注相邻词（局部），深层是不是更关注语义相关的词？

注意：保存注意力权重会增加内存占用，只在调试时加，调试完记得删掉。

实践 5：跟踪前向形状

一次 forward 的所有形状

目标：在脑子里完整跑通一次前向传播，盯死每个张量的形状。

# 在 MiniMindOmni.forward 关键位置插桩（纯文本输入场景）
def forward(self, input_ids):
    print(f"input_ids:      {input_ids.shape}")          # (1, T)
    text_ids = input_ids[:, 8, :] if input_ids.dim() == 3 else input_ids
    # 9 通道 (1,9,T) 时取第 8 通道=文本；纯文本 (1,T) 直接用
    h = self.thinker.embed_tokens(text_ids)
    print(f"after embed:    {h.shape}")                  # (1, T, 768)
    for i, layer in enumerate(self.thinker.layers):
        h = layer(h)
    print(f"after 8 blocks: {h.shape}")                  # (1, T, 768)
    logits = self.lm_head(h)
    print(f"text_logits:    {logits.shape}")             # (1, T, 6400)

别照抄 input_ids[8]。真实源码 model_omni.py:252 是 input_ids[:, 8, :]——取的是第 8 个通道（文本），不是第 8 个 batch。写成 input_ids[8] 在 (1, T) 或 (1, 9, T) 上都会越界报错。

该观察什么：从 Embedding 到 8 个 Block 再到 lm_head，(1, T, 768) 这个形状是不是一直不变？只有最后 lm_head 把 768 变成 6400？为什么中间维度稳定（因为残差连接要求输入输出同维）？

这个练习直接验证阶段 2 和阶段 3 讲的所有形状约定。

实践 5½：拆解双路径

Thinker 和 Talker 到底怎么协作

目标：这是阶段 3 全模态架构的唯一动手练习。在 Bridge 处插桩，亲手对比「Thinker 的隐状态传给 Talker vs 不传」，看清双路径到底在干什么。

背景：Talker 的输入里有一项是从 Thinker 第 3 层（bridge_layer）抽出来的隐藏状态，经 embed_proj 投影后注入。这一步是 Thinker→Talker 的「意图传递」。

# 在 MiniMindOmni.forward 里，Talker 组装输入那一段（约第 296 行附近）
# 找到 bridge 状态被注入的位置，加一个开关做对照实验

# 原始：用 Thinker 第 bridge_layer 层的隐状态
bridge_h = thinker_hidden[config.bridge_layer]          # (1, T, 768)
talker_input = ... + self.talker.embed_proj(bridge_h)   # 注入

# 对照：把 bridge_h 替换成全零，看 Talker 还能不能生成有意义的声音
bridge_h_zero = torch.zeros_like(bridge_h)
talker_input = ... + self.talker.embed_proj(bridge_h_zero)  # 不传意图

该观察什么：

  • 正常（传 bridge）：Talker 生成的 8 层码本解码后，是清晰、连贯的人声。
  • 对照（bridge 全零）：Talker 收不到 Thinker 的「想法」，生成的音频会变成含混的噪声或毫无意义的呜咽——因为它根本不知道该「说」什么。

这个对比会非常直观。如果对照实验里声音变废了，说明 Bridge 这条线确实承载了「文本意图」——它不是可有可无的装饰，而是 Talker 能说话的前提。这正是 MiniMind-O 区别于「ASR+LLM+TTS 简单串联」的关键：Thinker 和 Talker 通过张量深度耦合，而非各干各的。

延伸：再试试把 bridge_layer 从第 3 层改成第 0 层或第 7 层（在 config 里改），看输出音质怎么变。第 3 层是经验证过的甜点——太浅（第 0 层）意图还没成形，太深（第 7 层）信息已过于特定。

实践 6：驯服采样参数

目标：用同一个 prompt、不同采样参数，感受模型的「性格」变化。

# 同一个问题，三种「性格」
python eval_omni.py --mode 0 --temperature 0.1 --top_p 0.5    # 保守，几乎确定
python eval_omni.py --mode 0 --temperature 0.7 --top_p 0.85   # 自然（推荐）
python eval_omni.py --mode 0 --temperature 1.5 --top_p 0.95   # 奔放，天马行空

该观察什么：temperature=0.1 是不是每次回答几乎一样、有点机械？1.5 是不是多样但不一定连贯？为什么 0.7 通常是甜点？

这一关的价值：以后部署模型时，你能根据场景调参——客服场景要稳定（低 temperature），创意写作要多样（高 temperature）。

实践 7：跑一遍完整训练

目标：用 Mini 数据集，在单卡上跑完 T2A → A2A Proj → A2A Full 三阶段，亲手训练一个能用的模型。

# 改好 trainer/train.sh 里的数据路径后
bash trainer/train.sh

该观察什么（这些观察比「跑完」更重要）：

  • loss 曲线是不是持续下降？有没有突然飙升（学习率太大）
  • text_loss 和 audio_loss 的比例——audio 是不是比 text 小（因为除以了 8）
  • 学习率是不是按余弦曲线从高到低衰减
  • 训练速度（tokens/sec）和显存占用是否正常

耐心点：Mini 流水线在 3090 上约 2 小时。训练中如果 loss 变 NaN，立刻停下来排查（学习率太大或数据有问题），不要让它白跑。

给动手者的几条建议

1. 不要怕报错。每个报错都是一次学习机会。看到红字先读，再搜，再问——别直接跳过。

2. 改一点看一点。改完立刻运行观察变化，不要攒一堆改动再跑（出了错不知道是哪改导致的）。

3. 多用 print 和断点。理解和调试模型，最有效的工具就是 print(x.shape) 和 IDE 断点。

4. 记录你的实验。哪个参数、什么结果——记下来。否则做完就忘，等于白做。

5. 大胆改。这是开源项目，改坏了 git reset 就行。最深的理解来自「我改了这里，结果变成了那样」。
