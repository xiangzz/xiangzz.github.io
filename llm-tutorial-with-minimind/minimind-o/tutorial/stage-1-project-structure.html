先跑通，再读懂

阶段 1 · 把 MiniMind-O 跑起来，建立全局观

别一上来啃主文件

很多人学一个开源项目的第一反应是：找到最核心的那个文件，从第一行开始啃。MiniMind-O 里那个文件叫 model_omni.py，400 多行，全是类和张量运算。

这么干的人，90% 会在两小时内放弃。

因为他们跳过了最重要的一步：先让它在手里跑起来。

看见模型真的吐出文字、真的开口说话，你才会知道「这一坨代码到底在干什么」。有了这个「结果」垫底，回头读代码时每一段都有了落点——这是本章唯一的目标。

本章你将完成的事

1. 装好环境

创建一个干净的虚拟环境，装上 PyTorch 和项目依赖，确认 GPU 可用。

2. 跑出第一句话

用一条命令让模型回答问题，顺便生成一段语音——亲手验证模型是活的。

3. 看懂全局

不逐文件细读，而是用「职责」的视角建立目录地图，知道该去哪找什么。

4. 抓住数据流

用一张图记住「输入怎么变成输出」，作为后续所有章节的导航锚点。

Part 1：跑出第一句

别读代码了，先让它开口说话。

这一节全是可操作的命令。照着敲，遇到报错翻到本章最后一节的排错指南。目标只有一个：在终端看到模型生成的回复，并得到一个 mp3 音频文件。

第 1 步：建一个干净的环境

用 conda 隔离环境，避免和你机器上其他项目的依赖打架。

# 创建并激活专用环境（Python 3.10 是经过验证的稳定版本）
conda create -n minimind-o python=3.10 -y
conda activate minimind-o

# 验证 Python 版本
python --version    # 应输出 Python 3.10.x

为什么强调「干净」？MiniMind-O 依赖的 funasr（语音识别）、transformers（模型加载）对版本很敏感，混在别的环境里十有八九会冲突。一个独立环境能省掉你几天的排错时间。

第 2 步：PyTorch

PyTorch 的安装命令因 GPU 类型而异。先确认你有没有 NVIDIA 显卡：

nvidia-smi    # 有输出表格 = 有 N 卡；命令找不到 = 没有

有 N 卡（按 CUDA 版本选，121 是较通用的）：

pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121

没有 N 卡（CPU 版，能跑但慢得多）：

pip install torch torchvision torchaudio
# 装完立刻验证 GPU 是否可用
>>> import torch
>>> print(torch.cuda.is_available())   # True = GPU 可用，False = 只能用 CPU
>>> print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else "CPU only")

第 3 步：装项目依赖

# 在项目根目录下执行
pip install -r requirements.txt

这一步会装上 transformers、funasr（SenseVoice 语音编码）、soundfile、pydub、gradio 等。装的时间较长，请耐心。

装到一半报红色错误，先停下来！不要在有报错时继续往下敲命令。常见的两个坑：

  • funasr 装失败：多半是 Python 版本不对（必须 3.10），或缺少编译工具。
  • 网络超时：换成国内镜像源 pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

第 4 步：下载预训练权重

模型权重不在这个仓库里——它太大。MiniMind-O 一共需要 5 份权重：1 份主模型（放 out/）+ 4 份外部编码器（放 model/）。每份都很大，全部来自 ModelScope。

在项目根目录下依次执行：

# ① 主模型权重 → ./out/llm_768.pth（基座语言模型，训练用）
modelscope download --model gongjy/minimind-3o-pytorch llm_768.pth --local_dir ./out

# ② 语音编码器 → ./model/SenseVoiceSmall
modelscope download --model gongjy/SenseVoiceSmall --local_dir ./model/SenseVoiceSmall

# ③ 视觉编码器 → ./model/siglip2-base-p32-256-ve
modelscope download --model gongjy/siglip2-base-p32-256-ve --local_dir ./model/siglip2-base-p32-256-ve

# ④ 音频编解码器 → ./model/mimi
modelscope download --model gongjy/mimi --local_dir ./model/mimi

# ⑤ 说话人编码器 → ./model/campplus
modelscope download --model gongjy/campplus --local_dir ./model/campplus

只想跑推理、不想训练？把第 ① 条换成整包下载，会额外拿到已训练好的 sft_omni_768.pth：

modelscope download --model gongjy/minimind-3o-pytorch --local_dir ./out

下载完，目录长这样

5 份权重各归其位——主权重在 out/ 根目录，4 个编码器各占 model/ 下一个子文件夹：

minimind-o/
├── out/
│   └── llm_768.pth              # 主模型权重（基座）／推理则还会有 sft_omni_768.pth
├── model/
│   ├── SenseVoiceSmall/         # 语音编码器
│   ├── siglip2-base-p32-256-ve/ # 视觉编码器
│   ├── mimi/                    # 音频编解码器
│   └── campplus/                # 说话人编码器（声音克隆用）
└── ...

这 4 个编码器子目录的名字是写死在代码里的——比如 eval_omni.py 里硬编码了 ./model/SenseVoiceSmall、./model/siglip2-base-p32-256-ve、./model/mimi。所以路径和名字一个字都不能改，否则加载时会报 Can't load tokenizer / model。

第 5 步：见证奇迹

权重就位后，一行命令让模型开口：

$ python eval_omni.py --load_from model --weight sft_omni

这条命令的两个参数怎么对应到刚才下载的文件：

  • --load_from model：告诉程序「用项目里的 ./model/ 加载 4 个编码器」（不是文件路径，是固定字面值 model）
  • --weight sft_omni：主权重名前缀。程序会自动拼成 ./out/sft_omni_768.pth（--save_dir 默认 out，--hidden_size 默认 768）

你会看到类似这样的输出（打字机式逐字出现）：

📒 [Thinker]:
你好！很高兴认识你，有什么我可以帮忙的吗？
🎹 [Talker]: 28 frames | Audio decoded to: ./output/text-00.mp3

如果你看到了文字回复，并且 output/ 下生成了一个能播放的 mp3——恭喜，你已经成功了。模型是活的，后面所有章节都在解释「它怎么做到的」。

Part 2：用职责读目录

别记文件名，记每个文件夹「负责什么」。

跑通之后，我们来建立全局观。MiniMind-O 的文件不少，但它们其实只分成四类职责：定义模型、处理数据、训练、使用。记住这四个职责，你就知道每个文件属于哪一摊事，读代码时就不会迷路。

四类职责，一目了然

职责目录/文件它干什么
定义模型model/模型的「图纸」：每一层怎么算
处理数据dataset/把原始文本/音频/图像变成模型能吃的张量
训练模型trainer/定义「怎么学」：优化器、损失、循环
使用模型eval_omni.py / scripts/ / webui/加载训练好的模型，做推理和演示

这个四分法贯穿整个项目，也贯穿本教程的后续章节——每一类职责对应一个阶段。

model/：模型的图纸

这个目录是全书的主角。两个最核心的文件：

model_minimind.py

基础语言模型的架构——一个标准 Transformer。约 290 行。

它定义了 Thinker（思考者）的骨架：注意力、前馈网络、位置编码。

阶段 2 全章都在讲它。

model_omni.py

全模态模型，在基础 LLM 之上加了 Talker（说话者）和多模态融合。约 460 行。

这是最核心、最复杂的文件。

阶段 3 全章都在讲它。

此外还有 tokenizer.json（分词器词表）。声音克隆用的预置音色、实时通话用的 VAD（语音活动检测）逻辑，则分散在 scripts/ 和 webui/ 里——这些在阶段 6、7 会专门讲。

把这张图印在脑子里。后续每个阶段都是对这条流水线某个环节的放大：

  • 预处理环节 → 阶段 4 数据处理
  • Thinker 环节 → 阶段 2 基础语言模型
  • Thinker + Talker 融合 → 阶段 3 全模态模型
  • 输出解码环节 → 阶段 6 推理与评估

Thinker·Talker

这张图里有两个核心角色，提前认识它们：

Thinker 思考者

8 层 Transformer，是模型的「大脑」。

它理解所有输入（文本、音频、图像），并生成文字回复。

本质就是一个标准的小型 LLM。

Talker 说话者

4 层 Transformer，是模型的「嘴巴」。

它接收 Thinker 想好的内容，把它转成 8 层音频码，实现「开口说话」。

这是 MiniMind-O 区别于普通 LLM 的关键。

两者通过一个叫 Bridge 的桥接连起来：Talker 从 Thinker 的第 3 层「偷看」隐藏状态，从而知道 Thinker 想说什么。这个设计是阶段 3 的重头戏。

为什么是这个顺序

  • 先读 README：知道这项目要解决什么问题，避免「为了读而读」。
  • 再扫 requirements：看到 funasr 就知道有语音、看到 gradio 就知道有网页演示——依赖清单是项目能力的速览。

模型有多大？钱花在哪？

建立规模感，有助于你判断「哪些部分值得深究」。

组件参数量是否参与训练角色
Thinker（8 层 Transformer）~64M✅ 是理解输入、生成文本
Talker（4 层 Transformer）~47M✅ 是生成音频码
音频/视觉投影器~2M✅ 是对齐模态到统一空间
SenseVoice（音频编码）~234M❌ 冻结把语音变成特征
SigLIP2（视觉编码）~95M❌ 冻结把图像变成特征
Mimi（音频编解码）~96M❌ 冻结音频↔码本互转

关键洞察：真正「自己训练」的只有 ~113M 参数（Thinker+Talker+投影器），其余 400 多万参数的外部编码器都是直接拿来用、冻结不动的。这就是 MiniMind-O 能在单张 3090 上训练的秘密——它站在 SenseVoice、SigLIP2、Mimi 这些巨人的肩膀上。

排错指南

第一次跑通几乎一定会踩坑，这是正常的。

下面是新手跑 MiniMind-O 最常遇到的几个报错。按「症状」对照查找，每条都给了原因和修复方向。

环境与依赖类错误

torch.cuda.is_available() 返回 False

症状：明明有 N 卡，但 PyTorch 说 GPU 不可用。

原因：装了 CPU 版的 PyTorch，或 CUDA 版本不匹配。

修复：卸载重装对应 CUDA 版本 pip uninstall torch && pip install torch --index-url .../cu121；确认 N 卡驱动够新（nvidia-smi 看驱动版本）。

funasr 或 fun_text_chinese 装不上

症状：pip install -r requirements.txt 报一堆红字。

原因：Python 版本不对（必须 3.10），或缺少 C++ 编译工具。

修复：确认 python --version 是 3.10.x；Windows 装「Visual C++ Build Tools」；换清华镜像源重试。

ImportError: No module named 'xxx'

症状：运行时报找不到模块。

原因：依赖没装全，或装到了别的环境。

修复：确认你 conda activate minimind-o 了；重跑 pip install -r requirements.txt 看是否有静默失败的包。

权重与运行类错误

OSError: Can't load tokenizer / model

症状：加载模型时报路径错。

原因：编码器目录缺失或名字拼错，或主权重没下到 out/。

修复：核对 ./model/ 下四个子目录名字一字不差（SenseVoiceSmall、siglip2-base-p32-256-ve、mimi、campplus）；确认 ./out/sft_omni_768.pth 存在；--load_from 用字面值 model 而非文件路径。

CUDA out of memory

症状：跑到一半报显存不足。

原因：显卡显存太小，或生成长度设太长。

修复：减小 --max_new_tokens（如 256）；关掉其他占显存的程序；实在不行用 CPU 跑（慢但能跑）。

生成的 mp3 是空的 / 没声音

症状：文字正常，但音频文件 0 秒。

原因：Mimi 解码器没加载成功，或音频被过滤光了。

修复：确认 Mimi 权重路径正确；检查 --decode_audio 是否为 1；看终端是否有「Talker: 0 frames」的提示。

动手验证

确认你真的跑通了，而不只是看完了。

练习一：试遍每种输入

除了文本对话（mode 0），MiniMind-O 还能处理语音和图像。把下面几个模式都跑一遍，观察输出的差异：

# 语音对话：给它一段语音，它用语音回答
$ python eval_omni.py --mode 2 --load_from model --weight sft_omni

# 声音克隆：模仿某个人的音色说话
$ python eval_omni.py --mode 3 --load_from model --weight sft_omni

# 图像理解：给它一张图，让它描述
$ python eval_omni.py --mode 4 --load_from model --weight sft_omni

# 全部模式串跑一遍（用于全面测试）
$ python eval_omni.py --mode -1 --load_from model --weight sft_omni

思考：不同模式生成的 mp3，音色一样吗？为什么 mode 3 的声音和 mode 0 不同？

练习二：画出你自己的数据流

关掉教程，拿出一张纸，凭记忆画出「用户说一句话 → 模型用语音回答」的完整数据流。要求标出：

  1. 语音输入经过哪个编码器变成了什么？
  2. 它在哪里和文本特征「汇合」？
  3. Thinker 和 Talker 各自负责什么？
  4. 语音输出是怎么从数字变回声音的？

画不出来没关系——回去看 Part 3 的数据流图。能独立画出来，说明全局观已经建立，可以放心进入阶段 2 了。

两个主角
