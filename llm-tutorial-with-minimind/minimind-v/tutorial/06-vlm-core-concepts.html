6.1 VLM 的核心思想

图片就是一门"外语"，视觉编码器就是"翻译词典"，投影层就是"语言桥接"。

语言模型（LLM）本质上只会处理一串 token——它不认识图片，就像一个只会中文的人不认识英文。但如果有人帮你翻译，你就能理解英文内容。VLM 的核心思想就是：找一个"翻译官"把图片翻译成 token。

  • 一句话总结 —— 图片 = 外语，视觉编码器 = 翻译词典，投影层 = 语言桥接
  • 类比理解 —— "学外语"与"看图片"的过程惊人地相似
  • 为什么有效 —— 图片和文本都能变成 token 序列，LLM 天然能处理

语言模型（LLM）本质上是处理 token 序列的工具。文本经过分词器变成 token 大家已经熟悉了——[你好, 世界, ...]。而图片经过视觉编码器后，同样变成一系列 token——[patch1, patch2, ...]。既然都是 token，LLM 就能统一处理它们。这就是 VLM 能工作的根本原因。

6.2 三大组件详解

视觉编码器、MLP 投影层、Token 替换——VLM 的三大核心组件。

上一节讲了"图片是外语"的类比。这节我们深入看看，到底是哪三个组件合作完成了"翻译"工作。它们的分工非常清晰：视觉编码器负责"看"，投影层负责"翻译"，Token 替换负责"嵌入"。

  • 视觉编码器 SigLIP2 —— 把 256x256 图片变成 64 个 768 维向量（~95M 参数，冻结）
  • MLP 投影层 —— 把视觉特征翻译到 LLM 的语义空间（~1M 参数，训练）
  • Token 替换 —— 用视觉特征替换文本序列中的图片占位符

整体架构：两条路径汇聚

VLM 的数据流分为两条路径：视觉路径（图片 → 视觉编码器 → 投影层）和文本路径（文本 → 分词器 → 嵌入层）。两条路径在 Token 合并步骤汇合，然后一起送入 Transformer。

组件1：视觉编码器

做什么：把 256x256 的图片变成 64 个 768 维的向量。具体来说，图片被切成 8x8=64 个小块（每块 32x32 像素），每个小块经过 Vision Transformer 处理后输出一个 768 维向量。这样一张图片就变成了 64 个"视觉 Token"。

加载与冻结视觉编码器

视觉编码器是预训练好的——SigLIP2 已经在数亿图文对上训练过，非常擅长提取图片特征。我们直接拿来用，冻结它的所有参数，不计算梯度，不更新权重。这样做有两个好处：省训练时间 + 省显存。

# model_vlm.py 第46-59行
@staticmethod
def get_vision_model(model_path):
    model = SiglipVisionModel.from_pretrained(model_path)  # 加载预训练模型
    processor = SiglipImageProcessor.from_pretrained(model_path)

    # 关键：冻结所有参数！
    for param in model.parameters():
        param.requires_grad = False   # 不计算梯度，不更新权重

    return model.eval(), processor    # 设为评估模式

逐行解读：第2行加载预训练的 SigLIP2 模型和对应的图片预处理器。第6-7行遍历模型所有参数，将 requires_grad 设为 False，表示反向传播时不计算这些参数的梯度。第9行调用 .eval() 关闭 Dropout 和 BatchNorm 的训练行为。整个视觉编码器从此"只读"。

图片预处理与特征提取

图片送入 SigLIP2 之前需要两步：预处理（调整格式、归一化像素值）和特征提取（前向传播得到 768 维向量）。这两步分别对应下面两个函数。

# model_vlm.py 第62-65行 —— 图片预处理
@staticmethod
def image2tensor(image, processor):
    if image.mode in ['RGBA', 'LA']:
        image = image.convert('RGB')       # 确保是 RGB 格式
    inputs = processor(images=image, return_tensors="pt")  # 预处理
    return inputs
    # 返回: {pixel_values: [1, 3, 256, 256], pixel_mask: [1, 256, 256]}

image2tensor 做了两件事：先把 RGBA/LA 格式转为 RGB（去掉透明通道），然后用 SigLIP 的预处理器把图片变为 [1, 3, 256, 256] 的张量——即 batch=1、3 通道、256x256 像素。

# model_vlm.py 第68-73行 —— 提取视觉特征
@staticmethod
def get_image_embeddings(image_inputs, vision_model):
    with torch.no_grad():                           # 不计算梯度
        outputs = vision_model(**image_inputs)      # 前向传播
    return outputs.last_hidden_state                 # [1, 64, 768]

get_image_embeddings 在 torch.no_grad() 上下文中执行前向传播（因为视觉编码器已冻结，不需要梯度）。输出的 last_hidden_state 形状为 [1, 64, 768]——64 个 Patch，每个 768 维。这就是图片的"数字表示"。

组件2：投影层

做什么：SigLIP2 输出的 768 维向量和 LLM 嵌入层的 768 维向量虽然维度相同，但它们处于完全不同的语义空间——就像两个人说不同的语言，即使声音大小一样也听不懂。MLP 投影层就是"翻译官"，把视觉特征空间映射到语言特征空间。

# model_vlm.py 第23-33行
class MMVisionProjector(nn.Module):
    def __init__(self, in_dim, out_dim):
        self.mlp = nn.Sequential(
            nn.LayerNorm(in_dim),          # 归一化 [768 → 768]
            nn.Linear(in_dim, out_dim),    # 线性变换 [768 → 768]
            nn.GELU(),                     # 激活函数
            nn.Linear(out_dim, out_dim),   # 线性变换 [768 → 768]
        )

    def forward(self, x):
        return self.mlp(x)
        # 输入: [batch, 64, 768] → 输出: [batch, 64, 768]
        # 维度没变，但语义空间变了！

结构解读：投影层是一个两层 MLP。先用 LayerNorm 归一化输入，再经过两个线性层（中间用 GELU 激活）。虽然输入输出维度都是 768，但经过学习后，输出的向量会被"翻译"到 LLM 能理解的语言空间中。这个层只有 ~1M 参数，是整个 VLM 中唯一需要从头训练的部分。

组件3：Token 替换

这是 VLM 最关键的一步：把投影后的图片特征"塞进"文本序列中。具体做法是——文本中预先放好 64 个 <|image_pad|> 占位符，LLM 的嵌入层会给它们生成普通的文本嵌入。然后在送入 Transformer 之前，用视觉特征直接替换这些占位符的嵌入。

# model_vlm.py 第75-96行 (简化版)
def count_vision_proj(self, tokens, h, vision_tensors):
    marker = self.config.image_ids[0]   # <|image_pad|> 的 ID = 12
    out = []
    for b in range(batch_size):
        hb = h[b]                       # 当前样本的嵌入 [seq, 768]
        seq = tokens[b].tolist()        # 当前样本的 token ID 列表
        k = 0                           # 第几张图
        i = 0                           # 当前位置
        while i < len(seq):
            if seq[i] == marker:        # 找到了 <|image_pad|>
                start = i
                while i < len(seq) and seq[i] == marker:
                    i += 1              # 跳过所有连续的占位符
                # 用视觉特征替换这段占位符
                hb = torch.cat((hb[:start], vf[b][k][:i-start], hb[i:]))
                k += 1
            else:
                i += 1
        out.append(hb)
    return torch.stack(out)

代码解读：marker 是占位符的 token ID（12）。外层循环遍历每个样本，内层 while 循环扫描 token 序列。当找到连续的占位符时，记录起始和结束位置，然后用 torch.cat 把视觉特征"拼"进去——占位符之前的嵌入 + 视觉特征 + 占位符之后的嵌入。这样图片信息就无缝融入了文本序列。

6.3 forward 流程

把上面三个组件串起来，就得到 VLM 的完整前向传播——七个步骤，从输入到输出。

  • Step 1：文本 token 经嵌入层变为 hidden_states [batch, seq, 768]
  • Step 2：图片经 SigLIP2 提取视觉特征 [batch, 64, 768]
  • Step 3：视觉特征经 MLP 投影层"翻译"
  • Step 4：用投影后的视觉特征替换 hidden_states 中的占位符
  • Step 5：替换后的序列经 8 层 Transformer 处理
  • Step 6：经 lm_head 输出 logits [batch, seq, 6400]
  • Step 7：logits 与 labels 计算交叉熵损失

关键理解：Step 1-4 是 VLM 相比 LLM 新增的部分。Step 5-7 和纯 LLM 完全一样——Transformer 不知道自己处理的 token 有些来自图片、有些来自文字，它只看到一串 768 维向量。这种"欺骗"Transformer 的设计非常优雅。

6.4 LLM 与 VLM

VLM 在 LLM 基础上只新增了约 50 行核心代码。改动量极小，但能力从"只懂文字"扩展到了"同时懂图片和文字"。

6.5 冻结策略

不同训练阶段，冻结不同的组件——先让投影层学会"翻译"，再微调 LLM 适应视觉输入。

MiniMind-V 的训练分为两个阶段，每个阶段采用不同的冻结策略。视觉编码器始终冻结（它已经很擅长提取图片特征了），变的是投影层和 LLM 的训练范围。

  • Pretrain 阶段（freeze_llm=2） —— 只训练投影层，LLM 完全冻结。目标：让投影层干净地完成图文对齐
  • SFT 阶段（freeze_llm=1） —— 投影层 + LLM 首末层训练，中间层冻结。目标：学会看图问答，同时保留语言能力

两阶段冻结策略对比

为什么 SFT 要解冻首末层？首层负责处理视觉和文本特征的融合，需要适应新的视觉输入；末层直接影响输出格式，需要学会生成看图回答的格式。中间层承载了 LLM 的语言知识，冻结它可以保留这些能力不被破坏。
