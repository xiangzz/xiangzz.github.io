8.1 两阶段训练总览

MiniMind-V 的训练分为两个阶段：Pretrain（基础图文对齐）和 SFT（指令微调）。Pretrain 可以跳过——因为 SFT 数据已包含 Pretrain 数据。

两阶段的设计思路是：Pretrain 阶段只训练投影层，让它学会把视觉特征"翻译"到语言空间；SFT 阶段微调投影层 + LLM 首末层，让模型学会看图问答。这和人类学外语类似——先学会查词典（Pretrain），再学会用外语对话（SFT）。

  • Pretrain 阶段 —— 127 万条图文描述，冻结 LLM，仅训练投影层（freeze_llm=2），学习率 4e-4
  • SFT 阶段 —— 290 万条混合数据，解冻 LLM 首末层（freeze_llm=1），学习率 5e-6
  • 可跳过 Pretrain —— SFT 的 290 万条数据已包含 Pretrain 的 127 万条

每条数据的格式如下：

Parquet 文件列:
├── conversations: JSON 字符串
│   例: [{"role":"user","content":"<image>\n描述图片"},
│         {"role":"assistant","content":"这是一只金毛..."}]
│
└── image_bytes: 二进制 JPEG 数据
    例: <255, 216, 255, 224, ...>  (JPEG 文件头)

格式解读：conversations 是 JSON 格式的对话记录，<image> 标记图片出现的位置（后续会被替换为 64 个占位符）。image_bytes 是图片的二进制 JPEG 数据，直接从 Parquet 读取后用 Image.open(BytesIO()) 解码。这种把图片和文本打包在同一行的设计简化了数据管理。

为什么要混入纯文本对话？因为 SFT 数据中 92% 与图像有关。如果全用图文数据训练，模型可能"忘记"怎么做纯文本对话（灾难性遗忘）。纯文本数据就像"复习课"——确保模型在学习看图的同时，不丢掉语言能力。纯文本数据的 image_bytes 用 8x8 黑图占位，经过 SigLIP 处理后产生的视觉 token 对输出影响极小。

8.3 冻结策略详解

冻结策略决定了训练时哪些参数会被更新——这直接影响训练效率和模型能力。

MiniMind-V 有三个可控制的部分：视觉编码器（~95M 参数，始终冻结）、投影层（~1M 参数，始终训练）、LLM（~64M 参数，可变）。冻结策略通过 freeze_llm 参数控制 LLM 部分的训练范围。

  • 参数分布 —— 视觉编码器占绝大部分参数，但永远不动
  • 冻结策略对比 —— 三种策略的适用场景与设计原理

冻结策略对比与工作原理

三种冻结策略对应三种不同的训练阶段和数据量级。核心原则：数据越少，冻结越多——避免有限的数据破坏已经学到的知识。

策略 投影层 LLM 首层 LLM 中间层 LLM 末层 用途
freeze_llm=0 🔥 🔥 🔥 🔥 全参训练（数据充足时）
freeze_llm=1 🔥 🔥 ❄️ 🔥 SFT 默认
freeze_llm=2 🔥 ❄️ ❄️ ❄️ Pretrain 默认

为什么 SFT 解冻首末层？首层负责处理视觉和文本特征的融合——视觉 token 刚进来时需要适配；末层直接影响输出格式——需要学会生成看图回答的格式。中间层承载了 LLM 的核心语言知识，冻结它可以防止灾难性遗忘。

8.4 训练超参数对比

Pretrain 和 SFT 在学习率、batch size、序列长度等超参数上有显著差异。理解这些差异背后的原因，比记住数字更重要。

参数 Pretrain SFT 为什么不同
learning_rate 4e-4 5e-6 Pretrain 投影层随机初始化，需要大学习率快速收敛；SFT 微调已有权重，需要小学习率精细调整（差 80 倍！）
batch_size 16 4 Pretrain 任务简单（看图说描述），可以大 batch；SFT 任务复杂（看图推理问答），需要小 batch 精细学习
max_seq_len 450 768 Pretrain 主要是短描述（"这是一只金毛"）；SFT 包含长对话和多轮交互
freeze_llm 2 1 Pretrain 只需对齐视觉和语言；SFT 还需微调 LLM 学会指令遵循
数据量 ~127 万 ~290 万 SFT 数据已包含 Pretrain 数据，是 Pretrain 的超集

最重要的差异是学习率：4e-4 vs 5e-6，差了将近 80 倍。原因很简单——Pretrain 时投影层是随机初始化的（像一张白纸），需要大学习率快速学到有用的表示；SFT 时所有参数已经有了一个不错的起点，只需要小学习率微调。如果 SFT 用 4e-4 的学习率，会把已经学好的知识"冲掉"。

# 对应: train_sft_vlm.py 第27-79行
for step, (input_ids, labels, pixel_values) in enumerate(loader):
    # Step 1: 数据 → GPU
    input_ids = input_ids.to(device)                                    # 第28行
    labels = labels.to(device)                                          # 第29行
    pixel_values = pixel_values.to(device)                              # 第30行

    # Step 2: 余弦学习率 — 随训练进度平滑衰减
    lr = get_lr(epoch * iters + step, args.epochs * iters, learning_rate)
    for param_group in optimizer.param_groups:
        param_group['lr'] = lr                                          # 第33-34行

    # Step 3: 前向传播（混合精度）— BF16 加速
    with autocast_ctx:                                                  # 第36行
        res = model(input_ids, labels=labels, pixel_values=pixel_values)
        loss = (res.loss + res.aux_loss) / accumulation_steps           # 第38-39行

    # Step 4: 反向传播 — 自动求导
    scaler.scale(loss).backward()                                       # 第41行

    # Step 5: 梯度累积 + 裁剪 + 更新
    if step % accumulation_steps == 0:
        scaler.unscale_(optimizer)                                      # 第44行
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)        # 第45行 防止梯度爆炸
        scaler.step(optimizer)                                          # 第47行
        scaler.update()                                                 # 第48行
        optimizer.zero_grad(set_to_none=True)                           # 第50行

    # Step 6: 日志
    if step % log_interval == 0:
        Logger(f'Epoch:[{epoch+1}/{epochs}]({step}/{iters}), loss: {loss:.4f}')

    # Step 7: 保存模型
    if step % save_interval == 0:
        torch.save(model.state_dict(), ckp_path)                        # 第73行

关键机制逐个解释：get_lr() 实现余弦退火——学习率先保持 warmup，然后按余弦曲线衰减到接近 0。accumulation_steps 实现梯度累积——每 N 步才更新一次参数，等效于 batch_size 放大 N 倍。clip_grad_norm_ 梯度裁剪——将梯度范数限制在 1.0 以内，防止梯度爆炸导致训练崩溃。loss + aux_loss——主损失是交叉熵，辅助损失来自 MoE 的负载均衡。

8.6 混合精度训练

混合精度训练用 BFloat16 替代 Float32 进行前向和反向传播，在几乎不损失精度的情况下将速度提升近 2 倍、显存减半。这对小显存显卡训练大模型至关重要。

核心思路：模型权重保留一份 FP32 "主副本"（保证精度），但前向和反向传播用 BF16（提速减存）。梯度更新时回到 FP32（防止精度丢失）。加上损失缩放（Loss Scaling）防止 BF16 梯度下溢。整个循环自动完成，只需开启 autocast 和 GradScaler。

8.7 断点续训

训练过程中可能因为断电、OOM 等原因中断。断点续训机制确保从中断处继续，不丢失已训练的进度。

断点续训需要保存四个东西：模型权重（当前参数状态）、优化器状态（动量、自适应学习率等历史信息）、epoch 和 step（训练进度）、scaler 状态（混合精度的缩放因子）。加载时全部恢复，从上次的 step 继续训练。

GPU 数量适配：分布式训练时 step 数与 GPU 数量相关。保存时用 4 个 GPU，加载时只有 2 个 GPU，step 会自动转换：step = step * old_gpu_count / new_gpu_count。这确保不同硬件环境下断点续训的正确性。

安全保存策略：检查点先写入 .tmp 临时文件，写入完成后用 os.replace 原子替换正式文件。这样即使写入过程中断电，正式文件也不会损坏——要么是旧的完整检查点，要么是新的完整检查点。

8.8 自我检测

用以下问题检验你对训练流程的理解程度。尝试不看提示回答。

  1. 为什么 Pretrain 的学习率比 SFT 大 80 倍？
    提示：Pretrain 时投影层随机初始化（像白纸），需要大学习率快速收敛；SFT 时所有参数已有好的起点，需要小学习率精细调整
  2. SFT 数据为什么混入纯文本？
    提示：SFT 数据 92% 与图像有关，不混纯文本会导致模型"忘记"语言对话能力（灾难性遗忘）
  3. freeze_llm=1 解冻了哪些层？
    提示：投影层 + LLM 首层（处理视觉融合）+ LLM 末层（优化输出格式），中间层冻结保留语言知识
  4. 为什么要梯度裁剪？
    提示：防止梯度爆炸导致训练不稳定——将梯度范数限制在 1.0 以内
  5. 断点续训保存了什么？
    提示：模型权重 + 优化器状态（动量等）+ epoch/step 进度 + GradScaler 缩放因子
