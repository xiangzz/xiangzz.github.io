RMSNorm 类

RMS 归一化：比 LayerNorm 更高效，省去均值计算步骤。只有一个可学习参数 weight（γ），不像 LayerNorm 有 γ 和 β 两组。

class RMSNorm(torch.nn.Module):
    def __init__(self, dim: int, eps: float = 1e-5):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))  # [768] 可学习参数

    def norm(self, x):
        # x: [batch, seq, 768]
        return x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)

    def forward(self, x):
        return (self.weight * self.norm(x.float())).type_as(x)

逐行解析：

  • x.pow(2) —— 每个元素平方，形状不变 [batch, seq, 768]
  • .mean(-1, keepdim=True) —— 求最后一维（768）的平均值，得到 [batch, seq, 1]
  • torch.rsqrt(...) —— 取倒数平方根 = 1/√(均值+ε)
  • x * ... —— 广播乘法，每个元素除以均方根
  • x.float() —— 先转 float32 计算保证精度，.type_as(x) 转回原类型（如 bfloat16）

RoPE 预计算

预计算 RoPE 位置编码所需的 cos/sin 查找表。这张表在模型初始化时算一次，之后每次前向传播直接查表，不需要重复计算。

def precompute_freqs_cis(dim: int, end: int = 32768, rope_base: float = 1e6):
    # dim = 96 (head_dim), end = 32768 (max_position_embeddings)

    # Step 1: 频率表 [dim/2] = [48]
    freqs = 1.0 / (rope_base ** (torch.arange(0, dim, 2)[:dim//2].float() / dim))
    # freqs[i] = 1 / (1000000 ^ (2i/96))
    # i=0: freq = 1.0        (高频，捕捉相邻位置)
    # i=47: freq ≈ 0.00001   (低频，捕捉远距离位置)

    # YaRN 扩展（如果启用）
    if rope_scaling is not None:
        ramp = ...
        freqs = freqs * (1 - ramp + ramp / factor)

    # Step 2: 位置 × 频率 = 角度矩阵 [32768, 48]
    t = torch.arange(end)
    freqs = torch.outer(t, freqs)

    # Step 3: cos/sin 表 [32768, 96]
    freqs_cos = torch.cat([torch.cos(freqs), torch.cos(freqs)], dim=-1)
    freqs_sin = torch.cat([torch.sin(freqs), torch.sin(freqs)], dim=-1)
    return freqs_cos, freqs_sin

三步流程：(1) 构建 48 个频率值，从高频到低频；(2) 位置 [0, 1, ..., 32767] 与频率做外积，得到 32768×48 的角度矩阵；(3) 分别计算 cos 和 sin，拼接为 32768×96 的查找表。如果启用了 YaRN 扩展，会对频率做线性插值以支持超过 32768 的超长上下文。

Attention 类

这是整个模型最重要的类。它的 forward() 方法实现了完整的注意力计算流程。先看前三步：QKV 投影、多头重塑、RoPE 旋转、KV Cache 拼接。

def forward(self, x, position_embeddings, past_key_value=None, use_cache=False):
    bsz, seq_len, _ = x.shape    # [batch, seq, 768]

    # 1. 线性投影生成 Q, K, V
    xq = self.q_proj(x)          # [batch, seq, 768] → [batch, seq, 768]
    xk = self.k_proj(x)          # [batch, seq, 384] (GQA: 4个KV头 × 96维)
    xv = self.v_proj(x)          # [batch, seq, 384]

    # 2. 重塑为多头格式
    xq = xq.view(bsz, seq_len, 8, 96)   # [batch, seq, 8_Q_heads, 96]
    xk = xk.view(bsz, seq_len, 4, 96)   # [batch, seq, 4_KV_heads, 96]
    xv = xv.view(bsz, seq_len, 4, 96)

    # 3. QK 归一化（提升训练稳定性）
    xq, xk = self.q_norm(xq), self.k_norm(xk)

    # 4. 应用 RoPE 位置编码
    cos, sin = position_embeddings
    xq, xk = apply_rotary_pos_emb(xq, xk, cos, sin)

    # 5. KV Cache: 拼接过去的 K, V
    if past_key_value is not None:
        xk = torch.cat([past_key_value[0], xk], dim=1)   # 沿序列维度拼接
        xv = torch.cat([past_key_value[1], xv], dim=1)
    past_kv = (xk, xv) if use_cache else None

关键步骤说明：

  • Step 3 QK 归一化：q_norm 和 k_norm 对 Q 和 K 做额外的归一化，这是一个训练稳定性技巧，防止注意力分数过大
  • Step 5 KV Cache：推理时 past_key_value 不为 None，它存储了之前所有 Token 的 K 和 V。新 Token 的 K/V 直接拼接到缓存后面，避免重复计算

Attention 计算细节

QKV 准备好之后，接下来是注意力计算的核心步骤：GQA 扩展（repeat_kv）、两条计算路径（Flash / 手动）、输出投影。

    # 6. 转置 + repeat_kv 为注意力计算做准备
    xq = xq.transpose(1, 2)                          # [batch, 8, seq, 96]
    xk = repeat_kv(xk.transpose(1, 2), self.n_rep)   # [batch, 8, total_seq, 96]
    xv = repeat_kv(xv.transpose(1, 2), self.n_rep)   # [batch, 8, total_seq, 96]
    # n_rep = 8/4 = 2，每个 KV 头复制 2 次给 2 个 Q 头使用

    # 7. 计算注意力（两条路径）
    if self.flash:
        # Flash Attention 路径（更快，自动处理因果掩码）
        output = F.scaled_dot_product_attention(xq, xk, xv, is_causal=True)
    else:
        # 手动计算路径（更易理解）
        scores = (xq @ xk.transpose(-2, -1)) / math.sqrt(96)  # [batch, 8, seq, total_seq]
        scores[:, :, :, -seq_len:] += causal_mask                 # 因果掩码
        output = F.softmax(scores, dim=-1) @ xv                  # Softmax + 乘V

    # 8. 输出投影
    output = output.transpose(1, 2).reshape(bsz, seq_len, -1)  # [batch, seq, 768]
    output = self.o_proj(output)                                 # [batch, seq, 768]
    return output, past_kv

repeat_kv 做了什么？4 个 KV 头要服务 8 个 Q 头。方法很简单：每个 KV 头复制 n_rep=2 份。虽然看起来"浪费"，但矩阵运算的并行性让这比真正减少 Q 头数更高效。

两条路径：Flash Attention 是 PyTorch 2.0+ 的优化实现，自动处理因果掩码和内存优化。手动路径更易理解，适合调试。两者结果完全一致。

FeedForward 类

SwiGLU 前馈网络：gate_proj 与 up_proj 配合实现门控机制。代码只有一行，但包含三个线性变换和一个门控激活。

class FeedForward(nn.Module):
    def __init__(self, config):
        # gate_proj: 768 → 2432  (升维)
        # up_proj:   768 → 2432  (升维，与 gate 配合)
        # down_proj: 2432 → 768  (降维)
        # act_fn: SiLU (sigmoid(x) * x)
        self.gate_proj = nn.Linear(config.hidden_size, intermediate_size, bias=False)
        self.down_proj = nn.Linear(intermediate_size, config.hidden_size, bias=False)
        self.up_proj = nn.Linear(config.hidden_size, intermediate_size, bias=False)
        self.act_fn = ACT2FN[config.hidden_act]  # SiLU

    def forward(self, x):
        return self.down_proj(self.act_fn(self.gate_proj(x)) * self.up_proj(x))

SwiGLU 公式拆解：down_proj( SiLU(gate_proj(x)) * up_proj(x) )。三个路径各有分工：

  • gate_proj(x) —— 升维到 2432，经 SiLU 激活后变成 0~1 之间的门控信号
  • up_proj(x) —— 升维到 2432，是实际要传递的信息
  • 两者逐元素相乘——门控信号控制信息的通过量
  • down_proj(...) —— 降维回 768，恢复原始维度

MiniMindBlock

一个完整的 Transformer 层：Pre-Norm + Self-Attention + FFN + 残差连接。这是模型堆叠的基本单元，MiniMind-V 堆叠了 8 个这样的 Block。

class MiniMindBlock(nn.Module):
    def __init__(self, layer_id, config):
        self.self_attn = Attention(config)                           # 注意力
        self.input_layernorm = RMSNorm(config.hidden_size)          # 注意力前的归一化
        self.post_attention_layernorm = RMSNorm(config.hidden_size) # FFN前的归一化
        self.mlp = FeedForward(config) if not config.use_moe \
              else MOEFeedForward(config)                           # FFN 或 MoE

    def forward(self, hidden_states, position_embeddings, ...):
        residual = hidden_states                                    # 保存输入
        hidden_states, present = self.self_attn(                    # 注意力
            self.input_layernorm(hidden_states),                    # ← 先归一化
            position_embeddings, past_key_value, use_cache)
        hidden_states += residual                                   # ← 残差连接

        residual = hidden_states                                    # 保存
        hidden_states = self.mlp(                                   # FFN
            self.post_attention_layernorm(hidden_states))           # ← 先归一化
        hidden_states += residual                                   # ← 残差连接

        return hidden_states, present

代码结构完全对应 Pre-Norm 残差设计：每个子模块前都有一个 RMSNorm，子模块的输出与原始输入相加（残差连接）。输入和输出形状完全一致 [batch, seq, 768]，因此可以无限堆叠。如果 config.use_moe=True，则使用 MoE 版的 FFN 替代标准 FFN。

完整模型

顶层模型类，把所有组件组装到一起。继承 HuggingFace 的 PreTrainedModel 和 GenerationMixin，兼容 HuggingFace 生态。

class MiniMindForCausalLM(PreTrainedModel, GenerationMixin):
    def __init__(self, config):
        self.model = MiniMindModel(config)                # Transformer 主体
        self.lm_head = nn.Linear(768, 6400, bias=False)   # 输出映射到词表
        if config.tie_word_embeddings:
            self.model.embed_tokens.weight = self.lm_head.weight  # 共享权重

    def forward(self, input_ids, labels=None, ...):
        hidden_states, past_kv, aux_loss = self.model(input_ids, ...)  # Transformer
        logits = self.lm_head(hidden_states)                             # [batch, seq, 6400]
        if labels is not None:
            # Shift + 交叉熵损失
            loss = F.cross_entropy(logits[..., :-1, :], labels[..., 1:], ignore_index=-100)
        return MoeCausalLMOutputWithPast(loss=loss, logits=logits, ...)

关键设计解读：

  • self.model —— MiniMindModel 内部包含 Embedding 层 + 8 个 MiniMindBlock + 最终 RMSNorm
  • self.lm_head —— 将 768 维的隐藏状态映射到 6400 维的词表空间，得到每个词的 logits
  • 权重共享：embed_tokens.weight = lm_head.weight，减少约 500 万参数
  • Shift 技巧：logits[..., :-1, :] 去掉最后一个位置的预测，labels[..., 1:] 去掉第一个位置的标签，错位对齐实现"用前面的词预测下一个词"

    logits = self.lm_head(hidden_states)
    print(f"4. logits: {logits.shape}")

预期输出（以 batch=1, seq_len=10 为例）：

1. input_ids: torch.Size([1, 10]) —— 整数 Token ID

2. after embedding: torch.Size([1, 10, 768]) —— 每个 Token 变成 768 维向量

3. after transformer: torch.Size([1, 10, 768]) —— 经过 8 层 Block 后形状不变

4. logits: torch.Size([1, 10, 6400]) —— 映射到词表空间的概率分布

排错：我 print 出来的形状和速查表对不上？

多半是输入设置不同，不是代码错了。最常见的两个原因：

  • batch_size 不同：表里用 [1, 10, 768]，你如果用 batch=4 会看到 [4, 10, 768]，第一维是你的 batch。
  • 注意力中间形状带 num_key_value_heads：看 K/V 时如果出现 4 而不是 8，别慌——那是 GQA，K/V 只有 4 个头，后面 repeat_kv 会复制成 8 个。

遇到形状疑问，先确认 batch 和 num_key_value_heads 这两个变量。

动手：追踪一次前向传播。在 MiniMindBlock.forward() 的残差连接前后各加一个 print(hidden_states.shape)，跑一次推理，验证残差连接不改变张量形状。

预期结果

进入 Block:  torch.Size([1, 10, 768])
Attention 后: torch.Size([1, 10, 768])   # 残差相加，形状不变
FFN 后:       torch.Size([1, 10, 768])   # 残差相加，形状不变
离开 Block:  torch.Size([1, 10, 768])   # 8 层都是 768 维

如果任何一步形状变了，说明残差连接写错了——这是定位 bug 的好方法。

5.4 关键维度速查表

模型各阶段张量形状一览。阅读源码时随时查阅，帮助你快速定位"这一步的形状对不对"。

  • 完整维度追踪 —— 从输入到输出每一步的张量形状
  • 速查参考 —— 阅读源码时随时查阅维度变化

关键维度速查表

以 batch=1, seq_len=10 为例，追踪从输入到输出的每一步形状变化：

阶段 变量 形状 说明
输入input_ids[1, 10]Token ID 序列
嵌入后hidden_states[1, 10, 768]每个 Token 查表得到 768 维向量
Q 投影后xq[1, 10, 8, 96]8 个 Q 头，每头 96 维
K 投影后xk[1, 10, 4, 96]4 个 K 头（GQA）
repeat_kv 后xk[1, 10, 8, 96]每个 KV 头复制 2 份
转置后xq[1, 8, 10, 96]head 维度提前，便于矩阵运算
注意力分数scores[1, 8, 10, 10]每对词之间的关注度
注意力输出output[1, 10, 768]恢复原始维度
FFN 中间gate/up[1, 10, 2432]升维到 2432
FFN 输出down[1, 10, 768]降维回 768
lm_head 后logits[1, 10, 6400]映射到词表空间的 logits

关键规律：Transformer Block 内部所有操作的输入输出都是 [batch, seq, 768]——形状完全不变。唯一改变形状的操作发生在模型的两端：输入端的 Embedding（ID → 向量）和输出端的 lm_head（向量 → 词表 logits）。
