4.1 直觉与动机

在深入公式和代码之前，先用直觉理解 Transformer 为什么要这样设计。

  • 为什么需要注意力 —— 让每个词"看"所有其他词，计算"我应该关注谁"
  • 为什么替代 RNN —— 并行计算、长距离依赖，Transformer 的两大优势

为什么需要注意力？

考虑这句话："这只猫坐在垫子上，它很开心"。

"它"指代什么？人类一眼就知道是"猫"。但计算机怎么知道？答案是让每个词都去"看"所有其他词，计算自己应该最关注谁。

注意力的核心思想：让每个词"看"所有其他词，计算"我应该关注谁"。在上面的例子中，"它"对"猫"的注意力权重最高，因此模型能理解"它"指代的是"猫"。

为何取代 RNN

图：RNN vs Transformer 对比

【AI 生图提示词】请生成一张中文对比示意图，风格简洁、配色柔和、适合教学： - 画面主体：左右对比布局 - 左侧"RNN（旧方案）"：词1→词2→词3→词4 顺序连接，标注"必须一个一个处理，慢！远距离依赖弱" - 右侧"Transformer（新方案）"：词1、词2、词3、词4 之间两两互连，标注"所有词同时处理，快！直接捕捉远距离关系" - 配色建议：RNN 侧用浅红色背景，Transformer 侧用浅绿色背景 - 画面比例：16:9 - 避免：过度装饰、3D 效果

两大优势：

  • 并行计算 —— RNN 必须按顺序逐词处理（词 2 必须等词 1 处理完），无法并行。Transformer 的所有词同时处理，GPU 利用率极高。
  • 长距离依赖 —— RNN 中第 1 个词的信息要传递 100 步才能影响第 101 个词，信息衰减严重。Transformer 中任意两个词之间直接"连线"，无论距离多远。

  • 全局数据流 —— 从 Token IDs 到输出 Logits 的完整管线
  • Transformer Block —— 单个 Block 的 Pre-Norm 残差结构

  • FeedForward —— 对每个词独立做非线性变换，相当于"思考和处理"

4.3 RMSNorm

比 LayerNorm 更高效的归一化方式。MiniMind-V 在每个子模块之前都加了一个 RMSNorm。

  • 为什么需要归一化 —— 防止深层网络中数值爆炸或消失
  • RMSNorm vs LayerNorm —— 更快、更简洁的替代方案
  • 代码解读与手动计算 —— 理解每一行在做什么

为什么需要归一化？

Transformer 有 8 层，每层都做矩阵乘法。如果不在层与层之间做归一化，数值会指数级增长，几层之后就溢出了。

图：归一化前后对比

【AI 生图提示词】请生成一张中文对比示意图，风格简洁、配色柔和、适合教学： - 画面主体：左右对比 - 左侧"没有归一化 ❌"：层1输出 [0.1, 0.2] → 层2输出 [1.2, 3.4] → 层3输出 [45.6, 89.1] → 层4输出 [INF, INF] 数值爆炸，用红色警告标志 - 右侧"有归一化 ✅"：层1输出 [0.1, 0.2] → 归一化 [0.12, 0.24] → 层2输出 [0.3, 0.5] → 归一化 [0.15, 0.25] 数值稳定，用绿色对勾 - 配色建议：左侧浅红背景，右侧浅绿背景 - 画面比例：16:9 - 避免：过度装饰、3D 效果

归一化的作用就像一个"阀门"：每层输出后把数值范围压缩回合理区间，防止逐层放大导致数值爆炸（NaN / INF）。

对比 LayerNorm

LayerNorm 和 RMSNorm 的目的相同——归一化向量，但 RMSNorm 省去了减均值和偏置的计算，更快且效果相当。

LayerNorm（传统方案）

# 三步操作:
# 1. 减均值: x - mean(x)
# 2. 除标准差: / std(x)
# 3. 乘以 gamma, 加 beta
# 需要两组可学习参数 (gamma + beta)

RMSNorm（MiniMind 使用）

# 两步操作:
# 1. 除均方根: x / sqrt(mean(x²))
# 2. 乘以 gamma
# 省去减均值和偏置！
# 只需一组可学习参数 (gamma)

RMSNorm 的核心公式：output = x / √(mean(x²) + ε) × γ。其中 ε 是防止除零的小常数（MiniMind 用 1e-6），γ 是可学习的缩放参数。省去减均值操作在工程上减少了计算量，且实验表明对训练效果没有负面影响。

RMSNorm 代码

# model_minimind.py 第50-60行
class RMSNorm(torch.nn.Module):
    def __init__(self, dim: int, eps: float = 1e-6):  # MiniMind 实例化时传 config.rms_norm_eps=1e-6
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))  # 可学习的缩放参数 γ

    def norm(self, x):
        return x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)
        # x.pow(2)          → 每个元素平方
        # .mean(-1, keepdim) → 求最后一个维度的平均值（均方）
        # torch.rsqrt        → 取倒数平方根（1/√x）
        # 最终: x / √(mean(x²) + ε)

    def forward(self, x):
        return (self.weight * self.norm(x.float())).type_as(x)
        # 1. 先转 float32 计算保证精度
        # 2. 乘以可学习参数 weight
        # 3. 转回原类型

用具体数字验证，假设 γ 全为 1：

输入 x = [1.0, 2.0, 3.0, 4.0]

Step 1: 平方     x² = [1.0, 4.0, 9.0, 16.0]
Step 2: 均值     mean(x²) = (1+4+9+16)/4 = 7.5
Step 3: rsqrt    1/√(7.5 + 0.000001) ≈ 0.3651
Step 4: 缩放     output = [0.365, 0.730, 1.095, 1.460]

注意缩放后各元素的比例关系保持不变（1:2:3:4），只是整体大小被归一化了。这正是 RMSNorm 的作用——让数值保持在合理范围，同时不改变向量的方向。

4.4 RoPE

Transformer 不知道词的顺序，RoPE 通过旋转向量来编码位置信息。

  • 问题 —— 自注意力是"对称的"，打乱词序语义丢失
  • RoPE 原理 —— 每个位置的向量被旋转不同角度，点积自然包含相对位置
  • 代码解读 —— 预计算频率表和应用旋转的完整实现

词序问题

自注意力的计算是"对称的"——如果你把输入序列 ["我", "爱", "北京"] 打乱成 ["北京", "我", "爱"]，注意力矩阵只是行顺序变了，计算方式完全一样。这意味着模型无法区分"我爱北京"和"北京爱我"。

RoPE 的解决方案：通过旋转向量来编码位置信息。每个位置的向量被旋转不同的角度。低维度旋转快（捕捉局部位置关系），高维度旋转慢（捕捉远距离位置关系）。

RoPE 预计算频率表

RoPE 不在每次前向传播时计算旋转角度，而是提前计算好一张 cos/sin 表，训练和推理时直接查表。

# model_minimind.py 第62-78行
def precompute_freqs_cis(dim, end=32768, rope_base=1e6):
    # dim = 96 (head_dim), end = 32768 (max_position_embeddings)

    # Step 1: 计算每个维度的旋转频率
    freqs = 1.0 / (rope_base ** (torch.arange(0, dim, 2).float() / dim))
    # freqs[i] = 1 / (1000000 ^ (2i/dim))
    # 低维度 → 高频率（旋转快） → 捕捉局部位置关系
    # 高维度 → 低频率（旋转慢） → 捕捉远距离位置关系

    # Step 2: 计算每个位置的旋转角度
    t = torch.arange(end)                # 位置序列 [0, 1, 2, ..., max_len]
    freqs = torch.outer(t, freqs)        # 角度矩阵 [max_len, dim/2]
    # angles[pos, dim] = pos × freq[dim]

    # Step 3: 计算 cos 和 sin 表
    freqs_cos = torch.cat([torch.cos(freqs), torch.cos(freqs)], dim=-1)
    freqs_sin = torch.cat([torch.sin(freqs), torch.sin(freqs)], dim=-1)
    return freqs_cos, freqs_sin

两步计算的关键：torch.outer 在做什么？Step 1 算出的是每个维度的旋转速度（频率），Step 2 把"位置"和"频率"做外积，得到每个位置在每个维度上该旋转的角度——

角度 = 位置 × 频率

位置 0：所有维度角度都是 0（不旋转）
位置 1：第 0 维转 1.0 弧度，第 1 维转 0.012 弧度 ...
位置 2：第 0 维转 2.0 弧度，第 1 维转 0.024 弧度 ...

所以同一段文本里，位置靠后的词在每个维度上累积的角度更大。这正是"编码了位置"的来源。

关键理解：频率从高到低分布。第 0 维的频率是 1.0（每个位置都旋转很大角度），高维度的频率极小（约百万分之一量级，旋转极其缓慢）。这就像时钟——秒针转得快（捕捉细节），时针转得慢（捕捉大趋势）。

RoPE 应用旋转位置编码

预计算好 cos/sin 表后，在注意力计算前对 Q 和 K 向量做旋转操作：

# model_minimind.py 第80-84行
def apply_rotary_pos_emb(q, k, cos, sin):
    def rotate_half(x):
        # 把向量拆成两半，交换并取反
        return torch.cat((-x[...,后半], x[...,前半]), dim=-1)

    q_embed = q * cos + rotate_half(q) * sin    # 旋转 Query
    k_embed = k * cos + rotate_half(k) * sin    # 旋转 Key
    return q_embed, k_embed

4.5 自注意力

最核心的组件——让模型理解词与词之间的关系。

  • Q, K, V —— Query（我在找什么）、Key（我有什么）、Value（我的内容）
  • 注意力分数 —— Q 和 K 点积，衡量词之间的关注程度
  • 因果掩码 —— 防止"偷看"未来的词
  • 多头注意力 —— 多个头分别捕捉不同类型的关系
  • GQA —— 分组查询注意力，减少内存
  • KV Cache —— 缓存已计算的 K/V，加速推理

注意力整体流程

Self-Attention 的核心公式是 Attention(Q, K, V) = Softmax(QK^T / √d) × V。但这行公式背后包含多个步骤，让我们逐一看清。

Step 1: QKV

每个词通过三个不同的线性变换，变成三种角色。一个生动的比喻：你在图书馆找书——Q 是你的搜索关键词，K 是每本书的标签，V 是书的实际内容。

# model_minimind.py 第113-116行
xq = self.q_proj(x)    # Query: "我想知道什么"    [batch, seq, 768]
xk = self.k_proj(x)    # Key:   "我有什么特征"    [batch, seq, 384]
xv = self.v_proj(x)    # Value: "我的实际内容"    [batch, seq, 384]

# 重塑为多头形式
xq = xq.view(bsz, seq_len, 8, 96)   # 8 个 Q 头，每头 96 维
xk = xk.view(bsz, seq_len, 4, 96)   # 4 个 K 头（GQA）
xv = xv.view(bsz, seq_len, 4, 96)   # 4 个 V 头（GQA）
对照源码时你会多看到两行：QK-Norm

真实代码（model_minimind.py 第 117 行）在投影之后、应用 RoPE 之前，还对 Q 和 K 各做了一次 RMSNorm：

xq, xk = self.q_norm(xq), self.k_norm(xk)   # 第 117 行

这是近年训练稳定性的改进（QK-Norm）。它的作用是控制 Q、K 的数值范围，防止点积过大导致 Softmax 饱和。本教程为了讲清主线先省略了它——如果你照着源码读，记得这一步在 RoPE 之前。

注意 K 和 V 只有 4 个头，而 Q 有 8 个头。这就是 GQA（分组查询注意力）的核心——多个 Q 头共享同一组 K/V 头。这样做的好处是减少 KV Cache 的内存占用，同时保持和标准多头注意力几乎相同的效果。

Step 2: 分数与掩码

Q 和 K 做点积得到注意力分数矩阵。每个矩阵元素表示"第 i 个词对第 j 个词的关注程度"：

# Q 和 K 做点积，得到每个词对其他词的"关注程度"
scores = Q @ K^T / √(head_dim)
# 形状: [batch, heads, seq, seq]
# scores[b, h, i, j] = 第 b 个样本, 第 h 个头, 第 i 个词对第 j 个词的关注度

为什么要除以 √(head_dim)？当 head_dim 较大时（MiniMind 是 96），Q 和 K 的点积是 96 个乘积之和，数值会随之放大。如果不缩放，点积经常大到让 Softmax 落进"饱和区"——最大值对应的概率接近 1，其余全是 0，梯度几乎消失。除以 √d 把点积的方差拉回到约 1 的量级，让 Softmax 输出保持在梯度敏感的中间区域，训练才稳定。

以"我爱北京天安门"为例，4×4 矩阵中 scores[i][j] 表示第 i 个词对第 j 个词的关注度。数值越大颜色越深。

因果掩码（关键！）

语言模型不能偷看未来。上三角区域设为 -inf，Softmax(-inf) = 0，所以未来位置的权重变成 0。每个词只能看到自己和之前的词。

多头与 GQA

为什么不只用一个注意力头？因为词与词之间的关系有多种类型——语法关系、语义关系、指代关系……一个头学不过来。多头注意力让每个头专注不同的关系类型。

8 个头各自独立计算注意力，最后拼接回 768 维。MiniMind-V 进一步使用 GQA：8 个 Q 头共享 4 组 K/V 头（每 2 个 Q 头共享 1 组 K/V）。好处：减少内存、加快推理速度，效果几乎不变。GQA 是 LLaMA、Mistral 等主流模型的共同选择。

KV Cache

自回归生成时，每次只新增一个 Token，但前面的 Token 需要重新算 K 和 V 吗？不需要——缓存起来直接复用。

图：有无 KV Cache 对比

【AI 生图提示词】请生成一张中文对比示意图，风格简洁、配色柔和、适合教学： - 画面主体：左右对比 - 左侧"没有 KV Cache ❌"：生成第1词计算Q₁K₁→O₁ → 生成第2词重新计算Q₁K₁Q₂K₁Q₂K₂→O₂ → 生成第3词重新计算所有QK→O₃，标注"大量重复计算" - 右侧"有 KV Cache ✅"：生成第1词计算Q₁K₁→O₁并缓存K₁V₁ → 生成第2词Q₂×(缓存K₁+K₂)→O₂只算新部分 → 生成第3词Q₃×(缓存K₁K₂+K₃)→O₃只算新部分 - 配色建议：左侧浅红背景，右侧浅绿背景 - 画面比例：16:9 - 避免：过度装饰、3D 效果

KV Cache 的核心思想：已经计算过的 K 和 V 不需要重复计算，缓存起来直接复用。每次只需要计算新 Token 的 Q 与所有缓存的 K/V 的注意力。推理速度提升非常显著——生成长序列时，没有 KV Cache 的话计算量会随长度平方增长，有 KV Cache 则只线性增长。

4.6 前馈网络

如果说注意力是在"收集信息"，那么 FFN 就是在"思考和处理信息"。注意力层让词与词之间交互，FFN 层让每个词独立进行非线性变换。

  • SwiGLU 架构 —— 升维→门控激活→降维的三路结构
  • 代码解读 —— gate_proj、up_proj、down_proj 的协作方式

SwiGLU 架构与代码

MiniMind-V 使用 SwiGLU 作为前馈网络。它的特点是三路结构：gate_proj 和 up_proj 两个升维路径，通过门控机制（SiLU 激活）控制信息流动。

图：SwiGLU 前馈网络结构

【AI 生图提示词】请生成一张中文技术示意图，风格简洁、配色柔和、适合教学： - 画面主体：从左到右的流程图 - 流程：输入 x [batch, seq, 768] → 分两路：上 gate_proj(x) 768→2432 → SiLU激活 sigmoid(x)×x；下 up_proj(x) 768→2432 → 两路逐元素相乘 ⊙ → down_proj 2432→768 → 输出 [batch, seq, 768] - 配色建议：gate 路蓝色，up 路橙色，乘法节点紫色，down_proj 绿色 - 画面比例：16:9 - 避免：过度装饰、3D 效果 

# model_minimind.py 第136-146行
class FeedForward(nn.Module):
    def forward(self, x):
        return self.down_proj(self.act_fn(self.gate_proj(x)) * self.up_proj(x))
        #                ↑ 降维            ↑ SiLU激活       ↑ 升维     ↑ 升维
        #                2432→768          2432→2432         768→2432   768→2432

为什么升维到 2432？768 维到 2432 维（约 3.17 倍），给模型更多的"思考空间"。这个倍率来自 MiniMind 特有的 π 缩放：ceil(hidden_size × π / 64) × 64，与 LLaMA 的 8/3 倍缩放不同。gate_proj 通过 SiLU 激活函数生成 0~1 之间的门控信号，控制 up_proj 的信息有多少通过。这种门控机制比简单的 ReLU 激活更灵活，被 LLaMA、Mistral 等主流模型广泛采用。

4.7 MoE

多个专家 FFN 由 Router 分配，参数量大但计算量不变。MiniMind-V 支持可选启用 MoE。

  • 核心思想 —— Router 为每个 token 选择最合适的专家
  • 为什么用 MoE —— 总参数多但激活参数少
  • 负载均衡损失 —— 防止所有 token 涌向同一个专家

MoE 核心思想与优势

MoE 的灵感来自现实世界的专家分工：不用一个"全科医生"处理所有问题，而是有多个"专科医生"，根据问题类型选择最合适的一个。

图：MoE 路由机制

【AI 生图提示词】请生成一张中文技术示意图，风格简洁、配色柔和、适合教学： - 画面主体：流程图 - 流程：输入 Token → 路由器打分 [0.1, 0.6, 0.2, 0.1] → 选择得分最高的专家 → Expert 0（未选中灰色）/ Expert 1 ✅（选中高亮）/ Expert 2（未选中灰色）/ Expert 3（未选中灰色）→ 加权输出 0.6 × Expert1(x) - 配色建议：Router 橙色，选中专家绿色，未选中专家灰色 - 画面比例：16:9 - 避免：过度装饰、3D 效果

MiniMind-V 配置了 4 个专家 FFN，每个 Token 只激活 1 个。对比 Dense 模型：

模型总参数量每次激活参数效果
Dense (65M)65M65M基准
MoE (200M)200M~65M更好

MoE 的总参数是 Dense 的 3 倍，但每次只激活 1/4，计算量几乎不变。用少量计算获得大模型的效果——这是 MoE 的核心优势。

负载均衡损失

MoE 有一个潜在问题：Router 可能总是选同一个专家，其他专家完全闲置。为了防止这种情况，MiniMind-V 添加了辅助损失函数来惩罚不均匀的专家使用。

# model_minimind.py 第171-175行
# 问题: Router 可能总是选同一个专家，其他专家浪费了
# 解决: 添加辅助损失，惩罚不均匀的专家使用

load = F.one_hot(topk_idx, num_experts).float().mean(0)  # 每个专家被选中的频率
aux_loss = (load * scores.mean(0)).sum() * num_experts * coef
# 如果所有专家被均匀选中 → aux_loss 小 ✅
# 如果某个专家总是被选中 → aux_loss 大 ❌ → 反向传播会惩罚这种行为

为什么乘 load * score 而不是只看 load？只看 load 的话，专家被均分了但每个都不太确定，没解决问题。load * score 惩罚"既被频繁选中又自信"的专家，迫使 Router 的决策更分散、更均匀。这个辅助损失乘以一个小系数 router_aux_loss_coef=0.0005，不会干扰主训练目标。

残差连接的关键作用：让梯度可以直接"跳过"某些层传回去，使 8 层甚至更深的网络也能正常训练。没有它，梯度会在反向传播中逐层衰减（梯度消失），底层参数几乎无法更新。

4.9 自回归生成

逐 Token 生成文本——从预测到采样。模型不是一次输出整句话，而是一个字一个字地预测，每次把预测结果拼回输入，再预测下一个字。

  • 生成过程 —— 一个字一个字地预测，每次把预测结果拼回输入
  • 采样策略 —— Temperature、Top-K、Top-P 控制生成质量

生成过程

图：自回归生成序列图

【AI 生图提示词】请生成一张中文时序图，风格简洁、配色柔和、适合教学： - 画面主体：三列时序图——用户输入、模型、输出 - 流程：用户→模型"请描述这张图片" → 模型→输出预测"这"（当前输入："请描述这张图片这"）→ 模型→输出预测"张"（当前输入："请描述这张图片这张"）→ 模型→输出预测"图" → ... → 模型→输出预测"<eos>" → 生成结束 - 每步输入越来越长，标注"每次把预测结果拼回输入" - 配色建议：浅蓝背景，用户绿色，模型蓝色，输出橙色 - 画面比例：16:9 - 避免：过度装饰、3D 效果

模型输出的不是文字，而是词表上的概率分布（6400 个词各有一个概率值）。从概率分布中选出一个词作为输出，就是"采样"。采样策略决定了模型输出是保守还是大胆。

三种采样策略

模型输出概率分布后，如何从中选出一个词？直接选概率最高的（贪心解码）往往过于死板。三种策略各有特点：

Temperature（温度）

控制概率分布的"尖锐程度"：

  • T < 1（如 0.5）：分布更尖锐，高概率词更突出 → 更确定、更保守
  • T = 1：原始分布不变
  • T > 1（如 2.0）：分布更平坦，低概率词也有机会 → 更随机、更多样

公式：prob = Softmax(logits / T)

Top-K 与 Top-P

Top-K：只保留概率最高的 K 个词（如 K=50），其余概率设为 0，然后从候选中采样。简单直接。

Top-P（核采样）：把词按概率从高到低排序，累加概率直到超过 P（如 0.85）就截断。比 Top-K 更灵活——当模型很确定时候选少，不确定时候选多。

实际使用时通常组合：Temperature + Top-P 或 Temperature + Top-K + Top-P。

RMSNorm

比 LayerNorm 更快，省去减均值操作。每层输出后归一化，防止数值爆炸。

RoPE

旋转位置编码，让模型知道词的顺序。点积只取决于相对位置差。

自注意力

Q/K/V + 因果掩码 + 多头 + GQA。让每个词看到上下文，但不偷看未来。

FFN / MoE

SwiGLU 门控前馈网络。MoE 多专家路由，参数多但计算量不变。

残差连接

让梯度直接跳过某些层，支持 8 层深层网络的稳定训练。

采样策略

Temperature 控制随机性，Top-K/Top-P 限制候选范围，组合使用效果好。
