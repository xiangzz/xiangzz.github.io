model_vlm.py

VLM 核心模型定义：配置、视觉编码器集成与投影层

这是最重要的一个文件。在上一阶段你已经理解了 VLM 的三大组件和 forward() 流程，现在我们逐行阅读代码，看这些概念是如何落地的。按顺序阅读：VLMConfig → MiniMindVLM 类 → forward() → generate()。

  • VLMConfig —— 视觉相关配置参数的定义（9 行）
  • MiniMindVLM 类 —— 继承 LLM，组合视觉编码器与投影层
  • forward() 方法 —— VLM 前向传播的 5 个步骤
  • generate() 方法 —— 支持多图推理的生成逻辑

VLMConfig 与类

VLMConfig 继承自 LLM 的 MiniMindConfig，新增了 4 个视觉相关参数。MiniMindVLM 继承自 MiniMindForCausalLM，通过 super().__init__() 获得 LLM 的全部能力，再额外加载视觉编码器和创建投影层。

class VLMConfig(MiniMindConfig):      # 继承 LLM 的配置
    model_type = "minimind-v"

    def __init__(self,
        image_special_token='<|image_pad|>',   # 图片占位符
        image_ids=[12],                         # 占位符的 token ID
        image_hidden_size=768,                  # 视觉特征维度
        image_token_len=64,                     # 每张图的 token 数
        **kwargs):
        self.image_special_token = image_special_token
        self.image_ids = image_ids
        self.image_hidden_size = image_hidden_size
        self.image_token_len = image_token_len
        super().__init__(**kwargs)              # 传递其余参数给父类

Config 解读：image_special_token 是文本中的图片占位符字符串；image_ids=[12] 是占位符在词表中的 ID；image_hidden_size=768 是 SigLIP2 输出的特征维度；image_token_len=64 是每张图片生成的 token 数。注意 **kwargs 会把其余参数（如 hidden_size、num_layers 等）传递给父类 MiniMindConfig。

class MiniMindVLM(MiniMindForCausalLM):    # 继承 LLM！
    config_class = VLMConfig

    def __init__(self, config, vision_model_path="./model/siglip2-base-p32-256-ve"):
        self.config = config or VLMConfig()
        super().__init__(self.config)                     # 初始化 LLM 部分
        self.vision_encoder, self.processor = \           # 加载视觉编码器
            self.__class__.get_vision_model(vision_model_path)
        self.vision_proj = MMVisionProjector(             # 创建投影层
            self.config.image_hidden_size,                # 输入: 768 (视觉特征)
            self.config.hidden_size)                      # 输出: 768 (LLM 隐藏维度)

初始化流程：第4行先初始化 LLM（super().__init__()），获得嵌入层、8 层 Transformer、lm_head 等全部组件。第5-6行加载冻结的视觉编码器。第7-9行创建投影层，输入维度为视觉特征维度（768），输出维度为 LLM 隐藏维度（768）。三者组合起来，就是完整的 VLM。

forward 方法

这是 VLM 的核心——前向传播。上一阶段你已经看过七步流程图，现在看代码实现。关键点是 Step 2 中视觉处理只在有图片且处于序列起始位置时执行（KV Cache 推理时跳过）。

def forward(self, input_ids, labels=None, pixel_values=None, **args):
    batch_size, seq_length = input_ids.shape

    # === Step 1: 文本嵌入 ===
    hidden_states = self.model.dropout(self.model.embed_tokens(input_ids))
    # [batch, seq, 768] — 和纯 LLM 完全一样

    # === Step 2: 处理视觉输入 ===
    if pixel_values is not None and start_pos == 0:
        # 2a: 提取视觉特征并投影
        if hasattr(pixel_values, 'keys'):  # 字典格式 (SigLIP 输出)
            vision_tensors = self.vision_proj(
                MiniMindVLM.get_image_embeddings(pixel_values, self.vision_encoder))
        # 2b: Token 替换 — 用视觉特征替换占位符嵌入
        hidden_states = self.count_vision_proj(
            tokens=input_ids, h=hidden_states,
            vision_tensors=vision_tensors, seqlen=seq_length)

    # === Step 3: Transformer 处理 ===
    # 和纯 LLM 完全一样！Transformer 不知道有图片存在
    for layer_idx, (layer, past_key_value) in enumerate(
            zip(self.model.layers, past_key_values)):
        hidden_states, present = layer(
            hidden_states, position_embeddings,
            past_key_value=past_key_value, use_cache=use_cache)
        presents.append(present)

    # === Step 4: 输出 ===
    hidden_states = self.model.norm(hidden_states)
    logits = self.lm_head(hidden_states[:, slice_indices, :])

    # === Step 5: 计算损失 ===
    if labels is not None:
        loss = F.cross_entropy(
            logits[..., :-1, :].contiguous(),
            labels[..., 1:].contiguous(),
            ignore_index=-100)

逐步对比：Step 1 和纯 LLM 一样——token 过嵌入层。Step 2 是 VLM 新增的——提取视觉特征、投影、Token 替换。Step 3-5 和纯 LLM 完全一样——Transformer 处理、输出 logits、计算损失。整个 forward() 中只有 Step 2 是新增代码，约 30 行。

generate 方法

VLM 重写了父类的 generate()，唯一改动是支持多图推理：当 num_return_sequences > 1 时，把 pixel_values 复制多份，使得每个生成序列都能看到同一张图片。其余逻辑直接调用父类 LLM 的 generate()。

def generate(self, *args, num_return_sequences=1, **kwargs):
    # 支持多图：如果有 pixel_values，复制多份
    if num_return_sequences > 1 and 'pixel_values' in kwargs:
        pv = kwargs['pixel_values']
        kwargs['pixel_values'] = {k: v.repeat(num_return_sequences, ...)
                                  for k, v in pv.items()}
    # 调用父类 (LLM) 的 generate 方法
    return super().generate(*args, num_return_sequences=num_return_sequences, **kwargs)

设计思路：VLM 的 generate() 几乎不用改——因为 Token 替换已经把图片信息融入了 hidden_states，Transformer 和 LLM 完全一样。唯一需要处理的是多图/多样本场景下 pixel_values 的复制。

def __getitem__(self, index):
    # 1. 读取数据
    conversations = json.loads(self.table['conversations'][index].as_py())
    image_bytes = self.table['image_bytes'][index].as_py()

    # 2. 处理文本
    conversations = pre_processing_chat(conversations)  # 随机加系统提示
    prompt = self.create_chat_prompt(conversations)      # 应用模板
    input_ids = self.tokenizer(prompt).input_ids[:768]   # 分词 + 截断

    # 3. 处理图片

init_vlm_model

函数先创建 MiniMindVLM 并加载权重，然后按两步应用冻结策略：Step 1 先冻结一切（除了 vision_proj），Step 2 根据 freeze_llm 策略解冻对应的部分。

def init_vlm_model(vlm_config, from_weight='pretrain_vlm', freeze_llm=0):
    tokenizer = AutoTokenizer.from_pretrained(tokenizer_path)
    model = MiniMindVLM(vlm_config)

    # 加载权重
    if from_weight != 'none':
        weights = torch.load(weight_path)
        model.load_state_dict(weights, strict=False)

    # Step 1: 先冻结一切（除了 vision_proj）
    for name, param in model.named_parameters():
        if 'vision_proj' not in name:
            param.requires_grad = False

    # Step 2: 根据 freeze_llm 策略解冻
    if freeze_llm == 0:      # 全参训练
        for name, param in model.named_parameters():
            if 'vision_encoder' not in name:
                param.requires_grad = True
    elif freeze_llm == 1:    # 首末层
        for name, param in model.model.named_parameters():
            if 'layers.0.' in name or f'layers.{last_idx}.' in name:
                param.requires_grad = True
    elif freeze_llm == 2:    # 仅投影层
        pass  # 已经只有 vision_proj 是可训练的

    return model.to(device), tokenizer, preprocess

代码逻辑：注意 Step 1 先把所有参数冻结（保留投影层可训练），Step 2 再按需解冻。这种"先全部冻结再解冻"的模式比"先解冻再冻结"更安全——万一逻辑有 bug，最多训练少了，不会多训练不该训练的参数。另外 load_state_dict(weights, strict=False) 中 strict=False 允许权重文件缺少某些 key（如首次训练时没有投影层权重）。

训练循环详解

训练循环的核心逻辑和纯 LLM 几乎一样，唯一的区别是 DataLoader 返回的多了 pixel_values。以下是逐步解析：

# train_sft_vlm.py 第24-86行（简化版，省略了日志/尾步累积处理）
def train_epoch(epoch, loader, iters, start_step=0):
    for step, (input_ids, labels, pixel_values) in enumerate(loader):
        # 1. 数据移到 GPU
        input_ids = input_ids.to(device)
        labels = labels.to(device)
        pixel_values = pixel_values.to(device)

        # 2. 更新学习率（余弦退火）
        lr = get_lr(epoch * iters + step, total_steps, learning_rate)

        # 3. 前向传播（混合精度）
        with autocast_ctx:
            res = model(input_ids, labels=labels, pixel_values=pixel_values)
            loss = (res.loss + res.aux_loss) / accumulation_steps

        # 4. 反向传播
        scaler.scale(loss).backward()

        # 5. 梯度累积 + 裁剪 + 更新
        if step % accumulation_steps == 0:
            scaler.unscale_(optimizer)
            torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
            scaler.step(optimizer)
            scaler.update()
            optimizer.zero_grad(set_to_none=True)

        # 6. 定期保存
        if step % save_interval == 0:
            torch.save(model.state_dict(), ckp_path)

关键机制：autocast_ctx 开启 BFloat16 混合精度，前向传播用半精度加速；scaler.scale(loss).backward() 用 GradScaler 防止半精度梯度下溢；accumulation_steps 实现梯度累积——每 N 步才真正更新一次参数，等效于更大的 batch size；clip_grad_norm_ 梯度裁剪防止梯度爆炸。

对照真实源码时的差异：
  • pixel_values 是 dict 不是 tensor：真实代码第 30 行是 pixel_values = {k: v.to(device) for k, v in pixel_values.items()}，因为它要同时搬运 pixel_values 和 pixel_mask 两个键。简化版写成 .to(device) 只是为了易读。
  • 真实代码还有尾步处理（第 81-83 行）：当总步数不能被 accumulation_steps 整除时，循环结束后的残余梯度也要更新一次，否则最后几步白训了。
  • start_step 用于断点续训时从正确步数恢复，并据此换算学习率。

                    for k, v in MiniMindVLM.image2tensor(image, preprocess).items()}

    # 3. 构造 prompt：用 config 里的占位符 × 数量，别硬编码 64
    messages = [{"role": "user", "content":
        prompt.replace('<image>',
            model.config.image_special_token * model.config.image_token_len)}]
    # 4. 应用对话模板 + 分词
    inputs_text = tokenizer.apply_chat_template(messages, tokenize=False,
                                                add_generation_prompt=True)
    inputs = tokenizer(inputs_text, return_tensors="pt").to(args.device)

    # 5. 自回归生成（流式输出）
    generated_ids = model.generate(
        inputs=inputs["input_ids"], pixel_values=pixel_values,
        max_new_tokens=512, temperature=0.7, top_p=0.85,
        streamer=TextStreamer(tokenizer, skip_prompt=True))

逐步解读：Step 3 中 <image> 会被替换成 config.image_special_token × image_token_len（即 64 个 <|image_pad|>），它们在 forward() 中被视觉特征替换。用 config 属性而非硬编码 64——这样改配置时不用动代码。temperature=0.7 控制随机性（比训练时 generate 默认的 0.85 更确定，适合评估）。TextStreamer 实现逐 token 打印的流式效果。整个推理过程和纯文本 LLM 一样是自回归的。

第 9 章动手实践时，你会亲手运行 $ python eval_vlm.py --weight sft_vlm。这里看懂流程即可，具体命令第 9 章会给全。

补充：web_demo_vlm.py（Gradio 网页界面）和 convert_vlm.py（把 torch 权重转成 HuggingFace transformers 格式）逻辑与上面类似，加载方式不同——它们用 AutoModelForCausalLM.from_pretrained(..., trust_remote_code=True) 加载转换后的模型。需要时直接读这两个文件即可。
