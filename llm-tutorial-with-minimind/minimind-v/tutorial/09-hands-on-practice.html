逐步安装（步骤 1-5）

下面是完整的安装命令。每一步都有注释说明其目的和注意事项。

# ────────────── 步骤 1：克隆项目 ──────────────
git clone https://github.com/jingyaogong/minimind-v
cd minimind-v

# ────────────── 步骤 2：创建虚拟环境 ──────────────
# 使用 conda 创建独立的 Python 3.10 环境
conda create -n minimind-v python=3.10 -y
conda activate minimind-v

# ────────────── 步骤 3：安装 PyTorch ──────────────
# 根据你的 CUDA 版本选择对应命令（用 nvidia-smi 查看 CUDA 版本）
# CUDA 12.1:
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
# CUDA 11.8:
# pip install torch torchvision --index-url https://download.pytorch.org/whl/cu118

# ────────────── 步骤 4：安装项目依赖 ──────────────
# -i 参数使用清华镜像源，国内下载速度更快
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

# ────────────── 步骤 5：验证 PyTorch + CUDA ──────────────
python -c "import torch; print(f'PyTorch: {torch.__version__}'); print(f'CUDA: {torch.cuda.is_available()}')"
排错：CUDA: False 怎么办？

CUDA: False 是自学者卡得最多的一关。按顺序排查：

  1. 确认有 NVIDIA 显卡：$ nvidia-smi 能输出表格说明驱动正常；报错或无输出则先装驱动。
  2. PyTorch 的 CUDA 版本要和驱动匹配：用 nvidia-smi 右上角的 CUDA Version（这是驱动支持的最高版本）对照，选 ≤ 该版本的 PyTorch 安装命令。装错版本（比如驱动只支持 11.8 却装了 cu121）会显示 False。
  3. 重装对应版本：$ pip uninstall torch 后，用上面步骤 3 里匹配的命令重装。
  4. 确认在正确的虚拟环境里：$ conda activate minimind-v。

实在没有 GPU 也能跑——把代码里的 .cuda() 改成 .cpu()，推理可以工作，只是慢（CPU 跑 VLM 推理约几十秒一句）。

  • modelscope 命令找不到：先 $ pip install modelscope（它在 requirements.txt 里，正常装依赖就有了）。

9.2 实验1：观察模型推理

先跑通推理，亲眼看到模型的输出，建立直观感受。

环境搭建完成后，第一个实验就是运行推理脚本，让模型描述图片。这个实验看似简单，但它验证了整个流水线是否工作正常：视觉编码器加载、LLM 权重加载、图片预处理、自回归生成。通过这个实验你将体验三个维度的探索：

  • 运行推理脚本 —— 一行命令启动模型，观察输出
  • 尝试不同的提示语 —— 用不同的 prompt 引导模型关注不同方面
  • 调整生成参数 —— temperature 和 top_p 对输出多样性的影响

运行推理与提示语实验

一行命令启动推理。模型会逐一描述 dataset/eval_images/ 中的 6 张图片。

# 运行推理脚本
python eval_vlm.py --load_from model --weight sft_vlm

预期输出：模型会对每张图片生成一段中文描述。由于模型参数量较小（约 65M），描述可能不够精确，但你应该能看到模型基本理解了图片的主要内容。

接下来，修改 eval_vlm.py 中的 prompt 变量，尝试不同的提示语，观察模型如何响应不同角度的提问：

# 原始：开放式描述
prompt = "<image>\n请描述这张图中的主要物体和场景。"

# 变体 1：关注颜色 → 模型会更侧重颜色描述
prompt = "<image>\n图片里有什么颜色的物体？"

# 变体 2：限制输出长度 → 模型会尝试用一句话概括
prompt = "<image>\n用一句话描述这张图片。"

# 变体 3：英文提问 → 测试模型的多语言能力
prompt = "<image>\nWhat is in this image?"

# 变体 4：主观感受 → 测试模型是否具备"审美"能力
prompt = "<image>\n这张图片给你什么感觉？为什么？"

实验建议：对同一张图片分别用上述 5 种提示语，记录模型的输出。你会发现 prompt 的措辞对 VLM 的输出有显著影响——这就是 提示工程（Prompt Engineering） 的核心思想。

调整生成参数

大模型的生成过程受两个核心参数控制：temperature（温度）和 top_p（核采样阈值）。通过调整它们，你可以控制输出是"保守"还是"创意"。

# 低 temperature：输出更确定、更一致
# 模型会倾向于选择概率最高的词，适合事实性问答
python eval_vlm.py --temperature 0.3 --top_p 0.9

# 高 temperature：输出更多样、更有创意
# 模型会探索更多低概率的词，但可能出现不连贯的内容
python eval_vlm.py --temperature 1.5 --top_p 0.95
参数低值效果高值效果推荐场景
temperature确定性输出，更稳定随机性输出，更多样低值适合事实描述，高值适合创意写作
top_p只考虑概率最高的少数词考虑更多候选词通常与 temperature 配合使用

理解原理：temperature 控制概率分布的"陡峭程度"。temperature 越低，概率最高的那个词被选中的可能性越大；temperature 越高，所有词的概率越平均。top_p 则是从另一个角度控制——只保留累积概率达到 top_p 的候选词，其余直接丢弃。两个参数共同决定了生成文本的"保守程度"。

9.3 实验2：观察张量形状

在模型代码中添加 print 语句，观察数据在模型中的流动。

前面的实验让我们看到了模型的最终输出。但数据在模型内部经历了哪些变换？每一步张量的形状是如何变化的？这个实验通过在 forward() 方法中插入调试打印，让你亲眼观察数据从输入到输出的完整流动过程。这是理解 VLM 架构最直观的方式。

forward 调试

在 model_vlm.py 的 forward() 方法中添加以下打印语句，观察每一步的张量形状变化：

# 在 model_vlm.py 的 forward() 方法中添加以下代码（参考第 98-163 行）
def forward(self, input_ids, labels=None, pixel_values=None, **args):
    batch_size, seq_length = input_ids.shape
    print(f"═══ forward() 调试 ═══")
    print(f"1. input_ids: {input_ids.shape}")           # [1, seq_len]

    hidden_states = self.model.dropout(self.model.embed_tokens(input_ids))
    print(f"2. 嵌入后: {hidden_states.shape}")          # [1, seq_len, 768]

    if pixel_values is not None:
        # 注意：真实代码按图片数量分支处理，这里展示单图的情况
        vision_tensors = self.vision_proj(
            MiniMindVLM.get_image_embeddings(pixel_values, self.vision_encoder))
        print(f"3. 视觉特征: {vision_tensors.shape}")   # [64, 768]

        hidden_states = self.count_vision_proj(
            tokens=input_ids, h=hidden_states, vision_tensors=vision_tensors)
        print(f"4. Token替换后: {hidden_states.shape}") # [1, seq_len, 768]

    # ... Transformer 处理（8 层 Block + norm）...

    logits = self.lm_head(hidden_states)
    print(f"5. logits: {logits.shape}")                 # [1, seq_len, 6400]

预期输出（seq_len 取决于你的 prompt 长度，这里假设是 75）：

═══ forward() 调试 ═══
1. input_ids: torch.Size([1, 75])
2. 嵌入后: torch.Size([1, 75, 768])
3. 视觉特征: torch.Size([64, 768])
4. Token替换后: torch.Size([1, 75, 768])
5. logits: torch.Size([1, 75, 6400])
关键：seq_len 不是固定的

第 1 步的 75 来自"64 个 image_pad + 你的指令文本 + 对话模板标记"。换个 prompt 这个数字就变了。别把 75 当成定值——重要的是每一步之间形状的因果关系，而不是具体数字。

另外，真实 forward() 在处理多图时（pixel_values 带 batch 维）会走第 119/126 行的分支，对每张图分别投影再 torch.stack。本实验用单图，走的是简化路径。

逐步解读：

  • 步骤 1→2：input_ids 从 [1, seq_len] 变为 [1, seq_len, 768]——每个 Token ID 通过 Embedding 查表变成了 768 维向量
  • 步骤 3：视觉编码器输出 [64, 768]——图片被压缩成了 64 个 patch token，每个也是 768 维，与文本嵌入同维度
  • 步骤 4：Token 替换后形状不变仍为 [1, seq_len, 768]——视觉 token 替换了文本序列中的占位符，序列长度不变
  • 步骤 5：最终 logits 形状为 [1, seq_len, 6400]——每个位置都产生一个 6400 维的向量（词表大小），用于预测下一个 Token

快速测试与自定义脚本

方法一：命令行快速测试——把图片复制到评估目录，直接运行推理脚本：

# 1. 复制你的图片到评估目录（支持 JPG/PNG/BMP 等常见格式）

方法二：编写自定义脚本——更灵活，可以精确控制每一步：

import torch
from PIL import Image
from model.model_vlm import MiniMindVLM, VLMConfig
from transformers import AutoTokenizer

# 1. 加载模型和分词器
config = VLMConfig()
model = MiniMindVLM(config, vision_model_path="./model/siglip2-base-p32-256-ve")
weights = torch.load("out/sft_vlm_768.pth", map_location="cpu")
model.load_state_dict(weights, strict=False)
model = model.half().cuda().eval()  # 半精度 + GPU + 评估模式
tokenizer = AutoTokenizer.from_pretrained("./model", trust_remote_code=True)

# 2. 加载并预处理图片
image = Image.open("your_image.jpg").convert('RGB')
pixel_values = MiniMindVLM.image2tensor(image, model.processor)
pixel_values = {k: v.half().cuda() for k, v in pixel_values.items()}

# 3. 构造输入：用 config 里的占位符（不要硬编码 64）
prompt = config.image_special_token * config.image_token_len + "\n请描述这张图片。"
messages = [{"role": "user", "content": prompt}]
text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
input_ids = torch.tensor([tokenizer(text).input_ids]).cuda()

# 4. 自回归生成
with torch.no_grad():
    output = model.generate(input_ids, pixel_values=pixel_values,
                            max_new_tokens=200, temperature=0.7)
response = tokenizer.decode(output[0], skip_special_tokens=True)
print(response)
避坑提示：
  • AutoTokenizer.from_pretrained("./model") 必须加 trust_remote_code=True，否则加载自定义 tokenizer 会失败。
  • 不要硬编码 "<|image_pad|>" * 64——用 config.image_special_token * config.image_token_len。这样改配置（比如换更大视觉编码器）时不用动代码。
  • MiniMindVLM(config) 需要指定 vision_model_path 才会加载 SigLIP2 权重，否则 model.processor 会是 None。

代码关键点：

  • config.image_special_token * config.image_token_len：插入 64 个图像占位符，对应视觉编码器的 64 个 patch token
  • model.half().cuda()：使用 FP16 半精度节省显存，移到 GPU 加速推理
  • strict=False：允许加载部分权重（视觉编码器的权重不在 LLM 权重文件中）
  • max_new_tokens=200：限制生成长度，避免无限循环

9.5 实验4：修改模型参数

尝试修改配置参数，理解模型规模与效果的关系。

MiniMind-V 的模型参数通过 VLMConfig 配置。这个实验让你调整 hidden_size、num_hidden_layers、num_attention_heads 三个核心参数，观察参数量如何变化。虽然修改后需要重新训练才能得到有效的模型，但通过观察参数量变化，你能直观理解"模型规模"这个概念。

参数配置与规模权衡

修改 VLMConfig 的参数，用新配置初始化模型并计算参数量：

# 修改 VLMConfig 的参数
config = VLMConfig(
    hidden_size=768,       # 隐藏层维度，试试 512 或 1024
    num_hidden_layers=8,   # Transformer 层数，试试 4 或 12
    num_attention_heads=8, # 注意力头数，必须能整除 hidden_size
)

# 注意：修改参数后需要重新训练，因为权重维度会不匹配
# 但你可以用修改后的配置从零初始化一个模型来观察参数量变化
model = MiniMindVLM(config)
total = sum(p.numel() for p in model.parameters()) / 1e6
print(f"模型参数量: {total:.2f}M")

关键认识：参数量与 hidden_size 的平方成正比（因为权重矩阵是 d x d）。所以 hidden_size 从 768 增加到 1024（1.33 倍），参数量却从 65M 增加到 200M（3 倍）。这就是为什么大模型的计算成本增长得这么快。

9.6 实验5：尝试训练

启动训练流程，亲手跑一次模型学习。

前面的实验都在使用已经训练好的模型。这个实验让你亲手启动一次 SFT（监督微调）训练，观察 loss 如何下降、学习率如何变化。MiniMind-V 的训练脚本支持命令行参数配置，你不需要修改代码就能控制训练过程。

  • 快速训练测试 —— 用小 batch 先跑通流程，确认环境无误
  • 监控训练指标 —— 理解 loss、lr、耗时三个关键指标
  • 可视化训练曲线 —— 使用 SwanLab 追踪实验

训练命令与参数解析

首次训练建议用小 batch 和少量 epoch，先确认流程能跑通：

# 确保 sft_i2t.parquet 在 dataset/ 目录下
# 使用小 batch 测试训练是否能跑通
python trainer/train_sft_vlm.py \
    --epochs 1 \            # 只训练 1 个 epoch（快速验证）
    --from_weight llm \     # 从 LLM 基座权重开始（不是从零开始）
    --batch_size 2 \        # 每批 2 个样本（省显存）
    --max_seq_len 256 \     # 最大序列长度 256（截断长文本）
    --log_interval 10 \     # 每 10 步打印一次日志
    --save_interval 500     # 每 500 步保存一次检查点

训练过程中，你会看到类似这样的日志输出：

Epoch:[1/2](100/5000) loss: 2.3456 logits_loss: 2.3400 aux_loss: 0.0056 lr: 0.00000498

日志中的三个关键指标：

  • loss：总损失 = logits_loss + aux_loss。正常情况下应该随训练步数逐步下降。如果 loss 不降反升，说明学习率可能太大。
  • logits_loss：语言模型的主损失（预测下一个 Token 的交叉熵）。这是训练的核心目标。
  • aux_loss：辅助损失（MoE 负载均衡损失），确保各专家的负载均衡。值应该很小（< 0.01）。
  • lr：当前学习率。训练脚本使用余弦退火调度器，学习率会先升后降。
关于 --from_weight 与硬件要求
  • --from_weight llm 表示从 LLM 基座直接做 SFT，跳过了 Pretrain（投影层对齐）阶段。脚本的默认值其实是 pretrain_vlm（从已 Pretrain 的权重继续）。首次跑通用 llm 可以更快验证环境，但正式训练应走完整的 Pretrain→SFT 流程（见第 8 章）。
  • 显存要分清：推理 6-8GB 够用；但训练要同时驻留模型权重 + 梯度 + 优化器状态 + 激活值，batch=2 + seq=256 在 8GB 上很可能 OOM。建议训练用 12GB 以上显存，或把 --batch_size 降到 1、--max_seq_len 降到 128 先跑通。
  • OOM 报错（CUDA out of memory）：减小 batch_size、max_seq_len，或开启混合精度。CPU 无法训练（太慢）。

SwanLab 可视化

终端日志能看即时数据，但要看 loss 的整体趋势，需要可视化工具。SwanLab 是一个轻量级的训练可视化平台，可以追踪 loss、学习率等指标的变化趋势。
