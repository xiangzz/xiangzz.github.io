第 12 章

AI 与云端

Copilot 辅助写代码、Codespaces 云端开发、Gist 分享片段

2026 年用 GitHub 的现代方式

还在硬写

你的开发方式可能还停留在十年前

从零写每一行

样板代码、正则、SQL，你一行一行敲。而这些 AI 几秒就能生成，你只需 review。

被环境卡住

想用一台新电脑接着写项目，要装 Node、装依赖、配环境变量，半天就没了。能不能打开浏览器就开干？

分享小片段麻烦

想在群里发一段代码、问个报错，截图不清晰，建仓库又太重。有没有介于「聊天」和「仓库」之间的东西？

本章讲 GitHub 的三个现代工具：Copilot（AI 写代码）、Codespaces（云端开发环境）、Gist（代码片段分享）。
它们不改变 Git/GitHub 的核心机制，而是让你的开发效率成倍提升。

三个工具

分别解决「写得快」「开得快」「传得快」

工具一句话解决什么
Copilot AI 结对编程助手 写得快——自动补全、生成、解释代码
Codespaces 云端 VS Code 环境 开得快——浏览器里秒开开发环境
Gist 代码片段托管 传得快——快速分享单文件或小段代码

三者相互独立，可单独用，也可组合用。

Copilot 是什么

GitHub 的 AI 编程助手——写注释它生成代码，写代码它生成注释

它的能力

  • 代码补全：你写一半，它猜下一半
  • 注释生成代码：写「排序数组」，它给你实现
  • 代码解释：选中陌生代码，让它讲清楚
  • Chat 对话：像 ChatGPT，但能读你的项目上下文

在哪用

  • VS Code / JetBrains 等 IDE 插件
  • GitHub 网页（PR、issue 里直接问）
  • 命令行（gh copilot 扩展）
  • 移动端 GitHub App

怎么获取

Copilot 是付费服务，但学生、教师、开源维护者免费

免费途径

  • GitHub Education / Student Pack：在校学生认证后免费
  • 认证入口：education.github.com，用学校邮箱申请
  • 认证教师、活跃开源维护者同样免费

付费

普通用户约 $10/月。如果你是学生，别花这个钱——先去认证 Student Pack。

注意额度机制：学生免费版采用「每月 200 AI Credits」模型——日常补全、Chat 够用，但重度使用（大量长对话、复杂生成）可能触顶。基础补全功能通常不受限，超额主要是高级模型/高频请求。具体以 GitHub Education 最新政策为准。
学生认证要提前做。审核可能要几天，别等要交作业了才申请。认证后还能白嫖一堆其他开发者工具。

用好 Copilot

它不是替代你思考，是替你打字

写好注释/函数名

Copilot 按你的描述生成。function x() 它瞎猜；function validateEmail(email) 它给你靠谱实现。描述越清楚，建议越准。

用 Tab 接受，Esc 拒绝

灰色建议出现时，Tab 采纳、Esc 拒绝。不合适就拒绝，别将就着用不对的代码。

Chat 问上下文

「这段为什么报错」「怎么优化这个循环」——直接问，它能读当前文件。比来回切浏览器搜快。

用 /explain 学新代码

看不懂的代码选中，/explain 让它逐行讲解。学开源项目、读别人代码的神器。

Copilot 的坑

AI 会一本正经地写错——你必须 review

会编造 API

它可能调用不存在的函数、用废弃的 API。生成后一定要跑、要测，别盲信。

安全风险

可能生成含漏洞的代码（SQL 注入、XSS）。第 10 章的安全意识不能因为用了 AI 就丢。

不要泄露密钥

别在 Chat 里贴生产环境的密钥问问题。Copilot 会把它纳入上下文，理论上有外泄风险。

正确心态：Copilot 是「能打字的副驾驶」，你始终是主驾驶。它写得快，但对错由你负责。

Codespaces 是什么

云端的 VS Code——浏览器里直接打开一个配好的开发环境

图：Codespaces 工作原理

【AI 生图提示词】请生成一张中文技术示意图，风格简洁、配色柔和、适合教学： - 画面主体：左侧一台浏览器图标，右侧一朵云里的「开发环境」盒子（含 VS Code、Node、依赖等） - 各元素关系：浏览器发出「Code」按钮点击，云端几秒内启动一个容器，浏览器里呈现完整的 VS Code 界面，可写代码、跑终端 - 关键标注：云端盒子内标「预装语言、依赖、端口转发」，浏览器旁标「无需本地配置」 - 配色建议：浅灰背景，浏览器用蓝色，云端环境用绿色，箭头橙色 - 画面比例：16:9 - 避免：3D 效果、过多装饰

本质：GitHub 在云端给你开了一台配好的虚拟机，装好了 VS Code Web 版。你打开浏览器就是完整 IDE，关掉它还在，下次回来接着用。

何时用 Codespaces

不是每个场景都需要——看你的痛点

场景该用吗
换电脑/借电脑临时写代码 ✅ 完美——不用配环境
review PR 时想跑一下 ✅ 一键开环境测试
上课练习、教学演示 ✅ 统一环境，不踩配置坑
每天主力开发（同一台电脑） ❌ 本地 IDE 更省额度

Codespaces 适合「临时」「跨设备」「不想配环境」的场景，不适合长期主力开发。

启动 Codespace

任意仓库，一键开干

怎么开

  1. 仓库页面绿色 Code 按钮 → Codespaces 标签
  2. 点 Create codespace on main
  3. 等几十秒，云端环境就绪
  4. 浏览器里打开完整的 VS Code

开了之后

  • 代码已 clone、依赖可能已装
  • 能用终端、装扩展、跑服务
  • 端口转发：本地服务能在浏览器访问
  • 改完直接 commit/push，和本地一样

配置环境

devcontainer.json——告诉 Codespaces 这个项目要什么环境

// .devcontainer/devcontainer.json
{
  "image": "mcr.microsoft.com/devcontainers/javascript-node:20",
  "features": {
    "ghcr.io/devcontainers/features/python:1": { "version": "3.12" }
  },
  "postCreateCommand": "npm install",
  "forwardPorts": [3000],
  "customizations": {
    "vscode": { "extensions": ["esbenp.prettier-vscode"] }
  }
}
配置随仓库走。放进 .devcontainer/，任何人开 Codespace 都拿到一模一样的环境——Node 版本、Python、依赖、VS Code 扩展全配好。这是「环境一致性问题」的终极解法。

免费额度

个人账号每月有免费核心小时，用完要钱

账号类型每月免费
免费个人（Free） 120 核心小时（2 核 × 60h）
学生（Student Pack） 更多额度（认证后）
Pro 账号 180 核心小时
省额度习惯：用完及时停 Codespace（不是关浏览器，是在 GitHub 上 Suspend/Stop）；不用 4 核以上的机型；短期任务用完就删。长时间挂着会烧完额度。

Gist 是什么

轻量级代码片段托管——介于「聊天发代码」和「建仓库」之间

能做什么

  • 托管单个或几个文件的代码片段
  • 自动语法高亮
  • 支持 Markdown 渲染
  • 每个 Gist 有独立 URL，可分享
  • 支持版本历史（每次编辑是一次版本）

和仓库的区别

仓库是多文件的项目；Gist 是单文件为主的片段。Gist 没有 issue、PR、Actions——就是「存一段代码 + 给个链接」。

入口：gist.github.com。用 GitHub 账号直接登录。

公开 vs 秘密

Gist 的两种可见性——注意 Secret 的真实含义

Public GistSecret Gist
可搜索 ✅ 能被搜到 ❌ 不出现在搜索
访问 任何人可见 知道 URL 才能看
匿名性 公开 不是真正私密
Secret ≠ Private！Secret Gist 只是不被搜索收录，但有 URL 任何人都能访问。不要用它存密码、密钥、敏感信息——那不是它的设计用途。

Gist 实战

学生日常的高频用法

问问题/报错

把报错信息、出问题的代码贴成 Gist，发链接到群里/论坛。比截图清晰，比直接贴聊天框整洁，还带高亮。

存常用脚本

自己常用的配置文件、shell 脚本、VS Code snippets——存成 Gist，换电脑也能拿到。

嵌入博客/文档

Gist 提供 embed 代码，可嵌入支持它的博客系统。代码改动自动同步，不用重新贴。

写笔记

用 Markdown Gist 当轻量笔记——比建仓库轻，比聊天记录持久。

命令行 Gist

gh gist——不开网页也能创建和管理 Gist

# 从文件创建公开 Gist
$ gh gist create config.yml --public

# 从 stdin 创建（管道）
$ cat error.log | gh gist create -f "error.log"

# 列出你的 Gist
$ gh gist list

# 查看某个 Gist 内容
$ gh gist view abc12345

# 在浏览器打开
$ gh gist view abc12345 --web
和第 09 章的 gh 联动：报错时一行 command 2>&1 | gh gist create，把输出直接变成可分享链接。比手动复制粘贴快得多，特别适合在 issue/讨论里贴日志。

组合使用

三个工具串起来——一个真实的现代工作流

场景：临时修个 bug

  1. 在手机上收到 issue 通知
  2. 用 Codespaces 在浏览器开环境（不用回电脑）
  3. 用 Copilot 帮你快速定位 + 生成修复
  4. review 后 commit、开 PR
  5. 把关键 diff 贴成 Gist 给同事讨论
全程没开 IDE、没配环境、没装依赖。这是 2026 年「云原生」开发的样子——工具替你处理琐事，你专注解决问题本身。

何时别用

工具是好工具，但不是所有场景都适合

Copilot 别用时

  • 学基础语法时——AI 抢了你的练习机会
  • 考试/课堂测验——通常不允许
  • 写核心算法想自己想清楚时

Codespaces 别用时

  • 网络不稳定的环境
  • 长期主力开发（烧额度）
  • 需要本地 GPU/特殊硬件时

Gist 别用时

  • 多文件项目（用仓库）
  • 任何敏感信息（Secret 不安全）
  • 需要协作/审查（没 PR 功能）

动手试一试

三个工具各体验一次

你的任务

任务：按场景体验这三个工具。

要求：

  1. Gist：把一段自己写的代码贴成 Gist，拿到分享链接
  2. Codespaces：在任意仓库开一个 Codespace，在终端跑通一个命令后停掉
  3. Copilot（若有权限）：在 IDE 里写个注释，让 Copilot 生成函数，review 后采纳

提示

  1. 没有 Copilot 权限？先去 education.github.com 申请学生包
  2. Codespace 用完记得 Stop，省额度
  3. Gist 别贴任何敏感信息
