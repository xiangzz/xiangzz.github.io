面向对象的三大特性

封装、继承和多态是Java面向对象编程的核心，它们共同构建了清晰、可维护和可扩展的软件世界。

  • 封装 (Encapsulation): 将数据（属性）和操作数据的方法（行为）捆绑在一起，并对外部隐藏内部实现细节，只提供公共的访问接口。
  • 继承 (Inheritance): 允许一个类（子类）获取另一个类（父类）的属性和方法，实现了代码的复用，并为多态提供了基础。
  • 多态 (Polymorphism): 同一个消息（方法调用）可以根据发送对象的不同而表现出不同的行为。它极大地增强了程序的灵活性和可扩展性。

正是这三大特性，让我们的Java程序更加生动和强大。

类的封装

封装的核心思想是“高内聚，低耦合”。它确保了对象内部数据的安全性，使用者无需关心实现细节，只需通过预定义的接口与对象交互。

如果不封装，类的内部变量可以被随意读写，这可能导致数据不一致或逻辑混乱，给系统带来风险。

最佳实践：将成员变量设为 private，并通过公共的 public Getter 和 Setter 方法来控制访问。


public class Person {
    private String name; // 设为私有，只能在类内部访问
    private int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() { // Getter: 对外提供读取name的通道
        return name;
    }

    public void setName(String name) { // Setter: 对外提供修改name的通道
        // 可以在这里加入控制逻辑
        if(name != null && !name.isEmpty()) {
            this.name = name;
        }
    }
    
    public int getAge() {
        return age;
    }
}

封装的作用

封装的真正威力在于，我们可以在Getter和Setter方法中添加额外的逻辑，从而完全掌控属性的读写过程。

例如，我们可以规定名字不允许包含特定字符，或者年龄不能被设置为负数。


public class Person {
    private String name;
    private int age;

    // ... 构造方法 ...

    public void setName(String name) {
        // 名字不能为空，且不能包含"小"字
        if (name == null || name.contains("小")) {
            System.out.println("无效的名字！");
            return;
        }
        this.name = name;
    }

    public void setAge(int age) {
        // 年龄必须在 0 到 120 之间
        if (age < 0 || age > 120) {
            System.out.println("无效的年龄！");
            return;
        }
        this.age = age;
    }
    
    // ... Getters ...
}

通过这种方式，类的设计者可以强制执行业务规则，确保对象状态的有效性。

模块系统 (*)

从Java 9开始，引入了模块系统，旨在解决大型应用中依赖关系复杂、类路径混乱的问题。

模块化之前

所有依赖（JAR包）都放在类路径上，导致：

  • 强封装性缺失: 无法隐藏不应暴露的包。
  • 依赖关系模糊: 难以清晰地了解项目依赖。
  • 巨大的运行时: 即使只用到一小部分功能，也需引入整个JAR包。

模块化之后

通过 module-info.java 文件明确定义模块边界：

  • requires: 声明依赖哪些其他模块。
  • exports: 声明将哪些包暴露给其他模块使用。

这带来了更好的封装性、更清晰的依赖和更小的运行时镜像。

module-info.java 示例

// module-info.java
module com.example.features {
    // 声明依赖模块
    requires java.sql;
    requires com.google.gson; // 第三方库（自动模块名）

    // 导出对外可用的包
    exports com.example.features.api;
    exports com.example.features.core;
}

核心语义：requires 声明依赖；exports 控制对外可见包。未导出的包默认对其他模块不可访问。

封装实战：银行账户类

让我们通过一个完整的银行账户类来演示封装的威力。我们将逐步展示如何从一个不安全的类演进到一个完全封装的类。

❌ 第一步：不封装的危险版本


public class BankAccount {
    public String accountNumber;  // 任何人都能修改账号！
    public double balance;        // 余额可以被随意篡改！
    public String ownerName;      // 户主姓名可以被改变！
    
    // 没有任何保护措施
}

// 使用时的问题
BankAccount account = new BankAccount();
account.balance = -1000;  // 😱 余额变成负数！
account.accountNumber = ""; // 😱 账号被清空！

这种设计完全没有安全保障，任何人都可以随意修改账户信息！

⚠️ 第二步：基础封装版本


public class BankAccount {
    private String accountNumber;
    private double balance;
    private String ownerName;
    
    // 基础的getter和setter
    public double getBalance() { return balance; }
    public void setBalance(double balance) { this.balance = balance; }
    
    public String getOwnerName() { return ownerName; }
    public void setOwnerName(String ownerName) { this.ownerName = ownerName; }
}

虽然数据私有化了，但setter方法仍然允许不合理的操作！

✅ 第三步：完全封装的安全版本


public class BankAccount {
    private final String accountNumber;  // 账号一旦设定不可更改
    private double balance;
    private final String ownerName;      // 户主姓名不可更改
    private boolean isActive;            // 账户状态
    
    public BankAccount(String accountNumber, String ownerName) {
        if (accountNumber == null || accountNumber.trim().isEmpty()) {
            System.out.println("账号不能为空");
        }
        if (ownerName == null || ownerName.trim().isEmpty()) {
            System.out.println("户主姓名不能为空");
        }
        this.accountNumber = accountNumber;
        this.ownerName = ownerName;
        this.balance = 0.0;  // 新账户余额为0
        this.isActive = true;
    }
    
    // 只提供查询余额的方法，不提供直接设置余额的方法
    public double getBalance() {
        if (!isActive) {
            System.out.println("账户已被冻结");
        }
        return balance;
    }
    
    // 存款方法：有业务逻辑控制
    public void deposit(double amount) {
        if (!isActive) {
            System.out.println("账户已被冻结，无法存款");
            return; 
        }
        if (amount <= 0) {
            System.out.println("存款金额必须大于0");
            return;
        }
        if (amount > 50000) {
            System.out.println("单次存款不能超过5万元");
            return;
        }
        balance += amount;
        System.out.println("存款成功，当前余额：" + balance);
    }
    
    // 取款方法：有业务逻辑控制
    public void withdraw(double amount) {
        if (!isActive) {
            System.out.println("账户已被冻结，无法取款");
            return; 
        }
        if (amount <= 0) {
            System.out.println("取款金额必须大于0");
            return;
        }
        if (amount > balance) {
            System.out.println("余额不足");
            return;
        }
        if (amount > 20000) {
            System.out.println("单次取款不能超过2万元");
            return;
        }
        balance -= amount;
        System.out.println("取款成功，当前余额：" + balance);
    }
    
    // 冻结账户
    public void freeze() {
        isActive = false;
        System.out.println("账户已被冻结");
    }
    
    // 解冻账户
    public void unfreeze() {
        isActive = true;
        System.out.println("账户已解冻");
    }
    
    // 只读属性的getter
    public String getAccountNumber() { return accountNumber; }
    public String getOwnerName() { return ownerName; }
    public boolean isActive() { return isActive; }
}

通过完全封装，我们不仅保护了数据，还嵌入了业务规则，确保账户操作的安全性和合理性。

封装的应用：单例模式

单例模式是封装思想的高级应用。通过将构造方法私有化，我们完全控制了对象的创建过程。

单例模式的演进历程

🥚 饿汉式（Eager Loading）- 最简单但可能浪费内存


public class EagerSingleton {
    // 类加载时就创建实例（可能浪费内存）
    private static final EagerSingleton instance = new EagerSingleton();
    
    private EagerSingleton() {
        System.out.println("EagerSingleton 实例被创建");
    }
    
    public static EagerSingleton getInstance() {
        return instance;
    }
}

优点：线程安全，实现简单

缺点：类加载时就创建，可能浪费内存

😴 懒汉式（Lazy Loading）- 需要时才创建


public class LazySingleton {
    private static LazySingleton instance;
    
    private LazySingleton() {
        System.out.println("LazySingleton 实例被创建");
    }
    
    // 加synchronized确保线程安全，但性能较差
    public static synchronized LazySingleton getInstance() {
        if (instance == null) {
            instance = new LazySingleton();
        }
        return instance;
    }
}

优点：按需创建，节省内存

缺点：每次调用都要同步，性能较差

🏠 静态内部类（推荐）- 最优雅的解决方案


public class StaticInnerClassSingleton {
    
    private StaticInnerClassSingleton() {
        System.out.println("StaticInnerClassSingleton 实例被创建");
    }
    
    // 静态内部类，只有在被引用时才会加载
    private static class SingletonHolder {
        private static final StaticInnerClassSingleton INSTANCE = 
            new StaticInnerClassSingleton();
    }
    
    public static StaticInnerClassSingleton getInstance() {
        return SingletonHolder.INSTANCE;  // 触发内部类加载
    }
}

优点：线程安全、按需加载、性能好、代码简洁

缺点：无明显缺点，推荐使用

🌍 真实世界中的单例模式应用

🖥️ 系统配置管理器


public class ConfigManager {
    private static volatile ConfigManager instance;
    private Properties config;
    
    private ConfigManager() {
        config = new Properties();
        loadConfig(); // 一个从磁盘读取配置文件并初始化config的方法
    }

    public static ConfigManager getInstance() {
        if (instance == null) {
            synchronized (ConfigManager.class) {
                if (instance == null) {
                    instance = new ConfigManager();
                }
            }
        }
        return instance;
    }
    
    public String getProperty(String key) {
        return config.getProperty(key);
    }
}

public class Logger {

🏗️ 代理模式结构（基础版）

// 1. 真实的图片显示类
class RealImageDisplay {
    private String filename;
    
    public RealImageDisplay(String filename) {
        this.filename = filename;
        loadImageFromDisk(); // 模拟耗时的图片加载
    }
    
    private void loadImageFromDisk() {
        System.out.println("正在从磁盘加载图片: " + filename);
        // 模拟耗时操作
        try {
            Thread.sleep(1000);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
    
    public void display() {
        System.out.println("显示图片: " + filename);
    }
}

// 2. 代理类 - 添加缓存和延迟加载功能
class ImageProxy {
    private String filename;
    private RealImageDisplay realImage;
    private static java.util.Set loadedImages = new java.util.HashSet<>();
    
    public ImageProxy(String filename) {
        this.filename = filename;
        // 注意：这里不立即创建真实对象，实现延迟加载
    }
    
    public void display() {
        // 检查是否已经加载过
        if (loadedImages.contains(filename)) {
            System.out.println("从缓存显示图片: " + filename);
            return;
        }
        
        // 第一次访问时才创建真实对象
        if (realImage == null) {
            realImage = new RealImageDisplay(filename);
        }
        
        realImage.display();
        loadedImages.add(filename); // 标记为已加载
    }
}

什么是继承

继承是面向对象编程中最重要的概念之一。它不仅仅是代码复用，更是对现实世界中"分类"和"特化"关系的抽象。

继承带来的好处

🔄 代码复用

避免重复编写相同的代码，提高开发效率

📊 层次结构

建立清晰的类层次关系，便于理解和维护

🔧 扩展性

在不修改原有代码的基础上添加新功能

🎭 多态基础

为多态提供基础，实现灵活的程序设计

继承的基本规则

  • 单继承：Java中一个类只能直接继承一个父类（但可以实现多个接口）
  • 传递性：如果C继承B，B继承A，那么C也拥有A的特性
  • 访问控制：子类不能访问父类的private成员，但可以访问protected和public成员
  • 构造顺序：创建子类对象时，总是先调用父类的构造方法

类的继承

继承是代码复用的强大机制。它允许我们创建一个新类（子类），该类继承一个已存在类（父类）的属性和方法。

这形成了一种 "is-a" 的关系。例如，“学生”是一个“人”，“工人”也是一个“人”。学生和工人都拥有人的共性（如姓名、年龄），但又各自拥有独特的行为。

子类继承父类的“遗产”（非私有成员），并可以添加自己的新功能，实现“青出于蓝而胜于蓝”。

继承的语法：extends 关键字

在Java中，我们使用 extends 关键字来实现继承。一个类只能直接继承一个父类（单继承），但继承的层级可以无限延伸。


// 父类：Person
public class Person {
    String name;
    int age;

    public void hello() {
        System.out.println("你好，我叫 " + name);
    }
}

// 子类：Student 继承自 Person
public class Student extends Person {
    public void study() {
        // 可以直接使用从父类继承来的 name 属性
        System.out.println(name + " 正在学习...");
    }
}

// 使用
Student student = new Student();
student.name = "小明";
student.study(); // 调用自己的方法
student.hello(); // 调用从父类继承的方法

被 final 关键字修饰的类不能被继承。

父类构造器会被继承吗？

不同于成员变量和成员方法，父类的构造器并不被子类继承。但在创建子类对象时，会先调用父类构造器，这个调用发生在子类构造器中，通过 super 关键字完成。

  • 如果未显式写出 super(...)，编译器会自动插入一个 super() 去调用父类无参构造器。
  • super(...) 必须是子类构造器的第一行语句；否则编译报错。
  • 如果父类没有无参构造器，你又没有显式调用合适的 super(...)，也会编译错误。

示例1：未写 super() 时的自动调用

// 父类有无参构造
class Person {
    public Person() {
        System.out.println("Person 无参构造执行");
    }
}

// 子类构造器没有显式写 super()
class Student extends Person {
    public Student() {
        // 这里编译器会自动插入 super()
        System.out.println("Student 无参构造执行");
    }
}

// 使用
new Student();
// 输出：
// Person 无参构造执行
// Student 无参构造执行

示例2：父类没有无参构造，必须显式调用 super(...)

class Animal {
    public Animal(String name) {
        System.out.println("Animal 构造：" + name);
    }
}

class Dog extends Animal {
    public Dog() {
        // 编译错误：没有可用的无参构造可以自动调用
        // 必须在第一行显式写 super(name)
    }
}

// 正确写法：
class Dog2 extends Animal {
    public Dog2(String name) {
        super(name); // 必须是第一行！
        System.out.println("Dog2 构造：" + name);
    }
}

结论：构造器不继承，只能在子类构造器中通过 super(...) 调用父类构造器；且 super 必须写在第一行（不写时系统会尝试补一个 super()）。

super 关键字

super 并不是一个独立的对象，它表示“当前对象的父类部分（父类视角）”。因此可以：

  • 在构造器中用 super(...) 调用父类构造器。
  • 在实例方法/实例代码块中用 super.xxx 访问被子类遮盖的父类成员。

为什么 super 能准确定位到父类？

因为 Java 采用 单继承：一个类只能直接继承一个父类。因此 super 的指向是 唯一且确定 的，不存在多重父类的歧义。

super 与 this 的限制

  • super 与 this 都不能出现在 static 方法或 static 代码块中（static 属于类本身，并不依赖某个具体实例）。
  • 只有在 实例方法、实例代码块、构造器 中才能使用 super/this。

遮盖（Shadowing）与 super 的作用

当子类定义了与父类 同名的实例变量 时，子类的变量会 遮盖 父类变量。在子类自己的方法中，默认访问到的是子类变量；若要访问父类变量，需要用 super.变量名。

class Father {
    public int a = 5;
    public void f() { System.out.println("Father"); }
}

class Son extends Father {
    public int a = 7; // 子类的 a 遮盖了父类的 a

    @Override
    public void f() {
        System.out.println(a);      // 访问子类的 a -> 输出 7
    }

    public void g() {
        System.out.println(super.a); // 访问父类的 a -> 输出 5
        super.f();                   // 调用父类的 f() -> 输出 "Father"
    }
}

变量查找（未显式指定时）

在某个方法中访问名为 x 的变量但未显式指定时，查找顺序为：

  1. 先看该方法中是否有名为 x 的 局部变量
  2. 再看当前类中是否包含名为 x 的 成员变量
  3. 逐层向上寻找直接父类中的 可见成员变量
  4. 直到 java.lang.Object，还找不到则编译报错

总结：super 提供父类视角的访问，解决遮盖问题；由于单继承，super 的目标唯一。
记住：super/this 只能用于与实例相关的场景，不能在 static 中使用。

方法的重写 (Override)

大部分时候子类总是以父类为基础，再额外增加新的变量和方法，但有情况例外:

子类具有父类声明的功能，但是具体实现有所不同：多鳍鱼是鱼却可用肺呼吸，鸵鸟是鸟却不会飞。

class Bird {
    public void fly(){
        System.out.println(“自由飞翔”);
    }
}
class Ostrich extends Bird{
    public void fly(){
        System.out.println(“我只能在地上跑...”);
    }
}

重写 (Override) 是指子类可以提供一个与父类相同的方法签名的新实现，从而“覆盖”父类的行为。

什么是“方法签名” (Method Signature)？

方法签名 = 方法名 + 参数列表（参数的个数、类型、顺序）。

注意：方法签名不包含以下信息：

  • 返回值类型（例如 int / String）
  • 参数名称（例如 a / b）
  • 方法修饰符（public、static 等）
  • 异常声明（throws ...）
  • 泛型参数本身（重载基于擦除后的参数类型）

重写 vs 重载 与方法签名的关系

  • 重写 (Override)：父子类之间，方法签名必须相同；返回类型允许协变（子类方法可以返回更窄的引用类型）。
  • 重载 (Overload)：同一个类中，方法名相同，但参数列表不同（数量/类型/顺序至少有一处不同）。
  • 不能被重写的情况：static 方法（只能隐藏）、final 方法、private 方法（对子类不可见）。

辨析题：下面哪些是重写？哪些是重载？哪些会编译错误？

// 1) 重写允许“协变返回类型”
class A { Number f() { return 1; } }
class B extends A { Integer f() { return 2; } } // ✅ 重写（签名相同，返回类型更窄）

// 2) 参数列表不同 -> 重载
class Demo {
    void m(int a) {}
    void m(double a) {}             // ✅ 重载（类型不同）
    void m(int a, double b) {}
    void m(double a, int b) {}      // ✅ 重载（顺序不同）
}

// 3) 仅改返回类型 -> 编译错误（签名相同，无法仅凭返回类型区分）
class C {
    int add(int a, int b) { return a + b; }
    // double add(int a, int b) { return a + b; } // ❌ 编译错误：签名相同
}

// 4) 可变参数本质是数组 -> 与同类型数组签名相同，不能同时存在
class E {
    int sum(int... nums) { return 0; }
    // int sum(int[] nums) { return 0; } // ❌ 编译错误：签名等同（int... -> int[]）
}

// 5) equals 的常见坑：以下是重载，不是重写
class Person {
    boolean equals(String s) { return false; }   // ⚠️ 重载（未重写 Object.equals(Object)）
    @Override
    public boolean equals(Object o) { return super.equals(o); } // ✅ 正确重写
}

总结：判断重写/重载的核心在于“方法签名”。重写要求签名一致（返回类型可协变），重载要求参数列表发生变化。
仅靠返回类型、修饰符或异常声明都无法区分重载。

这与重载 (Overload) 不同：重载是在同一个类中定义多个同名但参数列表不同的方法。

方法重写的规则

重写的“两同两小一大”规则

  • 两同：方法名相同、参数列表相同（签名一致）。
  • 两小：
    • 返回类型更小或相等：子类方法可以返回更窄的引用类型（协变返回），例如 Number → Integer。
    • 抛出异常更小或相等：子类方法声明的受检异常集合必须是父类受检异常的子集（更具体，更少）。
  • 一大：访问权限更大或相等（≥）：private < 默认(package-private) < protected < public。
  • 一致：父子类的方法要有同样的静态标识。实际上，子类的static方法只是隐藏父类的static方法。

实验：静态方法只能隐藏，调用按“引用类型”静态绑定

class Base {
    public static void s() { System.out.println("Base.s"); }
}
class Sub extends Base {
    public static void s() { System.out.println("Sub.s"); } // 隐藏（不是重写）

    public void demo() {
        Base.s(); // 调用父类静态方法
        Sub.s();  // 调用子类静态方法
    }
}

Base b = new Sub();
b.s();        // 输出：Base.s   —— 静态绑定，按“引用类型”决定
Sub.s();      // 输出：Sub.s
new Sub().demo(); // Base.s 然后 Sub.s

实验：两小和一大

// 协变返回类型示例
class A { Number f() { return 1; } }
class B extends A { @Override Integer f() { return 2; } } // ✅ 返回类型更窄

// 受检异常示例
import java.io.*;
class P { void read() throws IOException {} }
class C extends P { @Override void read() throws FileNotFoundException {} } // ✅ 更具体
// class C2 extends P { @Override void read() throws Exception {} } // ❌ 更宽，编译错误

// 访问权限示例
class Base {
    protected void m() {}
}
class Sub extends Base {
    @Override public void m() {} // ✅ 权限更大（protected -> public）
    // @Override void m() {}     // ❌ 权限更小（protected -> package-private），编译错误
}

final 修饰符："最终的" → 不可改

final 关键字表示"最终的"、"不可改变的"，可以修饰类、方法和变量，用于限制继承、重写和修改。

🔒 final 的三种用法

final 类

不能被继承

final class Math {
    // 数学工具类
    // 不允许被继承
}

例：String、Integer、Math 等

final 变量

表示常量，必须初始化且不能被修改

final static double PI = 3.14159;
final int MAX_SIZE = 100;

// 编译错误：
// PI = 3.14; // ❌ 不能修改

常量命名通常使用大写字母

final 方法

在子类中不能被重写

class Parent {
    final void display() {
        System.out.println("不能被重写");
    }
}

class Child extends Parent {
    // void display() {} // ❌ 编译错误
}

💡 实际应用示例

万物之源： Object 类

在Java中，如果一个类没有明确地 extends 另一个类，那么它就默认继承自 java.lang.Object 类。

因此，Object 类是所有类的“祖先”，它提供了一些所有对象都应具备的基本方法。

常用方法包括：

  • String toString(): 返回对象的字符串表示。
  • boolean equals(Object obj): 比较两个对象是否“相等”。
  • int hashCode(): 返回对象的哈希码。
  • Class getClass(): 返回对象的运行时类。

重写示例：equals() 和 toString()

默认的 equals() 比较的是内存地址，而我们通常希望比较对象的内容。默认的 toString() 输出的是类名和哈希码，我们希望看到更有意义的信息。


public class Person {
    private String name;
    private int age;
    // ... 构造方法 ...

    @Override
    public String toString() {
        return "Person{" + "name='" + name + ''' + ", age=" + age + '}';
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true; // 是同一个对象
        if (obj == null || getClass() != obj.getClass()) return false; // 类型不同
        Person person = (Person) obj;
        // 比较核心属性
        return age == person.age && name.equals(person.name);
    }
}

重写后，即使是两个不同的对象，只要内容相同，equals() 也会返回 true。

什么是多态

多态（Polymorphism）是面向对象编程的精髓：同一个方法调用可以根据对象的实际类型产生不同的行为。

  • Java 引用变量有两种类型：编译时类型（由声明决定）与运行时类型（由实际赋给该变量的对象决定）。
  • 当编译时类型与运行时类型不一致时，就产生了多态。
  • 语法：SuperType x = new SubType(构造器参数);
  • 多态意味着父类变量可以指向子类对象（俗称“爸爸打儿子”）。
  • 问题：下方代码 a.speak() 到底执行哪个？
class Animal {
    public void speak() { System.out.println("Animal speak"); }
    public void eat() { System.out.println("Animal eat"); }
}
class Dog extends Animal {
    @Override
    public void speak() { System.out.println("Dog speak"); }
    public void wagTail() { System.out.println("Dog wag tail"); }
}

Animal a = new Dog();        // 编译时类型：Animal；运行时类型：Dog
a.speak();                   // 运行时调用 Dog.speak —— 多态（动态绑定）
// a.wagTail();              // 编译错误：编译时类型是 Animal，无法访问 Dog 独有方法

if (a instanceof Dog) {      // instanceof 关键字用于检测某对象是否是某类的实例
    Dog d = (Dog) a;         // 向下转型
    d.wagTail();             // 正常调用 Dog 的特有方法
}

多态的精髓：编译时类型决定了能访问的成员范围；运行时类型决定了方法调用的实际实现（动态绑定）。

实现多态的三个条件

  1. 继承关系：必须有父类和子类的继承关系
  2. 方法重写：子类必须重写父类的方法
  3. 向上转型：父类引用指向子类对象

多态的核心价值

  • 🔧 降低耦合：调用者不需要知道具体的实现类，只需要知道接口
  • 📈 提高扩展性：新增子类无需修改现有代码
  • 🎯 统一处理：可以用统一的方式处理不同类型的对象
  • 🔄 代码复用：同一套代码可以处理多种类型

多态与动态绑定

编译器明明只知道 a 是 Animal类型，它怎么“智能”地调用了 Dog 的方法呢？
这背后就是Java实现多态的核心机制：动态绑定。

绑定：把一个“方法调用”（如 a.speak()）和“方法具体的实现代码”关联起来的过程。绑定分为两种：

静态绑定 (Static Binding)
  • 时机： 编译时
  • 特点： 编译器100%确定调用哪个方法
  • 适用： private, static, final 方法
  • 关键： 看 引用的声明类型
动态绑定 (Dynamic Binding)
  • 时机： 运行时
  • 特点： 运行时JVM检查对象实际类型再决定
  • 适用： 所有可重写的实例方法（虚方法）
  • 关键： 看 对象的实际类型

动态绑定与虚方法

动态绑定得以实现，首先要感谢 虚方法 的概念。

  • 在C++等语言中，需要用 virtual 关键字标记一个方法，告诉编译器“它可能被重写”。
  • 而Java的设计更直接：
    每个类所有非 static、非 private、非 final 的实例方法，默认全部都是虚方法！

JVM在运行时通过方法表 (vtable)来实现动态绑定。

JVM为每个类维护一个方法表，其中包含方法签名到实际方法实现的映射：

// Animal 的方法表
class Animal {
  /*
    sepak()     -> Animal.speak
    eat()       -> Animal.eat
  */
}

// Dog 的方法表
class Dog extends Animal {
  /*
    speak()     -> Dog.speak (已重写)
    eat()       -> Animal.eat (继承而来)
    swagTail()  -> Dog.swagTail
  */
}


// 运行时调用过程：
// Animal a = new Dog();

// 1. 创建 Dog 对象时，其内部会包含一个
//    指向 Dog 类方法表的引用。

// a.speak();
// 2. JVM通过对象引用找到 Dog 的方法表。
// 3. 在表中查找 speak() 签名。
// 4. 执行该签名指向的实际方法实现，
//    即 Dog.speak()。

向上转型与向下转型：多态的体现

向上转型 (Upcasting): 将子类对象赋值给父类引用。这是自动且安全的。

Person person = new Student("小明", 18, "男");

向上转型后，该引用只能调用父类中定义的方法，但如果该方法在子类中被重写，实际执行的是子类的版本。这就是多态！

向下转型 (Downcasting): 将父类引用强制转换回子类引用。这需要显式转换，并且有风险。

Student student = (Student) person;

向下转型前，必须使用 instanceof 关键字进行检查，否则可能在运行时抛出 ClassCastException。


if (person instanceof Student) {
    Student student = (Student) person;
    student.study(); // 安全地调用子类特有的方法
}

抽象类

当一个父类只知道其子类应该包含什么方法，但无法确定这些方法的具体实现时，就可以将父类定义为抽象类。

核心规则

  • 定义： 使用 abstract 关键字修饰的类是抽象类，修饰的方法是抽象方法。
  • 抽象方法： 只有方法声明，没有方法体 { }，以分号结尾。如abstract void myMethod();
  • 包含抽象方法的类 必须 被声明为抽象类。
  • 抽象类 不能 被实例化 (不能 new)，但可以作为引用类型，用于实现多态。
  • 继承抽象类的子类 必须 实现父类所有的抽象方法，除非该子类自己也是一个抽象类。
  • 一个抽象子类可以重写父类的具体方法，并将其重新声明为抽象方法。

// 1. 定义抽象类和抽象方法
public abstract class Animal {
    public abstract void makeSound(); // 抽象方法

    public void run() { // 具体方法
        System.out.println("动物在跑...");
    }
}

// 2. 子类继承并实现抽象方法
public class Dog extends Animal {
    @Override
    public void makeSound() {
        System.out.println("汪汪！");
    }
}

// 3. 使用：不能实例化父类，但可用于多态
Animal myPet = new Dog();
myPet.makeSound(); // 输出: 汪汪！

// Animal shelter = new Animal(); // 编译错误！抽象类不能被实例化

接口

接口是比抽象类更纯粹的抽象。它只定义了一组行为规范（方法签名），而不关心任何实现。

接口体现了 "has-a" 或 "can-do" 的关系。

  • 接口中的方法默认是 public abstract 的。
  • 接口中的变量默认是 public static final 的（常量）。
  • 实现接口的类必须实现其所有抽象方法。


// 定义“会游泳”的能力
public interface Swimmable {
    void swim();
}

// Duck 类实现了这两种能力
public class Duck implements Swimmable {

    @Override
    public void swim() { System.out.println("鸭子在游泳..."); }
}

接口的继承

接口不仅能被类实现，还可以像类一样继承其他接口，从而在父接口的基础上扩展能力。接口也支持多重继承（extends A, B）。 

// 父接口：通用“可移动”能力
public interface Movable {
    void move();
}

// 子接口：在父接口基础上扩展“会飞/会游泳”
public interface Flyable extends Movable {
    void fly();
}

public interface Swimmable extends Movable {
    void swim();
}

// 子接口可以多重继承，组合多种能力
public interface Amphibious extends Flyable, Swimmable { }

// 实现类只需实现组合后的全部抽象方法
public class DuckHybrid implements Amphibious {
    @Override public void move() { System.out.println("移动中..."); }
    @Override public void fly()  { System.out.println("鸭子在飞..."); }
    @Override public void swim() { System.out.println("鸭子在游泳..."); }
}

要点

  • 子接口会继承父接口的抽象方法与默认方法。
  • 当多父接口存在同名默认方法冲突时，子接口或实现类必须显式覆盖。
  • 接口可多重继承（extends A, B），类不可多重继承但可实现多个接口。

接口的“菱形问题”

一个类可以实现多个接口。

当一个类实现多个接口，而这些接口恰好包含同名、同参数的默认方法时，编译器会陷入困惑：究竟该继承哪一个？这就是著名的“菱形问题”。Java 要求开发者必须明确解决这个冲突。

场景：飞行与游泳的冲突

假设我们有两个接口，Flyer 和 Swimmer，它们都有一个名为 takeOff() 的默认方法。


public interface Flyer {
    default void takeOff() {
        System.out.println("扇动翅膀，飞向天空！");
    }
}

public interface Swimmer {
    default void takeOff() {
        System.out.println("双腿一蹬，潜入水中！");
    }
}

冲突的产生

现在，一个“水陆两栖飞机”AmphibiousPlane 试图同时实现这两个接口。此时，编译器会报错，因为它不知道该选用哪个 takeOff() 实现。


// 下面的代码会导致编译错误：AmphibiousPlane inherits unrelated defaults for takeOff()
// public class AmphibiousPlane implements Flyer, Swimmer {}

解决方案：显式覆盖

解决方法是在实现类 AmphibiousPlane 中重写 takeOff() 方法，并明确指定要调用哪个父接口的默认实现，或者提供一个全新的实现。 


public class AmphibiousPlane implements Flyer, Swimmer {
    @Override
    public void takeOff() {
        // 方案一：选择其中一个父接口的实现
        System.out.println("决策：优先选择飞行模式...");
        Flyer.super.takeOff(); // 使用 Flyer 的默认方法

        // 方案二：或者，你也可以调用 Swimmer 的
        // Swimmer.super.takeOff();

        // 方案三：提供一个全新的实现
        // System.out.println("水陆两栖模式启动，涡轮喷射，水花四溅，冲上云霄！");
    }
}

核心规则

当一个类面临来自多个父接口的同名默认方法冲突时，它必须通过重写（@Override）该方法来消除歧义。在方法内部，可以使用 InterfaceName.super.methodName() 语法来精确调用特定父接口的默认实现。

接口与多态

接口也可以实现多态。当一个类实现一个接口时，它的对象实例就可以被这个接口类型的引用所指向。

这允许我们编写更通用的代码，操作的是接口而不是具体的类，从而实现“面向接口编程”，极大地提高了代码的灵活性和可扩展性。


// 1. 定义一个接口，作为行为契约
public interface Flyable {
    void fly();
}

// 2. 不同的类实现这个接口
public class Bird implements Flyable {
    @Override
    public void fly() {
        System.out.println("小鸟在空中振翅飞翔...");
    }
}

public class Airplane implements Flyable {
    @Override
    public void fly() {
        System.out.println("飞机在高空引擎轰鸣地飞行...");
    }
}

// 3. 使用接口引用实现多态
public class TestPolymorphism {
    public static void main(String[] args) {
        // 接口引用指向不同的实现类对象
        Flyable flyer1 = new Bird();
        Flyable flyer2 = new Airplane();

        makeItFly(flyer1); // 输出: 小鸟在空中振翅飞翔...
        makeItFly(flyer2); // 输出: 飞机在高空引擎轰鸣地飞行...
    }

    // 这个方法接受任何实现了Flyable接口的对象
    public static void makeItFly(Flyable f) {
        f.fly();
    }
}

Java 8+ 为接口引入了新特性，使接口更加强大和灵活。

🚀 现代接口的完整特性


public interface ModernInterface {

    int MAX_SIZE = 100;
    String DEFAULT_NAME = "Unknown";

抽象类 vs 接口：深度对比分析

抽象类和接口都是实现抽象的重要手段，但它们有着不同的设计理念和使用场景。

📊 详细对比表

对比维度 抽象类 (Abstract Class) 接口 (Interface)

🏗️ 选择抽象类的场景

  • 有共同的代码需要复用
  • 需要定义非public的方法
  • 需要定义实例变量
  • 类之间有明确的"is-a"关系
  • 需要提供构造方法

🔌 选择接口的场景

  • 定义一组能力或行为规范
  • 需要多重继承的效果
  • 不同类需要相同的行为
  • 强调"can-do"的能力关系
  • API设计和框架开发

实战案例：智能设备管理系统

通过一个完整的案例来理解抽象类和接口的协同使用。

🌍 系统设计思路


// 抽象类：定义设备的共同本质（is-a关系）
public abstract class SmartDevice {
    protected String deviceId;
    protected String brand;
    protected boolean isOnline;
    
    // 构造方法
    public SmartDevice(String deviceId, String brand) {
        this.deviceId = deviceId;
        this.brand = brand;
        this.isOnline = false;
    }
    
    // 具体方法：所有设备的共同行为
    public void connect() {
        isOnline = true;
        System.out.println(brand + " 设备 " + deviceId + " 已连接");
    }
    
    public void disconnect() {
        isOnline = false;
        System.out.println("设备 " + deviceId + " 已断开");
    }
    
    // 抽象方法：不同设备的特定行为
    public abstract void performMainFunction();
    public abstract String getDeviceType();
}

// 接口：定义设备的能力（can-do关系）
interface Controllable {
    void turnOn();
    void turnOff();
    boolean isOn();
}

interface Schedulable {
    void setSchedule(String time, String action);
    void executeScheduledTask();
}

interface VoiceControlled {
    void processVoiceCommand(String command);
    default void enableVoiceControl() {
        System.out.println("语音控制已启用");
    }
}

// 具体设备类：智能灯泡
public class SmartBulb extends SmartDevice 
                      implements Controllable, Schedulable, VoiceControlled {
    private boolean isLightOn = false;
    private int brightness = 50;
    private String scheduledAction;
    
    public SmartBulb(String deviceId, String brand) {
        super(deviceId, brand);
    }
    
    @Override
    public void performMainFunction() {
        System.out.println("智能灯泡提供照明功能");
    }
    
    @Override
    public String getDeviceType() {
        return "Smart Bulb";
    }
    
    // 实现 Controllable 接口
    @Override
    public void turnOn() {
        isLightOn = true;
        System.out.println("灯泡已开启，亮度：" + brightness + "%");
    }
    
    @Override
    public void turnOff() {
        isLightOn = false;
        System.out.println("灯泡已关闭");
    }
    
    @Override
    public boolean isOn() {
        return isLightOn;
    }
    
    // 实现 Schedulable 接口
    @Override
    public void setSchedule(String time, String action) {
        scheduledAction = action;
        System.out.println("已设置定时任务：" + time + " - " + action);
    }
    
    @Override
    public void executeScheduledTask() {
        if (scheduledAction != null) {
            System.out.println("执行定时任务：" + scheduledAction);
        }
    }
    
    // 实现 VoiceControlled 接口
    @Override
    public void processVoiceCommand(String command) {
        switch (command.toLowerCase()) {
            case "开灯":
                turnOn();
                break;
            case "关灯":
                turnOff();
                break;
            case "调亮":
                brightness = Math.min(100, brightness + 20);
                System.out.println("亮度调至：" + brightness + "%");
                break;
            default:
                System.out.println("无法识别的语音命令：" + command);
        }
    }
}

看看如何通过多态和接口实现灵活的设备管理。


public class SmartHomeManager {
    private List<SmartDevice> devices = new ArrayList<>();
    
    public void addDevice(SmartDevice device) {
        devices.add(device);
        device.connect();
    }
    
    // 多态：统一管理所有设备
    public void showAllDevices() {
        for (SmartDevice device : devices) {
            System.out.println("设备类型：" + device.getDeviceType());
            device.performMainFunction();  // 多态调用
        }
    }
    
    // 接口：只控制可控制的设备
    public void turnOnAllControllableDevices() {
        for (SmartDevice device : devices) {
            if (device instanceof Controllable) {
                Controllable controllable = (Controllable) device;
                controllable.turnOn();
            }
        }
    }
    
    // 接口：为支持语音的设备执行语音命令
    public void executeVoiceCommand(String command) {
        for (SmartDevice device : devices) {
            if (device instanceof VoiceControlled) {
                VoiceControlled voiceDevice = (VoiceControlled) device;
                voiceDevice.processVoiceCommand(command);
            }
        }
    }
}

枚举类

当一个变量的取值范围是有限且固定的集合时（如星期、季节、状态），使用枚举类是最佳选择。

枚举 (Enum)提供了类型安全，避免了使用字符串或整数常量可能导致的错误，并使代码更具可读性。


// 定义一个表示状态的枚举
public enum Status {
    RUNNING("跑步中"), 
    STUDYING("学习中"), 
    SLEEPING("睡觉中");

    private final String description;

    // 枚举的构造方法默认是 private
    Status(String description) {
        this.description = description;
    }

    public String getDescription() {
        return description;
    }
}

// 使用枚举
Status currentStatus = Status.STUDYING;
System.out.println("当前状态: " + currentStatus.getDescription()); // 输出: 当前状态: 学习中

枚举的本质是继承自 java.lang.Enum 的特殊类，功能远比简单的常量强大。

⚠️ 常见错误和陷阱

学习过程中容易犯的错误，提前了解可以避免很多坑。

🚫 陷阱1：封装破坏

❌ 错误示例


public class Student {
    public String name;           // 直接暴露字段
    public List<String> courses;   // 暴露可变集合
    
    public List<String> getCourses() {
        return courses;           // 返回内部集合的直接引用
    }
}

// 使用时可能出现的问题
Student student = new Student();
student.name = "";               // 可以设置无效值
student.getCourses().clear();    // 外部可以修改内部状态

✅ 正确做法


public class Student {
    private String name;
    private List<String> courses = new ArrayList<>();
    
    public void setName(String name) {
        if (name != null && !name.trim().isEmpty()) {
            this.name = name;
        } else {
            throw new IllegalArgumentException("姓名不能为空");
        }
    }
    
    public String getName() {
        return name;
    }
    
    public List<String> getCourses() {
        return new ArrayList<>(courses);  // 返回副本，保护内部状态
    }
    
    public void addCourse(String course) {
        if (course != null && !courses.contains(course)) {
            courses.add(course);
        }
    }
}

🚫 陷阱3：多态误用

❌ 常见错误


Animal animal = new Dog();
Dog dog = animal;              // 编译错误：不能直接向下转型
dog.wagTail();

// 或者
if (animal instanceof Dog) {
    Dog dog = (Dog) animal;
    dog.wagTail();             // 虽然可以，但破坏了多态的意义
}

✅ 正确做法：通过接口或抽象方法实现


// 定义能力接口
interface TailWagger {
    void wagTail();
}

class Dog extends Animal implements TailWagger {
    @Override
    public void wagTail() {
        System.out.println("摇尾巴");
    }
}

// 使用时
Animal animal = new Dog();
if (animal instanceof TailWagger) {
    TailWagger wagger = (TailWagger) animal;
    wagger.wagTail();          // 基于能力的调用，更符合OOP原则
}

💡 最佳实践总结

  • 封装：永远使用private字段 + public方法，验证输入，保护内部状态
  • 继承：确保真正的"is-a"关系，优先考虑组合而非继承
  • 多态：通过接口和抽象类设计，避免强制类型转换
  • 接口：保持接口小而专注，遵循单一职责原则
  • 抽象类：提供合理的默认实现，为子类留出扩展空间

总结：封装、继承与多态

今天我们学习了面向对象编程的三大核心特性，它们是构建高质量Java应用的基石。

  • 封装是基础，它保护数据，隐藏细节，提供了清晰的接口。
  • 继承是扩展，它复用代码，建立了类之间的层次关系。
  • 多态是灵魂，它提升了灵活性和可扩展性，让程序“活”了起来。

同时，我们也了解了抽象类、接口和枚举等重要概念，它们都是实现这些特性的重要工具。
