游戏规则与平台概述

1. 五子棋基础介绍

五子棋起源于中国，规则简单但变化无穷。

1.2 游戏规则

  • 棋盘: 15×15 的网格。
  • 落子: 黑方先手，白方后手，轮流落子。
  • 获胜: 横、竖、斜任一方向连续5子同色即胜。
  • 平局: 棋盘下满且无五连珠。
  • 禁手 (可选):
    • 本项目主要实现基础规则（无禁手）。
    • 扩展说明: 标准规则中黑方有"三三"、"四四"、"长连"禁手。

2. 在线对战平台概述

基于 C/S (Client-Server) 架构的命令行实时网络对战系统。

2.2 核心功能需求

  • 用户系统: 输入昵称登录，身份标识。
  • 房间与匹配:
    • 大厅(Lobby): 查看所有房间状态。
    • 加入(Join): 指定房间号进入，两人同房。
  • 实时对战:
    • 棋盘同步: 服务器维护权威状态并推送。
    • 回合控制: 严格轮流落子。
    • 胜负判定: 服务器实时计算。
  • 辅助功能: ANSI颜色渲染，清屏刷新。

架构设计与技术栈

Part 2: 核心算法与棋盘模型

为什么要写这个作业？(Motivation)

上一节我们有了“眼睛”（日志），这一节我们要造“大脑”。

五子棋看起来简单——“谁先连成5个谁赢”。但在计算机眼里，它只是一堆数字。

  • 数据建模: 你需要把现实中的棋盘映射到内存中。
  • 算法逻辑: 你需要告诉计算机，怎么才算“连成5个”。

GameBoard 类是整个项目的核心。如果它写错了（比如误判输赢），那么后面的网络对战、房间管理做得再好也是白搭。

核心知识点 (Key Concepts)

1. 二维数组与坐标系

int[15][15] 是最直观的表示。

  • x (row): 0-14 (垂直方向，从上到下)
  • y (col): 0-14 (水平方向，从左到右)
  • 值: 0=空, 1=黑, 2=白
2. 方向向量 (Direction Vectors)

如何检查五子连珠？笨办法是写4个大循环。

聪明办法是利用向量简化代码：

  • 水平: dx=0, dy=1
  • 垂直: dx=1, dy=0
  • 对角: dx=1, dy=1
  • 反斜: dx=1, dy=-1

算法优化: 只需检查新落子点周围的4个方向，无需扫描全盘。

Part 3: 面向对象建模

为什么要写这个作业？(Motivation)

在作业 2 中，我们有了一个永远不会犯错的“裁判”（GameBoard）。但现在的游戏是“死”的——没有玩家，没有回合，没有开始和结束。

我们需要引入 面向对象 (OOP) 的核心思想来模拟现实世界：

  • Player (玩家): 有名字、有颜色、有连接。
  • GameRoom (房间): 这就像棋牌室里的一张桌子。它把两个玩家和一副棋盘组合在一起，并负责维护规则。

这个作业将把零散的逻辑组装成一个可运行的游戏闭环。

核心知识点 (Key Concepts)

1. 组合 (Composition)

GameRoom 拥有 (Has-a) 棋盘。

这种设计让我们可以随时更换棋盘（如重置游戏），而不影响房间本身。

2. 线程安全初探

将来 Player1 和 Player2 在不同线程。

如果两人同时点“准备”或同时“落子”？

涉及修改状态的方法(addPlayer, makeMove)需加 synchronized。

3. 状态机 (State Machine)

房间有生命周期，不能在 GameOver 后继续落子。

维护标记位：isGameStarted, isGameOver。

任务拆解 (Step-by-Step)

Task 1: Player 类

简单的实体类 (POJO)。

  • 属性：name, socket (暂null), color ("black"/"white"), currentRoom。
  • 接口：sendMessage(String msg) (暂时用 System.out 模拟)。

Task 2: GameRoom 类 (核心)

  • 2.1 初始化:
    • roomId
    • new GameBoard()
    • playerCount (建议使用 AtomicInteger 以确保线程安全，或在同步块中操作)。
  • 2.2 addPlayer(Player p):
    • 人满(>2)返回 false。
    • 第一个是 p1，第二个是 p2。
    • 更新 p.currentRoom。
  • 2.3 startGame(): 重置棋盘，随机分配颜色，isGameStarted=true。

Task 2: GameRoom (续) - makeMove

makeMove(x, y, color) 五步逻辑

  1. 检查状态: 游戏是否开始？是否结束？
  2. 检查轮次: color 是否等于 currentTurnColor？(防止连下)。
  3. 执行落子: 调用 board.makeMove。
  4. 检查胜负: 调用 board.checkWin。
    • 赢了 -> isGameOver=true。
  5. 切换回合: 没赢 -> 黑变白，白变黑。

Part 4: 资源管理

为什么要写这个作业？(Motivation)

现在你已经能造出一个完美的“对战房间”了。但问题来了：如果有 1000 个玩家同时登录，你难道要手动 new GameRoom() 500次吗？

我们需要一个房间管理器 (RoomManager)，就像酒店的大堂经理：

  • 接待: 给新开的房间分配唯一的门牌号 (ID)。
  • 查询: 随时告诉玩家“3号房在这儿”。
  • 清理: 当房间空了，负责回收资源，而不是让它永远占用内存。

核心知识点 (Key Concepts)

1. 集合选型 (List vs Map)
  • List<GameRoom>: 查找 ID=888 需要遍历，复杂度 O(n)。效率低。
  • Map<Integer, GameRoom>: map.get(888)，复杂度 O(1)。服务器开发中查找速度至关重要。
2. 线程安全 (Concurrency)
  • ConcurrentHashMap: 强烈推荐。Java为高并发设计的Map，防止多线程读写崩溃。
  • AtomicInteger: 替代 int id++。保证 ID 生成的原子性，多线程下绝不重复。

任务拆解 (Step-by-Step)

Task 1: RoomManager 定义

类：com.wuzi.server.RoomManager

  • 1.1 成员变量: 
    private final Map rooms;
private final AtomicInteger idGenerator;
  • 1.2 构造方法:
    • rooms = new ConcurrentHashMap<>();
    • idGenerator = new AtomicInteger(1);
    • 可选: 预先创建 10 个房间，避免第一批玩家等待。

Task 2: 核心业务方法

  • 创建房间: 
    public GameRoom createRoom() {
    int id = idGenerator.getAndIncrement(); // 安全获取ID
    GameRoom room = new GameRoom(id);
    rooms.put(id, room);
    ServerLogger.info("房间 " + id + " 已创建");
    return room;
}
  • 销毁房间: removeRoom(int id) -> rooms.remove(id) + 日志。
  • 查找与列表:
    • getRoom(int id): 简单代理 Map 的 get。
    • getAllRooms(): 直接返回 Map (或只读视图)。

Part 5: Socket 网络编程

为什么要写这个作业？(Motivation)

前四个作业都是“单机游戏”。现在的目标是让它们“联网”。

让北京的 Alice 输入 put 5 5，上海的 Bob 屏幕上立刻出现黑子。

这需要 Socket (套接字) —— 网络世界的“电话插孔”。

核心知识点 (Key Concepts)

1. C/S 架构

Server: 像24小时客服中心，一直监听 (ServerSocket)。

Client: 像顾客，主动拨打服务器电话 (Socket)。

2. 多线程并发

主线程只负责“接电话” (accept)。

一旦接通，雇佣新线程 (ClientHandler) 专门陪 Alice 聊天，主线程回到门口等待下一个。

3. 文本协议

约定交流语言：

  • ls rooms
  • enter room <id>
  • put <x> <y>

服务端任务拆解

Task 1: 服务员 ClientHandler

实现 Runnable 接口。

  • 1.1 构造: 接收 Socket 和 RoomManager。
  • 1.2 run() 方法:
    1. 获取输入流(BufferedReader)和输出流(PrintWriter)。
    2. 读取第一行作为名字，创建 Player。
    3. while(true) 循环读取指令。
    4. 解析指令 (split(" "))，调用 GameRoom 逻辑。
    5. 关键: 结果通过 out.println 发回客户端。

    while(true) {
        // 阻塞直到有人连接
        Socket client = server.accept();
        // 把客人交给服务员
        pool.execute(new ClientHandler(client, manager));
    }
}

客户端、联调与评分

Task 3: 玩家终端 GameClient

双线程架构: 为什么？你不知道对手何时落子，不能傻等。

  • 主线程: 读取键盘 (Scanner) -> 发送给服务器。
  • 接收线程: 后台循环读取服务器消息 -> 打印到屏幕。

The Grand Finale (联调步骤)

  1. 启动 Server。
  2. 启动 Client A (Alice)。
  3. 启动 Client B (Bob)。
  4. Alice: ls rooms -> 看到空房间。
  5. Alice: enter room 1 -> 等待。
  6. Bob: enter room 1 -> 游戏开始!
  7. Alice: put 7 7 -> 双方看黑子。
  8. Bob: put 7 8 -> 双方看白子。

评分标准

  • 并发能力 (40%): 服务器必须能同时处理 Alice 和 Bob，不能因 Alice 没说话就卡住 Bob。
  • 协议解析 (30%): 正确处理 ls, enter, put。错误命令(put abc)有提示且不崩溃。
  • 用户体验 (30%): 棋盘刷新及时。断开连接能正确清理资源(踢出房间)。
