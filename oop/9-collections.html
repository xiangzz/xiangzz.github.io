常规结构痛点

场景：我们要开发一个简单的学生管理系统，需要保存全班同学的名单。

😰 使用数组 String[]


// 容量固定，操作复杂
String[] students = new String[50];
students[0] = "张三";
students[1] = "李四";
// 需要手动管理大小和索引

🤔 痛点分析：

  • 容量问题：如果只有30人，浪费20个空间；第51个学生怎么办？
  • 增删问题：删除第2个学生，需手动移动后续所有元素
  • 查找问题：检查"王五"是否存在，必须从头遍历(O(n))
  • 功能问题：需要"不重复"名单？数组无能为力

😍 使用容器框架


// 动态大小，操作简单
List<String> students = new ArrayList<>();
students.add("张三");
students.add("李四");
// 自动管理大小，丰富的操作方法

✨ 容器框架的优势

🚀
  • 自动扩容：不用担心容量问题
  • 高效增删：add(), remove() 一行代码
  • 查找性能：Set/Map 平均 O(1)，List.contains O(n)
  • 功能丰富：Set(去重)、Map(键值对)等

实战案例：学生管理

🎯 场景1：存储班级学生名单，按录入顺序排列

🤔 分析：

  • 按录入顺序 → 有序
  • 可能有重名 → 可重复
  • 有序 + 可重复 → List
  • 常用操作：点名(遍历)、查看第N个学生(get) → ArrayList查询最快

// 1. 创建名单
List<String> studentList = new ArrayList<>();

// 2. 添加学生
studentList.add("张三");
studentList.add("李四");
studentList.add("王五");
studentList.add("张三"); // List允许重复

// 3. 按索引获取
System.out.println("第2个学生是: " + studentList.get(1));

// 4. 遍历(点名)
for(String student : studentList) {
    System.out.println(student);
}

📚 场景2：存储已选课程名称，不能重复

🤔 分析：

  • 课程名称 → String
  • 不能重复 → 唯一
  • 唯一 → Set
  • 只关心"是否选了某门课"(contains)，性能优先 → HashSet

// 1. 创建课程池
Set<String> courseSet = new HashSet<>();

// 2. 添加课程
courseSet.add("Java程序设计");
courseSet.add("计算机网络");
courseSet.add("Java程序设计"); // 重复被自动忽略

// 3. 检查
System.out.println(courseSet.size()); // 输出: 2
System.out.println("是否选了Java? " + courseSet.contains("Java程序设计"));

🎓 场景3：存储学号和对应的GPA

🤔 分析：

  • 学号(Integer) + GPA(Double) → 键值对
  • 学号唯一，用来查找GPA → Key唯一
  • Key-Value → Map
  • 查找速度最快，不关心顺序 → HashMap

// 1. 创建成绩单
Map<Integer, Double> gpaMap = new HashMap<>();

// 2. 录入成绩
gpaMap.put(1001, 3.8);
gpaMap.put(1002, 3.5);
gpaMap.put(1003, 4.0);

// 3. 查询成绩
Double gpa = gpaMap.get(1002);
System.out.println("1002号的GPA是: " + gpa);

// 4. 遍历
for(Map.Entry<Integer, Double> entry : gpaMap.entrySet()) {
    System.out.println("学号: " + entry.getKey() + ", GPA: " + entry.getValue());
}

💡 核心要点与性能提示

⚡ 性能关键

  • ArrayList: 随机访问 get(i) 为 O(1)，插入/删除 O(n)。
  • HashSet/HashMap: 增删查平均 O(1)，依赖 hashCode。
  • LinkedList: 头尾操作 O(1)，随机访问 O(n)。

🛠️ 实用技巧

  • 空指针保护: 优先用 getOrDefault 替代 get。
  • 批量操作: addAll / removeAll 比循环更高效。
  • 集合转换: new ArrayList<>(set) 可快速去重转列表。

容器遍历方式

一站式掌握 List、Set、Map 的高效遍历与安全操作

📊 遍历方式性能与场景对比

方式 适用场景 特点
增强for 只读遍历 (List/Set) 语法最简洁，无法删除
Iterator 需要删除元素 唯一安全的遍历删除方式
Stream API 复杂处理 (过滤/映射) 函数式风格，支持并行
entrySet Map 遍历 (推荐) 同时获取Key和Value，最高效

⚠️ 关键陷阱：ConcurrentModificationException

永远不要在 foreach 循环中直接调用 list.remove()！

✅ 正确做法：使用 Iterator.remove() 或 Java 8+ removeIf()。

List<String> list = new ArrayList<>(Arrays.asList("A", "B", "C", "D"));

// ❌ 错误做法：会抛出 ConcurrentModificationException
try {
    for (String item : list) {
        if (item.equals("B")) {
            list.remove(item);  // 在 foreach 中直接修改集合
        }
    }
} catch (ConcurrentModificationException e) {
    System.out.println("捕获异常: " + e.getClass().getSimpleName());
}

// ✅ 正确做法 1：使用 Iterator
List<String> list1 = new ArrayList<>(Arrays.asList("A", "B", "C", "D"));
Iterator<String> iterator = list1.iterator();
while (iterator.hasNext()) {
    String item = iterator.next();
    if (item.equals("B")) {
        iterator.remove();  // 安全删除
    }
}

// ✅ 正确做法 2：使用 removeIf()（Java 8+）
List<String> list2 = new ArrayList<>(Arrays.asList("A", "B", "C", "D"));
list2.removeIf(item -> item.equals("B"));  // 简洁安全

💻 核心代码范例

List / Set 遍历

// 1. 增强for (推荐只读)
for (String s : list) { ... }

// 2. Iterator (安全删除)
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if ("target".equals(it.next())) {
        it.remove(); // ✅ 安全
    }
}

// 3. Stream (过滤+处理)
list.stream()
    .filter(s -> s.length() > 3)
    .forEach(System.out::println);
Map 遍历

// 1. entrySet (推荐高效)
for (Map.Entry<K,V> entry : map.entrySet()) {
    K key = entry.getKey();
    V val = entry.getValue();
}

// 2. forEach (Java 8+ 简洁)
map.forEach((k, v) -> {
    System.out.println(k + "=" + v);
});

🔢 集合的数学运算


// 并集（Union）
Set<String> set1 = new HashSet<>(Arrays.asList("A", "B", "C"));
Set<String> set2 = new HashSet<>(Arrays.asList("C", "D", "E"));

Set<String> union = new HashSet<>(set1);
union.addAll(set2); // [A, B, C, D, E]

// 交集（Intersection）
Set<String> intersection = new HashSet<>(set1);
intersection.retainAll(set2); // [C]

// 差集（Difference）
Set<String> difference = new HashSet<>(set1);
difference.removeAll(set2); // [A, B]

// 实际应用：求两个课程的共同学生
public static <T> Set<T> getIntersection(Set<T> set1, Set<T> set2) {
    Set<T> result = new HashSet<>(set1);
    result.retainAll(set2);
    return result;
}

进阶：线程安全与最佳实践

高并发场景下的集合选择与生产环境开发规范

🔒 线程安全指南

原则：普通集合（ArrayList/HashMap）非线程安全。多线程环境必须使用并发集合。

✅ 推荐方案 (JUC)


// Map: 高性能并发读写
Map<K,V> map = new ConcurrentHashMap<>();

// List: 读多写少 (写时复制)
List<T> list = new CopyOnWriteArrayList<>();

// Queue: 高性能非阻塞队列
Queue<T> queue = new ConcurrentLinkedQueue<>();

🚫 避免使用 (遗留类)


// 性能差，所有操作加锁
Vector<T> v = new Vector<>();
Hashtable<K,V> t = new Hashtable<>();
// Collections.synchronizedList(...)

�️ 开发最佳实践

  • 面向接口编程
    List<String> list = new ArrayList<>();
  • 设置初始容量
    预估大小，避免频繁扩容 (Resize代价大)。
    new HashMap<>(16);
  • 使用不可变集合 (Java 9+)
    List.of("A", "B"), Map.of("K", "V")
    (更安全，占用内存更少)
  • 判空处理
    返回空集合 Collections.emptyList() 而非 null。
    使用 CollectionUtils.isEmpty(list)。
  • Map 遍历
    优先使用 entrySet() 或 forEach()。

ArrayList 深度解析

🏗️ 动态数组原理

📊 ArrayList vs 普通数组


// 普通数组 - 容量固定
String[] array = new String[5];
// array[6] = "越界"; // 数组越界异常

// ArrayList - 自动扩容
List<String> list = new ArrayList<>();
for (int i = 0; i < 1000; i++) {
    list.add("元素" + i); // 自动扩容
}

// ArrayList内部维护一个Object[]数组
// transient Object[] elementData;
// private int size;

⚡ 扩容机制详解


// ArrayList扩容源码分析
private void grow(int minCapacity) {
    int oldCapacity = elementData.length;
    int newCapacity = oldCapacity + (oldCapacity >> 1); // 1.5倍扩容

    if (newCapacity - minCapacity < 0) {
        newCapacity = minCapacity;
    }

    elementData = Arrays.copyOf(elementData, newCapacity);
}

// 扩容过程：
// 1. 创建新数组（1.5倍大小）
// 2. 复制旧数组到新数组
// 3. 丢弃旧数组

💡 扩容的性能影响

ArrayList的默认初始容量是10，每次扩容时创建1.5倍大小的新数组并复制所有元素。频繁扩容会严重影响性能。

最佳实践：在知道大致元素数量时，使用 new ArrayList<>(expectedSize) 预设容量。

🎯 适用场景分析

✅ 适合ArrayList的场景

  • 频繁随机访问：通过索引获取元素
  • 顺序遍历：for循环或迭代器遍历
  • 读多写少：查询操作远多于增删操作
  • 元素数量相对稳定：不会频繁大幅变化

❌ 不适合ArrayList的场景

  • 频繁插入删除：特别是在列表中间
  • 需要线程安全：多线程环境读写
  • 元素数量变化极大：频繁扩容影响性能
  • 大量唯一性检查：contains操作频繁

🆚 ArrayList vs 其他List实现

⚡ ArrayList vs LinkedList


// 性能对比测试
public class ListPerformanceTest {

    public static void main(String[] args) {
        final int COUNT = 100000;

        // 测试随机访问
        List<Integer> arrayList = new ArrayList<>();
        List<Integer> linkedList = new LinkedList<>();

        // 填充数据
        for (int i = 0; i < COUNT; i++) {
            arrayList.add(i);
            linkedList.add(i);
        }

        // 随机访问测试
        long start = System.currentTimeMillis();
        for (int i = 0; i < 1000; i++) {
            arrayList.get(new Random().nextInt(COUNT));
        }
        long arrayListTime = System.currentTimeMillis() - start;

        start = System.currentTimeMillis();
        for (int i = 0; i < 1000; i++) {
            linkedList.get(new Random().nextInt(COUNT));
        }
        long linkedListTime = System.currentTimeMillis() - start;

        System.out.println("ArrayList随机访问: " + arrayListTime + "ms");
        System.out.println("LinkedList随机访问: " + linkedListTime + "ms");
        // 结果：ArrayList快数百倍
    }
}

🏗️ HashMap 内部结构

📊 基本数据结构


// HashMap核心字段
public class HashMap<K,V> {
    // 哈希桶数组
    transient Node<K,V>[] table;

    // 键值对数量
    transient int size;

    // 扩容阈值 = 容量 * 加载因子
    int threshold;

    // 加载因子（默认0.75）
    final float loadFactor;

    // Node节点结构
    static class Node<K,V> {
        final int hash;
        final K key;
        V value;
        Node<K,V> next;
    }
}

🔢 哈希计算过程


// 1. 计算Key的哈希值
static final int hash(Object key) {
    int h;
    // 高16位异或低16位，减少哈希冲突
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}

// 2. 计算数组索引位置
// n = table.length 必须是2的幂
int index = (n - 1) & hash;

// 示例：容量16，hash值为5
// n = 16, n-1 = 15 (二进制1111)
// hash = 5 (二进制0101)
// index = 15 & 5 = 5

💡 为什么容量必须是2的幂？

为了让哈希分布更均匀，Java 8使用(n - 1) & hash来计算索引。当n是2的幂时，n-1的二进制全为1，这样hash的任何一位都能影响结果，使哈希分布更均匀。

🔗 Java 7: 链表法


// 哈希冲突时使用链表连接
// 时间复杂度：O(n)

// 插入过程：
// 1. 计算hash和索引
// 2. 遍历链表检查是否已存在
// 3. 不存在则在链表头部插入
// 4. 存在则更新value

// 查找过程：
// 1. 计算hash和索引
// 2. 遍历链表查找目标key
// 3. 找到返回value，未找到返回null

// 缺点：链表过长时性能急剧下降

🌳 Java 8: 链表 + 红黑树


// 链表长度超过8时转换为红黑树
static final int TREEIFY_THRESHOLD = 8;

// 红黑树节点
static final class TreeNode<K,V> extends Node<K,V> {
    TreeNode<K,V> parent;
    TreeNode<K,V> left;
    TreeNode<K,V> right;
    boolean red;
}

// 时间复杂度优化：
// - 链表：O(n)
// - 红黑树：O(log n)

// 转换条件：
// 1. 链表长度 >= 8
// 2. 桶数组容量 >= 64
                        

// 扩容机制：当 size >= threshold 时扩容
// threshold = capacity * loadFactor
// 默认：初始容量16，加载因子0.75，扩容阈值12

// 扩容过程：
// 1. 创建新的数组，容量翻倍
// 2. 重新计算所有元素的hash和位置
// 3. 将元素迁移到新数组
// 4. 红黑树分裂（如果存在）

// 性能影响：扩容是O(n)操作，应尽量避免

// 1. 正确实现hashCode和equals
class GoodKey {
    private int value;

    // ✅ 好的hashCode实现
    @Override
    public int hashCode() {
        return Integer.hashCode(value);
    }

    // ✅ 正确的equals实现
    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (!(obj instanceof GoodKey)) return false;
        return value == ((GoodKey) obj).value;
    }
}

// 定义在类内部，实现自然排序规则
public class Student implements Comparable<Student> {
    private String name;
    private int age;
    private double gpa;

    public Student(String name, int age, double gpa) {
        this.name = name;
        this.age = age;
        this.gpa = gpa;
    }

    // ✅ 实现compareTo方法
    @Override
    public int compareTo(Student other) {
        // 按年龄升序排序
        return Integer.compare(this.age, other.age);

        // 其他比较方式：
        // return this.name.compareTo(other.name); // 按姓名
        // return Double.compare(this.gpa, other.gpa); // 按GPA
    }

    // getter和setter方法...
}

// 使用方式
List<Student> students = Arrays.asList(
    new Student("张三", 20, 3.5),
    new Student("李四", 18, 3.8),
    new Student("王五", 22, 3.2)

Collections.sort(students); // 直接排序，使用自然排序规则

🛠️ Comparator：自定义排序


// 定义在外部，灵活的排序规则
public class StudentComparator {

    // 按姓名排序
    public static Comparator<Student> byName() {
        return Comparator.comparing(Student::getName);
    }

      // 按GPA降序排序
    public static Comparator<Student> byGpaDescending() {
        return Comparator.comparing(Student::getGpa)
                           .reversed();
    }

    // 多条件排序：先按GPA降序，再按年龄升序
    public static Comparator<Student> complexSorting() {
        return Comparator.comparing(Student::getGpa)
                           .reversed()
                           .thenComparing(Student::getAge);
    }
}

// 使用方式
List<Student> students = new ArrayList<>();

// 方式1: 使用Comparator排序
Collections.sort(students, StudentComparator.byName());

// 方式2: Java 8 Lambda表达式
students.sort(Comparator.comparing(Student::getAge));

// 方式3: 复杂排序
students.sort(StudentComparator.complexSorting());

📚 实战应用案例

🎓 案例1：学生成绩排序系统


public class StudentSorter {

    public static void sortStudents(List<Student> students, String criteria) {
        switch (criteria) {
            case "name":
                students.sort(Comparator.comparing(Student::getName));
                break;
            case "age":
                students.sort(Comparator.comparing(Student::getAge));
                break;
            case "gpa":
                students.sort(Comparator.comparing(Student::getGpa).reversed());
                break;
            case "comprehensive":
                students.sort(
                    Comparator.comparing(Student::getGpa).reversed()
                             .thenComparing(Student::getAge)
                             .thenComparing(Student::getName)
                );
                break;
        }
    }
}

🗺️ 案例2：Map按键值排序


public class MapSorter {

    // 按Key排序
    public static <K, V> Map<K, V> sortByKey(Map<K, V> map, Comparator<K> comparator) {
        return map.entrySet().stream()
                .sorted(Map.Entry.comparingByKey(comparator))
                .collect(Collectors.toMap(
                    Map.Entry::getKey,
                    Map.Entry::getValue,
                    (oldValue, newValue) -> oldValue,
                    LinkedHashMap::new
                ));
    }

    // 按Value排序
    public static <K, V extends Comparable<V>> Map<K, V> sortByValue(Map<K, V> map) {
        return map.entrySet().stream()
                .sorted(Map.Entry.comparingByValue())
                .collect(Collectors.toMap(
                    Map.Entry::getKey,
                    Map.Entry::getValue,
                    (oldValue, newValue) -> oldValue,
                    LinkedHashMap::new
                ));
    }
}

💡 排序最佳实践总结

📝 何时使用Comparable

  • 类有明确的"自然排序"规则
  • 排序规则在类设计时就确定
  • 需要多次使用相同排序规则
  • TreeSet/TreeMap的默认排序

🛠️ 何时使用Comparator

  • 需要多种不同的排序规则
  • 类无法修改（如第三方库）
  • 需要动态改变排序规则
  • 复杂的排序逻辑
