持续集成与持续部署

代码推送到 main，自动测试、构建、上线

你有没有想过

为什么大公司的代码从不出现"忘记跑测试就上线"的事故？为什么他们的部署只需要点一个按钮？

因为他们有 CI/CD。每次代码推送，机器自动执行：检查代码 → 跑测试 → 构建 → 部署。

这个比喻只是为了帮你建立直观感受：CI/CD 像一条自动质检流水线，代码像产品一样经过每道工序。不合格的产品（代码）会被自动拦截，不会到达客户手中。

CI/CD 流程

从 git push 到自动部署的完整链路

graph LR
    A[git push] --> B[GitHub Actions]
    B --> C[Lint 检查]
    B --> D[类型检查]
    B --> E[单元测试]
    C --> F{全部通过?}
    D --> F
    E --> F
    F -->|是| G[构建 Docker 镜像]
    F -->|否| H[通知开发者]
    G --> I[推送镜像到 Registry]
    I --> J[SSH 部署到服务器]
    J --> K[健康检查]
    K -->|通过| L[部署完成]
    K -->|失败| M[自动回滚]

核心概念

GitHub Actions 的六个关键词

概念说明类比
Workflow自动化流程定义一条流水线
Event触发条件启动按钮
Job一组步骤一个工位
Step单个操作工位上的动作
Action可复用操作单元可复用的工具
Runner执行任务的虚拟机执行环境

Part 1: 基础 CI

配置一个完整的持续集成流水线。

CI 工作流配置

推代码时自动跑 Lint + 测试 + 构建

# .github/workflows/ci.yml
name: CI
on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20', cache: 'npm' }
      - run: npm ci
      - run: npx eslint src/ --max-warnings=0
      - run: npx tsc --noEmit

  test:
    runs-on: ubuntu-latest
    needs: lint
    services:
      postgres:
        image: postgres:16-alpine
        env: { POSTGRES_DB: test_db, POSTGRES_USER: test_user, POSTGRES_PASSWORD: test_password }
        ports: ['5432:5432']
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20', cache: 'npm' }
      - run: npm ci
      - run: npx prisma migrate deploy
      - run: npx vitest run --coverage

触发事件

什么时候跑流水线？你来定

事件触发条件示例
push代码推送到分支branches: [main]
pull_request创建/更新 PRtypes: [opened]
release发布 Releasetypes: [published]
schedule定时执行cron: '0 2 * * *'
workflow_dispatch手动触发UI 点击运行

使用 npm ci 而不是 npm install。它严格按照 lock 文件安装，速度更快，结果更可预测。

Part 2: 自动部署

测试通过后，自动构建镜像并部署到服务器。

部署到 VPS

通过 SSH + Docker 自动部署

# .github/workflows/deploy-vps.yml
name: Deploy to VPS
on:
  push:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20', cache: 'npm' }
      - run: npm ci
      - run: npx vitest run

  deploy:
    runs-on: ubuntu-latest
    needs: test
    environment: production
    steps:
      - name: Deploy via SSH
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.VPS_HOST }}
          username: ${{ secrets.VPS_USER }}
          key: ${{ secrets.VPS_SSH_KEY }}
          script: |
            cd /opt/myapp
            git pull origin main
            docker compose up -d --build
            docker compose exec -T app npx prisma migrate deploy

Docker 镜像发布

构建并推送到 GitHub Container Registry

# .github/workflows/docker-publish.yml
jobs:
  build-and-push:
    runs-on: ubuntu-latest
    permissions: { packages: write }
    steps:
      - uses: actions/checkout@v4
      - uses: docker/setup-buildx-action@v3
      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
      - uses: docker/build-push-action@v5
        with:
          context: .
          push: true
          tags: ghcr.io/${{ github.repository }}:latest
          cache-from: type=gha
          cache-to: type=gha,mode=max

自动 Release

打 Tag 自动生成发布说明

# .github/workflows/release.yml
name: Create Release
on:
  push:
    tags: ['v*']

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - name: Generate changelog
        run: |
          PREV_TAG=$(git describe --tags --abbrev=0 HEAD^)
          git log --pretty=format:"- %s (%h)" $PREV_TAG..HEAD > changelog.txt
      - name: Create GitHub Release
        uses: actions/create-release@v1
        env: { GITHUB_TOKEN: "${{ secrets.GITHUB_TOKEN }}" }
        with:
          tag_name: ${{ github.ref }}
          body_path: changelog.txt

排错：CI 失败

症状：PR 提交后 CI 一直红灯，但本地测试全部通过。
原因：CI 环境和本地不同——Node 版本不一致、数据库没启动、环境变量缺失。
修复：检查 actions/setup-node 的版本号；确认 services 中的数据库健康检查配置；检查 env 环境变量。 
# 本地复现 CI 环境
$ act pull_request    # 用 act 工具在本地跑 GitHub Actions

最佳实践

让 CI/CD 更快、更安全

实践说明收益
缓存依赖cache: 'npm'加速 CI
最小权限只授予必要的 permissions安全
并行任务lint 和 test 并行执行减少总时间
环境保护GitHub Environments 配审批防误部署
Secrets 管理敏感信息存 GitHub Secrets安全
分支保护PR 必须通过 CI 才能合并最后防线
