你有没有想过

网页上的按钮为什么能"记住"你的点击？手机 App 怎么知道你在哪座城市？

这些看似神奇的事情，背后都是同一样东西在驱动：程序。

程序就是一组指令，告诉计算机该做什么。写程序的人叫程序员，写程序的过程就叫编程。

接下来几章，你将从零开始学会用 JavaScript 这门语言来编程——它既能在浏览器里运行，也能在服务器上运行，是今天最流行的编程语言之一。

什么是编程

用语言和计算机对话，让它帮你干活

编程（Programming）是指用一种特定的语言向计算机发出指令，让计算机按预定逻辑执行任务的过程。

说白了，编程就是给计算机写一份精确到每一步的菜谱。你写的每一行代码，就是菜谱中的一个步骤。

这个比喻只是为了帮你建立直观感受。在计算机内部，代码实际上是被翻译成 CPU 能理解的二进制指令来执行的，并不存在什么"菜谱"。

不管什么程序，核心都离不开这四件事：

输入

接收数据——用户点击、键盘输入、文件内容、网络请求，都是输入。

处理

对数据进行计算、筛选、转换。这是程序的核心逻辑。

输出

把处理结果呈现给用户，或者传给其他系统。

控制流

决定程序的执行顺序——什么时候重复，什么时候跳过，什么时候停下来。

什么是 JavaScript

一门既能写网页动画，又能写服务器接口的语言

JavaScript（简称 JS）是一种高级、解释型、动态类型的编程语言，1995 年由 Brendan Eich 在 Netscape 公司仅用 10 天设计出初版。如今它已是世界上最流行的编程语言之一。

用人话说：JavaScript 是一门不需要编译、写完就能直接运行的语言。你写一段 JS 代码，浏览器或 Node.js 马上就能执行它，给你结果。

它的核心特点：

  • 解释型：不需要预先编译，由 JS 引擎直接解释执行
  • 动态类型：变量不需要声明类型，运行时自动确定
  • 多范式：支持面向对象、函数式和事件驱动等多种风格
  • 跨平台：浏览器、服务器、手机、桌面、物联网都能跑

JavaScript 和 Java 是两种完全不同的语言。它们只是在名称上相似。JavaScript 最初叫 Mocha，后改名 LiveScript，最终为了营销目的借了 Java 的名气。

JS 能做什么

不只是一个"网页脚本语言"

领域实际应用
Web 前端网页交互、DOM 操作、动画效果、SPA 应用
Web 后端Node.js 服务器、API 开发、实时通信
移动端React Native 跨平台应用
桌面端Electron（VS Code、Discord 都用它）
游戏Canvas / WebGL 2D/3D 游戏
机器学习TensorFlow.js

从网页到服务器，从手机到桌面，JavaScript 几乎无处不在。这也是我们选择它作为全栈开发主力语言的原因。

JS 引擎全景

同一种语言，不同的运行环境

JavaScript 代码不是直接在操作系统上运行的。它需要一个JS 引擎来解析和执行，再由运行时环境提供额外的能力。

引擎负责把你的代码翻译成机器能执行的指令。运行时则决定了你能用哪些功能——浏览器里你能操作网页，Node.js 里你能读写文件。

JS 简史与 ES 版本

从 10 天造出来的语言，到全球第一

JavaScript 的标准叫 ECMAScript（简称 ES），由 ECMA 国际组织的 TC39 委员会维护。JS 是 ES 标准的一种实现。

年份版本关键特性
1995JS 诞生Brendan Eich 用 10 天设计初版
2009ES5严格模式、JSON、forEach/map/filter
2015ES6（ES2015）里程碑：let/const、箭头函数、class、Promise、模块
2017ES2017async/await

从 ES2015 开始，每年发一个新版本。人们常说的"ES6+"泛指 ES2015 及之后的所有新特性。

Part 1: 开发环境搭建

在写代码之前，先把工具准备好

木匠开工之前要先备好锯子和锤子，写代码也一样。你需要三样东西：一个编辑器、一个运行环境、一个浏览器。接下来带你从零安装 VS Code 和 Node.js，再学会在浏览器控制台里直接运行代码。工具到手，后面写代码才能畅通无阻。

安装 Node.js

让 JavaScript 脱离浏览器，在你的电脑上直接运行

Node.js 是基于 Chrome V8 引擎的 JavaScript 运行时。有了它，你可以在终端里直接运行 JS 代码，不用打开浏览器。

安装方式（选一种即可）：

  • 官方安装包：从 nodejs.org 下载 LTS 版本
  • nvm：Node Version Manager，可管理多个版本
  • fnm：Rust 编写的快速版本管理器

安装完成后，打开终端验证：

$ node --version
v20.11.0

$ npm --version
10.2.4

如果看到版本号，说明安装成功。

Node.js REPL

一个即写即运行的小 playground

在终端输入 node 回车，就进入了 Node.js 的交互式环境（REPL）。你可以直接输入 JS 代码，按回车立刻看到结果。

$ node
> 2 + 3
5
> "Hello, " + "World"
'Hello, World'
> .exit

常用 REPL 命令

  • .help — 显示帮助
  • .exit — 退出 REPL（或按两次 Ctrl+C）
  • Tab — 自动补全
  • ↑ — 查看上一条输入

所有现代浏览器都内置了开发者工具（DevTools），按 F12 或 Ctrl+Shift+I 打开。

打开后切换到 Console 标签，你可以直接输入 JS 代码并运行：

Part 2: 第一个程序

环境准备好了，现在来写你的第一段 JavaScript 代码

工具装好了，怎么确认它能用？最快的办法就是写一个程序，让计算机说句"你好"。

你会在三种环境里分别跑通同一个程序，搞懂代码放在哪里、怎么运行。

写完之后，你还会学会用注释给代码加"便签"——方便一周后回来看还能看懂。

Hello World

用三种方式让计算机说"你好"

同一段 console.log("Hello, World!")，在浏览器控制台、HTML 文件、Node.js 终端里都能跑通。原因是 JavaScript 有自己的运行时引擎——浏览器里是 V8（Chrome）或 SpiderMonkey（Firefox），Node.js 也用 V8。只要引擎在，它就能读懂并执行 JS 代码。console.log() 是所有 JS 环境都内置的基础功能，所以同一句代码在哪里都能用。

方式一：浏览器控制台 — 打开 DevTools Console，直接输入：

console.log("Hello, World!");

方式二：HTML 文件 — 创建 hello.html，用 <script> 标签把 JS 嵌入网页：

<!DOCTYPE html>
<html lang="zh-CN">
<body>
    <h1>我的第一个 JS 程序</h1>
    <script>
        console.log("Hello, World!");
    </script>
</body>
</html>

方式三：Node.js — 创建 hello.js，终端执行 node hello.js：

// hello.js
console.log("Hello, World!");
$ node hello.js
Hello, World!

三种方式本质一样：都是 JS 引擎读取代码 → 理解含义 → 执行输出。区别只在于代码放在哪里和怎么触发运行。初学阶段用浏览器控制台最方便，后续项目会逐渐用到 Node.js。

代码注释

给未来的自己留一张便条

你写了一段代码，今天完全清楚每一行在干什么。但一周后再打开，可能就不记得了。注释就是写给人类读者的说明文字，计算机执行时会完全忽略它们。

// 单行注释：用双斜线开头，适合简短说明

/*
 多行注释：用斜线和星号包裹
 适合写较长的说明
 */

// 注释的三个最佳实践：
// 1. 解释"为什么"这样做，而不是"做了什么"
// 2. 标记待办：// TODO: 后续优化这个逻辑
// 3. 临时禁用代码（调试时很有用）

// console.log("这行被注释掉了，不会执行");

初学时容易走两个极端：完全不写注释，或者每一行都写注释。好的注释像路标，只在关键的岔路口出现。

script 标签位置

放在哪里，决定了页面加载的体验

浏览器是从上往下逐行读取 HTML 的。如果 <script> 放在页面顶部，浏览器会先停下来加载和执行 JS，用户就会看到一片空白——因为页面还没来得及"画"出来。

位置说明
<head> 中浏览器先执行 JS，页面内容暂时看不到
<body> 底部推荐：页面内容先显示，再执行 JS
defer 属性浏览器边读 HTML 边下载 JS，等页面全部读完再执行
async 属性浏览器边读 HTML 边下载 JS，下载完立刻执行

最佳实践：把 <script> 放在 <body> 底部，或使用 defer 属性。这样用户能更快看到页面内容。

Part 3: 输入与输出

程序的核心是"接收数据 → 处理 → 输出结果"

你的程序能说"你好"了，但它还不会听你说话。

一个真正有用的程序，得能接收用户的数据、处理后再输出结果。

你在浏览器里怎么弹窗让用户输入？在 Node.js 里怎么读取命令行参数？

这一节把两个环境的输入输出方式都讲清楚，后面写练习和项目就用得上。

console 输出

最常用的调试工具，没有之一

console.log("普通日志");
console.warn("警告信息");
console.error("错误信息");

// 格式化输出
console.log("姓名: %s, 年龄: %d", "张三", 25);

// 表格输出——非常适合查看数组和对象
console.table([
    { name: "张三", age: 25 },
    { name: "李四", age: 30 }
]);

// 计时——测量代码执行耗时
console.time("耗时");
for (let i = 0; i < 1000000; i++) {}
console.timeEnd("耗时");

浏览器交互

alert、confirm、prompt——简单但实用

// 弹出提示（阻塞式，必须点确定才继续）
alert("这是一条提示信息");

// 确认对话框，返回 true 或 false
let result = confirm("确定要删除吗？");

// 输入对话框，返回用户输入的字符串，取消则返回 null
let name = prompt("请输入你的名字：", "默认值");
这些方法会阻塞页面。 也就是说，弹出框没关掉之前，用户什么都不能操作。适合调试和小工具，生产环境请用自定义弹窗组件。

Node.js 输入

在终端里把数据传给程序

浏览器有 prompt() 弹窗来获取输入，Node.js 没有界面，所以输入方式不同。最简单的方式是命令行参数——运行程序时直接在后面带上数据：

// greet.js
let name = process.argv[2]; // 取第三个参数
console.log("你好, " + name + "!");
$ node greet.js 张三
你好, 张三!

process.argv 是 Node.js 内置的数组，自动收集命令行上的所有内容。argv[0] 是 node 的路径，argv[1] 是脚本文件的路径，argv[2] 开始才是你传入的参数。后续章节会学到更高级的交互式输入方式。

常见环境问题

不要在有红色波浪线时强行运行代码。 先把报错修好，否则只会越改越乱。

问题一：node --version 提示"命令未找到"

原因：Node.js 没有安装，或安装后没有加入系统 PATH。

修复：重新从 nodejs.org 下载安装包安装；如果已安装，重启终端再试。

问题二：console.log 没有任何输出

原因：可能是文件名写错了，或者代码写在了注释里。

修复：检查文件名是否正确，确认代码没有被 // 或 /* */ 注释掉。

问题三：HTML 文件中的 JS 不执行

原因：<script> 标签写在 <head> 里，且操作的 DOM 元素还没加载。

修复：把 <script> 移到 </body> 之前，或者给 <script> 加上 defer 属性。
