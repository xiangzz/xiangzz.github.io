Part 1: PaaS 部署

推代码即部署，适合快速上线。

部署到 Vercel

两条命令上线你的 Next.js 应用

$ npm install -g vercel
$ vercel login
$ vercel                    # 首次部署（preview）
$ vercel --prod             # 生产部署
// vercel.json（可选配置）
{
  "framework": "nextjs",
  "env": {
    "DATABASE_URL": "@database_url",
    "JWT_SECRET": "@jwt_secret"
  }
}
$ vercel env add DATABASE_URL production
$ vercel env add JWT_SECRET production

部署到 Railway

内置数据库，全栈一站搞定

$ npm install -g @railway/cli
$ railway login
$ railway init
$ railway up                    # 部署

PM2 进程管理

Node.js 的守护神

$ npm install -g pm2
$ pm2 start dist/index.js --name "my-app"
// ecosystem.config.js
module.exports = {
  apps: [{
    name: 'my-app',
    script: 'dist/index.js',
    instances: 'max',           // 按 CPU 核心数启动
    exec_mode: 'cluster',       // 集群模式
    max_memory_restart: '512M', // 内存超限自动重启
    env_production: { NODE_ENV: 'production', PORT: 3000 },
  }],
};
$ pm2 start ecosystem.config.js --env production
$ pm2 list          # 查看进程
$ pm2 logs my-app   # 查看日志
$ pm2 monit         # 实时监控
$ pm2 reload my-app # 零停机重载
$ pm2 startup       # 开机自启
$ pm2 save          # 保存进程列表

Nginx 反向代理

HTTPS、安全头、静态文件一站搞定

# /etc/nginx/sites-available/my-app
upstream nodejs_app {
    server 127.0.0.1:3000;
    keepalive 64;
}

server {
    listen 443 ssl http2;
    server_name myapp.com;

    ssl_certificate /etc/letsencrypt/live/myapp.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/myapp.com/privkey.pem;

    # 安全头
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;

    # API 反向代理
    location /api/ {
        proxy_pass http://nodejs_app;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location / {
        proxy_pass http://nodejs_app;
    }
}

Let's Encrypt 免费 HTTPS

健康检查端点

让监控系统知道你的应用还好不好

// src/routes/health.ts
app.get('/health', async (req, res) => {
  const checks = {
    status: 'ok',
    uptime: process.uptime(),
    checks: {
      database: await checkDatabase(),
      redis: await checkRedis(),
      memory: checkMemory(),
    },
  };
  const isHealthy = Object.values(checks.checks)
    .every(c => c.status === 'ok');
  res.status(isHealthy ? 200 : 503).json(checks);
});

async function checkDatabase() {
  try {
    await prisma.$queryRaw`SELECT 1`;
    return { status: 'ok' };
  } catch (error) {
    return { status: 'error', message: error.message };
  }
}

  });

排错：服务挂了

症状：网站突然无法访问，502 Bad Gateway。
原因：Node.js 进程崩溃（内存溢出、未捕获异常）。
修复：PM2 会自动重启。用 pm2 logs 查看崩溃日志，定位原因。常见问题：内存泄漏（重启频率高）、未处理的 Promise rejection。 
$ pm2 logs my-app --lines 100   # 查看最近日志
$ pm2 show my-app                # 查看重启次数
$ pm2 monit                      # 实时监控内存和 CPU
