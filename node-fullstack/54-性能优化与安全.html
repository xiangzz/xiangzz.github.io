Part 1: 后端性能

缓存策略和数据库索引，数量级的性能提升。

Redis 缓存

不重复计算，直接返回结果

缓存就是把计算结果存起来，下次同样的请求直接返回，不再重复计算。

// 通用缓存包装器
async function cacheable<T>(
  key: string,
  fetcher: () => Promise<T>,
  ttl: number = 300  // 默认5分钟
): Promise<T> {
  const cached = await redis.get(key);
  if (cached) return JSON.parse(cached);

  const data = await fetcher();
  await redis.setex(key, ttl, JSON.stringify(data));
  return data;
}

// 使用
const user = await cacheable(
  `user:${id}`,
  () => prisma.user.findUnique({ where: { id } }),
  600  // 10分钟
);

这个比喻只是为了帮你建立直观感受：缓存像把常用工具放在桌面，而不是每次都去仓库找。实际上缓存涉及失效策略、穿透防护等复杂机制。

缓存失效策略

数据改了，缓存要跟着变

// 写操作后使缓存失效
app.put('/api/users/:id', async (req, res) => {
  const user = await prisma.user.update({
    where: { id: Number(req.params.id) },
    data: req.body,
  });

  // 使相关缓存失效
  await redis.del(`user:${req.params.id}`);
  await redis.del('users:list');

  res.json(user);
});
模式策略适用场景
Cache-Aside先查缓存，miss 时查 DB 回填通用
Write-Through写数据时同时更新缓存一致性要求高
Write-Behind先写缓存，异步写 DB写密集场景

数据库索引

给查询加速的目录

// prisma/schema.prisma
model Post {
  id        Int      @id @default(autoincrement())
  title     String
  slug      String   @unique
  published Boolean  @default(false)
  createdAt DateTime @default(now())
  authorId  Int
  author    User     @relation(fields: [authorId], references: [id])

  @@index([authorId])                // 外键索引
  @@index([published, createdAt])    // 复合索引
}

复合索引有最左前缀原则：索引 [published, createdAt] 能优化 WHERE published = true，但不能优化 WHERE createdAt > '2024-01-01'（跳过了第一列）。

N+1 问题

最常见的数据库性能杀手

// 错误：N+1 查询
const posts = await prisma.post.findMany(); // 1次
for (const post of posts) {
  const author = await prisma.user.findUnique({  // N次！
    where: { id: post.authorId },
  });
}

// 正确：使用 include 预加载
const posts = await prisma.post.findMany({
  include: { author: true },  // 1次 JOIN 搞定
});

// 更好：只查需要的字段
const posts = await prisma.post.findMany({
  select: {
    id: true, title: true,
    author: { select: { id: true, name: true } },
  },
});

Part 3: 安全防御

XSS、CSRF、SQL 注入、依赖审计——四大安全威胁。

XSS 跨站脚本

恶意脚本注入到你的页面中

XSS 是攻击者把恶意 JavaScript 注入到网页中，在其他用户浏览时执行。

// React JSX 自动转义（安全）
const userInput = '<script>alert("xss")</script>';
return <div>{userInput}</div>;  // 自动转义

// 需要渲染 HTML 时使用 DOMPurify
import DOMPurify from 'dompurify';
const clean = DOMPurify.sanitize(dirtyHtml, {
  ALLOWED_TAGS: ['b', 'i', 'a', 'p'],
});

// 配置 CSP 头（Content Security Policy）
import helmet from 'helmet';
app.use(helmet({
  contentSecurityPolicy: {
    directives: {
      defaultSrc: ["'self'"],
      scriptSrc: ["'self'"],
    },
  },
}));

CSRF 跨站伪造

诱导用户在不知情下执行操作

// 防御1：SameSite Cookie（最简单有效）
app.use(session({
  cookie: {
    httpOnly: true,    // JS 无法读取
    secure: true,      // 仅 HTTPS
    sameSite: 'strict', // 不允许跨站发送
  },
}));

// 防御2：验证 Origin 头
function csrfCheck(req, res, next) {
  const origin = req.headers.origin;
  const allowed = ['https://myapp.com'];
  if (req.method !== 'GET' && !allowed.some(o => origin?.startsWith(o))) {
    return res.status(403).json({ error: 'CSRF check failed' });
  }
  next();
}

SQL 注入

Prisma 默认参数化查询，天然免疫

// Prisma 自动参数化（安全）
const user = await prisma.user.findUnique({
  where: { email: userInput },  // 安全
});

// 危险：SQL 字符串拼接（绝对不要这样做！）
// const q = `SELECT * FROM users WHERE email = '${userInput}'`
// userInput = "admin' OR '1'='1" → 返回所有用户！

// 安全：Prisma tagged template 自动参数化
const result = await prisma.$queryRaw`
  SELECT * FROM "User" WHERE email = ${userInput}
`;
永远不要信任用户输入。无论前端做了什么验证，后端都必须重新验证。前端验证只是提升体验，不能替代后端安全检查。

排错：密钥泄露

症状：GitHub 收到安全告警，或发现 .env 文件被提交到了仓库。
原因：忘记把 .env 加入 .gitignore，或代码中硬编码了密钥。
修复：（1）立即轮换泄露的密钥；（2）用 BFG Repo-Cleaner 从 Git 历史中删除；（3）用 git-secrets 或 gitleaks 防止再次泄露。 
# 用 gitleaks 扫描代码中的密钥
$ gitleaks detect --source . --verbose
