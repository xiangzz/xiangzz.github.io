Part 1: 后端性能

缓存策略和数据库索引，数量级的性能提升。

Redis 缓存

不重复计算，直接返回结果

缓存就是把计算结果存起来，下次同样的请求直接返回，不再重复计算。

// 通用缓存包装器
async function cacheable<T>(
  key: string,
  fetcher: () => Promise<T>,
  ttl: number = 300  // 默认5分钟
): Promise<T> {
  const cached = await redis.get(key);
  if (cached) return JSON.parse(cached);

  const data = await fetcher();
  await redis.setex(key, ttl, JSON.stringify(data));
  return data;
}

// 使用
const user = await cacheable(
  `user:${id}`,
  () => prisma.user.findUnique({ where: { id } }),
  600  // 10分钟
);

这个比喻只是为了帮你建立直观感受：缓存像把常用工具放在桌面，而不是每次都去仓库找。实际上缓存涉及失效策略、穿透防护等复杂机制。

缓存失效策略

数据改了，缓存要跟着变

// 写操作后使缓存失效
app.put('/api/users/:id', async (req, res) => {
  const user = await prisma.user.update({
    where: { id: Number(req.params.id) },
    data: req.body,
  });

  // 使相关缓存失效
  await redis.del(`user:${req.params.id}`);
  await redis.del('users:list');

  res.json(user);
});
模式策略适用场景
Cache-Aside先查缓存，miss 时查 DB 回填通用
Write-Through写数据时同时更新缓存一致性要求高
Write-Behind先写缓存，异步写 DB写密集场景

数据库连接池

避免每次请求都重建连接

建立数据库连接是一个昂贵的操作——TCP 握手、TLS 协商、权限校验，单次可能要 50-200ms。连接池在应用启动时预先创建一组连接，请求到来时直接复用。

// Prisma 内置连接池，通过 URL 参数配置
// .env
DATABASE_URL="postgresql://user:pass@localhost:5432/mydb?connection_limit=20&pool_timeout=30"
参数作用建议值
connection_limit最大连接数CPU 核心数 x 2 + 1
pool_timeout获取连接等待时间10-30s

Prisma 默认连接池大小为 num_physical_cpus * 2 + 1。在 Serverless 环境中，由于实例频繁冷启动，建议使用 Prisma Data Proxy 或 PgBouncer 等外部池化方案。

数据库索引

给查询加速的目录

// prisma/schema.prisma
model Post {
  id        Int      @id @default(autoincrement())
  title     String
  slug      String   @unique
  published Boolean  @default(false)
  createdAt DateTime @default(now())
  authorId  Int
  author    User     @relation(fields: [authorId], references: [id])

  @@index([authorId])                // 外键索引
  @@index([published, createdAt])    // 复合索引
}

复合索引有最左前缀原则：索引 [published, createdAt] 能优化 WHERE published = true，但不能优化 WHERE createdAt > '2024-01-01'（跳过了第一列）。

N+1 问题

最常见的数据库性能杀手

// 错误：N+1 查询
const posts = await prisma.post.findMany(); // 1次
for (const post of posts) {
  const author = await prisma.user.findUnique({  // N次！
    where: { id: post.authorId },
  });
}

// 正确：使用 include 预加载
const posts = await prisma.post.findMany({
  include: { author: true },  // 1次 JOIN 搞定
});

// 更好：只查需要的字段
const posts = await prisma.post.findMany({
  select: {
    id: true, title: true,
    author: { select: { id: true, name: true } },
  },
});

压缩与 HTTP 缓存

减小体积 + 避免重复传输

Gzip 或 Brotli 压缩可以将文本资源体积减少 60%-80%。HTTP 缓存让浏览器在资源未变更时直接使用本地副本。

// Express 压缩中间件
import compression from 'compression';

app.use(compression({
  level: 6,               // 压缩级别 1-9
  threshold: 1024,        // 大于 1KB 才压缩
  filter: (req, res) => {
    if (req.headers['x-no-compression']) return false;
    return compression.filter(req, res);
  },
}));
// 静态资源长期缓存（带 hash 文件名）
app.use('/static', express.static('public', {
  maxAge: '1y',            // 缓存 1 年
  immutable: true,         // 文件内容不变
}));

// API 响应短期缓存
app.get('/api/config', (req, res) => {
  res.set('Cache-Control', 'public, max-age=300'); // 5 分钟
  res.json(config);
});

// 资源变更时协商缓存
res.set({
  'ETag': '"33a64df5"',
  'Last-Modified': 'Thu, 01 Jul 2026 00:00:00 GMT',
});
策略响应头适用场景
强缓存Cache-Control: max-age=31536000带 hash 的静态资源
协商缓存ETag / If-None-MatchAPI 响应、HTML
不缓存Cache-Control: no-store敏感数据、实时信息

速率限制深入

滑动窗口 vs 固定窗口，分布式计数

简单的每分钟 100 次限制可能被窗口边界突刺攻击绕过——在两个窗口的交界点各发 100 次，实际 200 次只在 1 秒内完成。

// express-rate-limit：完整配置
import rateLimit from 'express-rate-limit';

// 反向代理（Nginx / ELB / Cloudflare）后必须设置 trust proxy，
// 否则 req.ip 永远是代理回环地址（如 127.0.0.1），限流会退化成"全站共享一个桶"。
// 设为代理层数（通常是 1），不要设为 true（会有 IP 欺骗风险）。
app.set('trust proxy', 1);

const apiLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,    // 15 分钟
  limit: 100,                   // 每个 IP 最大请求数
  standardHeaders: 'draft-7',   // 返回 RateLimit-* 头
  legacyHeaders: false,         // 禁用 X-RateLimit-* 头
  message: { error: '请求过于频繁，请 15 分钟后再试' },
  // 用默认 keyGenerator 即可，它会读取上面 trust proxy 解析后的 req.ip。
  // 不要自己读 req.headers['x-forwarded-for']——该头部可被客户端任意伪造，攻击者能借此绕过限流。
  skip: (req) => req.path === '/health',  // 健康检查不限速
});

app.use('/api/', apiLimiter);
反代场景下最容易踩的两个限流坑：① 没设 trust proxy，导致所有请求的 req.ip 都是 127.0.0.1，限流对全站失效；② 自己读 x-forwarded-for 头当 key，而该头可被任意伪造，攻击者换个 IP 字符串就能绕过限流。正确做法是设置 trust proxy 后用默认 keyGenerator，让 Express 安全地解析真实客户端 IP。
算法优点缺点
固定窗口实现简单，内存少边界突刺问题
滑动窗口平滑限流，无突刺内存稍多，实现复杂
令牌桶允许合理突发流量参数调优复杂
 
// 通过 RateLimit 标准化头返回配额信息
app.get('/api/data', (req, res) => {
  // 响应头：RateLimit-Limit: 100, RateLimit-Remaining: 95
  res.json({ ok: true });
});
// 分布式环境：使用 Redis 存储计数
import { RedisStore } from 'rate-limit-redis';
import { createClient } from 'redis';

const client = createClient({ url: process.env.REDIS_URL });
await client.connect();

const limiter = rateLimit({
  store: new RedisStore({
    sendCommand: (...args: string[]) => client.sendCommand(args),
  }),
  windowMs: 60 * 1000,
  limit: 100,
});

CORS 跨域资源共享

控制哪些来源可以访问你的 API

同源策略是浏览器安全的基础——默认情况下，网页只能请求同协议、同域名、同端口的资源。CORS（跨域资源共享）是允许特定来源访问的机制。

// 基础配置：允许特定来源
import cors from 'cors';

app.use(cors({
  origin: ['https://myapp.com', 'https://admin.myapp.com'],
  methods: ['GET', 'POST', 'PUT', 'DELETE'],
  allowedHeaders: ['Content-Type', 'Authorization'],
  credentials: true,            // 允许携带 Cookie
  maxAge: 86400,                // 预检请求缓存 24 小时
}));
注意：当 credentials: true 时，不能使用 origin: '*'。浏览器会拒绝带通配符 origin + 凭证的组合。必须显式指定允许的来源列表。 
// 动态来源验证（多租户场景）
const allowedDomains = ['.myapp.com', 'localhost:3000'];

app.use(cors({
  origin: (origin, callback) => {
    // 允许无 origin 的请求（如移动端、Postman）
    if (!origin) return callback(null, true);

    const isAllowed = allowedDomains.some(domain =>
      origin === domain || origin.endsWith(domain)
    );

    if (isAllowed) {
      callback(null, true);
    } else {
      callback(new Error('Origin ' + origin + ' not allowed by CORS'));
    }
  },
  credentials: true,
}));

CSP 内容安全策略

告诉浏览器哪些资源可以加载和执行

Content-Security-Policy 响应头是一个深度防御层——即使攻击者成功注入了恶意脚本，CSP 也能阻止其执行。

// 使用 Helmet 配置 CSP
import helmet from 'helmet';

app.use(helmet({
  contentSecurityPolicy: {
    directives: {
      defaultSrc: ["'self'"],           // 默认只允许同源
      scriptSrc: ["'self'", "'nonce-abc123'"],  // 脚本仅同源 + nonce
      styleSrc: ["'self'", "'unsafe-inline'"],  // 样式允许内联
      imgSrc: ["'self'", "data:", "https://cdn.myapp.com"],
      connectSrc: ["'self'"],           // fetch/XHR 仅同源
      fontSrc: ["'self'", "https://fonts.googleapis.com"],
      objectSrc: ["'none'"],            // 禁止 Flash 等插件
      baseUri: ["'self'"],              // 限制 <base> 标签
      formAction: ["'self'"],           // 表单提交仅同源
      frameAncestors: ["'none'"],       // 禁止被 iframe 嵌入
    },
  },
  // 其他安全头也一并启用
  crossOriginEmbedderPolicy: true,
  crossOriginOpenerPolicy: true,
  crossOriginResourcePolicy: { policy: "same-origin" },
}));
// 对应生成的 HTTP 响应头
// Content-Security-Policy: default-src 'self';
//   script-src 'self' 'nonce-abc123';
//   style-src 'self' 'unsafe-inline';
//   img-src 'self' data: https://cdn.myapp.com;
//   connect-src 'self';
//   font-src 'self' https://fonts.googleapis.com;
//   object-src 'none';
//   base-uri 'self';
//   form-action 'self';
//   frame-ancestors 'none'

CSRF 跨站伪造

诱导用户在不知情下执行操作

// 防御1：SameSite Cookie（最简单有效）
app.use(session({
  cookie: {
    httpOnly: true,    // JS 无法读取
    secure: true,      // 仅 HTTPS
    sameSite: 'strict', // 不允许跨站发送
  },
}));

// 防御2：验证 Origin 头
function csrfCheck(req, res, next) {
  const origin = req.headers.origin;
  const allowed = ['https://myapp.com'];
  if (req.method !== 'GET' && !allowed.some(o => origin?.startsWith(o))) {
    return res.status(403).json({ error: 'CSRF check failed' });
  }
  next();
}

SQL 注入

Prisma 默认参数化查询，天然免疫

// Prisma 自动参数化（安全）
const user = await prisma.user.findUnique({
  where: { email: userInput },  // 安全
});

// 危险：SQL 字符串拼接（绝对不要这样做！）
// const q = `SELECT * FROM users WHERE email = '${userInput}'`
// userInput = "admin' OR '1'='1" → 返回所有用户！

// 安全：Prisma tagged template 自动参数化
const result = await prisma.$queryRaw`
  SELECT * FROM "User" WHERE email = ${userInput}
`;
永远不要信任用户输入。无论前端做了什么验证，后端都必须重新验证。前端验证只是提升体验，不能替代后端安全检查。

      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npm audit --audit-level=high
        continue-on-error: false

Dependabot 配置（.github/dependabot.yml）可以指定哪些依赖需要自动更新、review 人等。对于关键安全依赖，建议设置自动合并低风险升级。

密钥管理最佳实践

环境隔离 + 最小权限 + 定期轮换

密钥管理不是"存到 .env 就完了"。生产环境需要集中式管理，审批流程，以及泄漏后的快速响应能力。

// 1. 环境分离 —— 开发 / 测试 / 生产各自独立密钥
// .env.development
DATABASE_URL=postgresql://localhost/devdb
JWT_SECRET=dev-only-not-secret

// .env.production（由部署平台注入，不入库）
DATABASE_URL=postgresql://prod-db.internal:5432/app
JWT_SECRET=（32+ 字节强随机值）
存储方案适用场景安全等级
.env + .gitignore本地开发基础
GitHub SecretsCI/CD 流水线良好
云 KMS (AWS/GCP)中大型应用优秀
HashiCorp Vault企业级最高
绝对禁止：
• 在任何 Git 仓库中提交 .env 文件
• 在代码中硬编码 API Key 或密码
• 前端代码中存放后端密钥
• 多人共享同一个生产密钥
• 密钥从不轮换（超过 90 天）

密钥轮换流程（双密钥过渡法）

# 1. 生成新密钥
NEW_SECRET=$(openssl rand -hex 32)

# 2. 服务端双密钥并行验证（过渡期 7 天）
# 3. 7 天后下线旧密钥

# 4. 客户端迁移到新密钥
echo "密钥轮换完成"
阶段操作验证
准备生成新密钥，通知团队本地测试
过渡期双密钥并行验证监控错误日志
收尾下线旧密钥全量回归测试

排错：密钥泄露

症状：GitHub 收到安全告警，或发现 .env 文件被提交到了仓库。
原因：忘记把 .env 加入 .gitignore，或代码中硬编码了密钥。
修复：（1）立即轮换泄露的密钥；（2）用 BFG Repo-Cleaner 从 Git 历史中删除；（3）用 git-secrets 或 gitleaks 防止再次泄露。

练习三：CORS 修复

解决本地前后端分离的跨域障碍

场景：前端运行在 http://localhost:5173，后端 API 在 http://localhost:3000。前端调用 fetch('http://localhost:3000/api/data') 被浏览器拦截，控制台报 Access-Control-Allow-Origin 错误。

任务：在后端 Express 中添加 CORS 中间件，使前端可以跨域请求，同时允许携带 Cookie。

参考答案

import cors from 'cors';

app.use(cors({
  origin: 'http://localhost:5173',  // 明确指定前端来源
  credentials: true,                // 允许 Cookie
  methods: ['GET', 'POST', 'PUT', 'DELETE'],
}));

练习四：Helmet 安全头配置

CSP / HSTS / X-Content-Type-Options

任务：使用 Helmet 中间件一次性启用多个安全头。要求：
① CSP 仅允许同源脚本和样式
② HSTS 强制 HTTPS（max-age 至少 30 天）
③ 禁用 MIME 类型嗅探（X-Content-Type-Options: nosniff）

参考答案

import helmet from 'helmet';

app.use(helmet());  // 自动启用 X-Content-Type-Options: nosniff 等

// 手动追加 HSTS（Helmet 默认不开启严格 HSTS）
app.use(helmet.hsts({
  maxAge: 2592000,        // 30 天（单位：秒）
  includeSubDomains: true,
  preload: true,
}));

// CSP 配置（需手动启用）
app.use(helmet.contentSecurityPolicy({
  directives: {
    defaultSrc: ["'self'"],
    scriptSrc: ["'self'"],
    styleSrc: ["'self'", "'unsafe-inline'"],
    imgSrc: ["'self'", "data:"],
  },
}));
