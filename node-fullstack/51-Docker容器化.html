Docker 容器化

告别"在我机器上能跑"的环境噩梦

你有没有想过

为什么代码在本地跑得好好的，部署到服务器就报错？为什么新同事配环境要花一整天？

这些都是环境不一致导致的：Node 版本不同、数据库没装、环境变量没配。

Docker 把应用和它的所有依赖打包成一个容器，确保在任何环境都能一致运行。开发、测试、生产，一个镜像走天下。

核心概念

七个 Docker 关键词

镜像 Image

只读的应用模板。类似安装光盘。

容器 Container

镜像的运行实例。类似运行中的程序。

Dockerfile

构建镜像的指令文件。类似构建脚本。

Registry

镜像仓库。类似 npm registry。

Volume

持久化数据存储。类似外接硬盘。

Network

容器间通信网络。类似局域网。

Compose

多容器编排工具。管理一组容器。

Docker vs 虚拟机

轻量级的进程隔离

特性Docker 容器虚拟机
启动速度秒级分钟级
资源占用MB 级别GB 级别
性能接近原生有虚拟化开销
镜像大小几十到几百 MB通常几 GB
单机密度数百个几个到几十个

这个比喻只是为了帮你建立直观感受：虚拟机像整栋别墅，容器像合租公寓的一个房间。实际上容器共享宿主内核，只是进程级别的隔离。

常用命令

日常开发最常用的 Docker 命令

# 镜像管理
$ docker pull node:20-alpine        # 拉取镜像
$ docker images                      # 列出本地镜像
$ docker build -t my-app:latest .    # 构建镜像

# 容器管理
$ docker run -d -p 3000:3000 --name my-app my-app:latest
$ docker ps                          # 查看运行中容器
$ docker logs -f my-app              # 实时查看日志
$ docker exec -it my-app sh          # 进入容器终端

# 清理
$ docker system prune                # 清理未使用资源
$ docker volume prune                # 清理未使用卷

Part 1: Dockerfile

用多阶段构建打造精简的生产镜像。

多阶段构建

构建和运行分离，镜像体积缩小 80%

# 第一阶段：构建
FROM node:20-alpine AS builder
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build

# 第二阶段：运行
FROM node:20-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production

# 创建非 root 用户
RUN addgroup --system --gid 1001 nodejs && \
    adduser --system --uid 1001 appuser

# 只复制构建产物
COPY --from=builder --chown=appuser:nodejs /app/dist ./dist
COPY --from=builder --chown=appuser:nodejs /app/node_modules ./node_modules
COPY --from=builder --chown=appuser:nodejs /app/package.json ./

USER appuser
EXPOSE 3000
HEALTHCHECK --interval=30s --timeout=3s \
  CMD wget --no-verbose --tries=1 --spider http://localhost:3000/health || exit 1

CMD ["node", "dist/index.js"]

构建效果对比

多阶段构建的收益一目了然

方式镜像大小包含内容安全性
单阶段无优化~1.2 GB源码 + devDeps + 工具低
多阶段构建~180 MB编译产物 + prod 依赖高
多阶段 + standalone~80 MB仅运行时文件最高
永远不要在镜像中硬编码密钥。使用 -e 参数或 Docker Secrets 传递敏感配置。确保 .env 在 .dockerignore 中。

Part 2: Compose 编排

一个命令启动 Node + PostgreSQL + Redis 全套环境。

Compose 编排

三个服务，一个文件搞定

graph LR
    subgraph Docker Compose
        N[Nginx :80] --> A[Node.js App :3000]
        A --> DB[(PostgreSQL :5432)]
        A --> R[(Redis :6379)]
    end
    U[用户] --> N
                
# docker-compose.yml
services:
  app:
    build: .
    ports: ["3000:3000"]
    environment:
      - DATABASE_URL=postgresql://postgres:secret@db:5432/myapp
      - REDIS_URL=redis://redis:6379
    depends_on:
      db: { condition: service_healthy }
    restart: unless-stopped

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: myapp
      POSTGRES_PASSWORD: secret
    volumes: [postgres-data:/var/lib/postgresql/data]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]

  redis:
    image: redis:7-alpine
    volumes: [redis-data:/data]

volumes:
  postgres-data:
  redis-data:

开发环境覆盖

同一个项目，不同环境不同配置

# docker-compose.override.yml（开发自动加载）
services:
  app:
    command: npm run dev
    volumes:
      - .:/app               # 挂载源码（热重载）
      - /app/node_modules    # 不覆盖容器依赖
    environment:
      - NODE_ENV=development
    ports:
      - "3000:3000"
      - "9229:9229"          # 调试端口
$ docker compose up -d              # 启动所有服务
$ docker compose logs -f app        # 查看 app 日志
$ docker compose exec db psql -U postgres -d myapp
$ docker compose down               # 停止所有服务

排错：容器问题

症状：容器启动后立刻退出，docker ps 看不到。
原因：应用启动报错（如连不上数据库），进程退出导致容器停止。
修复：用 docker logs my-app 查看退出日志；确保 depends_on 配了 condition: service_healthy。 
# 查看退出容器的日志
$ docker ps -a                     # 看所有容器（含已停止的）
$ docker logs my-app               # 查看崩溃原因
$ docker compose logs app          # Compose 方式查看
