命令 vs 工具

这是理解 Qoder CLI 的一个关键区分

斜杠命令（确定性功能）

你输入 /status，CLI 程序直接执行一个固定动作——查状态、显示结果。没有 AI 介入，结果确定。

像点菜单：点"查看状态"就上"查看状态"。

/clear    清空会话
/usage    看 Credits
/quit     退出

内置工具（AI 调用的能力）

Read、Write、Bash 这些是AI 在干活时调用的能力。你说"读一下 app.ts"，AI 决定调用 Read 工具。

像厨房的炊具：AI 是厨师，工具是它手里的刀和锅。

Read    读文件
Write   写文件
Grep    搜内容
Bash    跑命令
一句话总结：命令是你对 CLI 下的指令，工具是AI执行任务时用的手段。两者配合——你用命令管会话，AI 用工具干活。

会话管理

控制对话历史的四个命令，每天都用

命令作用什么时候用
/clear 清空当前会话历史 切换到完全不同的任务，不想旧上下文干扰
/compact 总结压缩历史 对话太长要爆上下文，但还想保留要点
/resume 查看并恢复历史会话 回到昨天没干完的那个任务继续
/tasks 查看后台运行的任务 有耗时任务在跑，想看进度
新手最该养成习惯的：每完成一个大任务后，用 /clear 清空——避免上一个任务的上下文"污染"下一个任务的判断。这是保持 AI 专注的简单技巧。

账号与状态

查自己、查 CLI 的四个命令

/status — CLI 体检

显示版本、当前模型、账号、API 连通性、工具状态。出问题时第一个该敲的命令，帮你定位是网络、账号还是配置的问题。

/usage — 用量查看

显示当前 Credits 消耗情况。任务跑得久或多时，定期看看有没有超额风险。

/config — 系统配置

查看 CLI 当前的系统配置，包括权限模式、自动升级等设置项。

/login / /logout

登录与登出账号。已在第 02 章详细讲过。

四件套工具

AI 干活时最常用的四个内置工具

Qoder CLI 内置了 Grep、Read、Write、Bash 等工具，无需任何配置即可使用。它们是 AI 操作文件和执行命令的基础。

Grep — 搜索内容

在项目里搜索代码、文本、配置。AI 用它定位相关文件。

你说"找到所有调用 login 的地方"，AI 就调 Grep。

Read — 读取文件

读取源代码、文档、配置。大文件只读相关片段，省 token。

AI 看代码靠它，理解项目靠它。

Write — 写文件

创建新文件或修改已有文件。每次写入会经过权限检查。

AI 改代码靠它，但需你批准（默认模式）。

Bash — 执行命令

运行构建、测试、Git 等任何 shell 命令。风险最高，权限最严。

AI 跑测试、跑构建靠它。

控制工具

你可以限制 AI 能用哪些工具——这是安全的关键

工具"可见"和"允许执行"是两件事。启动时用参数控制：

参数作用
--tools限制本次会话可见的工具（白名单）
--allowed-tools预先允许指定工具，免确认
--disallowed-tools禁止指定工具
 
# 只读探索：AI 只能看，不能改
qodercli --tools Read Grep Glob --allowed-tools 'Read,Grep,Glob'

# 允许安全的状态检查命令免确认
qodercli --allowed-tools 'Read,Grep,Bash(git status)'

# 非交互式审查时禁止任何文件编辑
qodercli -p "review this repo" --disallowed-tools 'Write,Edit'
这是只读会话的标准写法：--tools Read Grep Glob 让 AI 只能用看和搜的工具，物理上无法修改文件。排查问题、做代码审查时特别有用。权限系统的完整内容见第 11 章。

启动参数

启动 CLI 时常用的几个一次性参数

参数说明示例
-w指定工作区目录qodercli -w /Users/demo/projects/nacos
-c继续上次会话qodercli -c
-r恢复指定会话qodercli -r xxx-c09a-40a9-...
--max-turns最大对话轮数qodercli --max-turns=10
--yolo跳过权限检查（危险）qodercli --yolo
--yolo 的警告：它等同于跳过所有权限确认，AI 改文件、跑命令都不问你。只在完全可信的沙盒环境用，比如一次性实验。生产项目千万别用——这是"事故制造机"。--yolo 等价于 --permission-mode bypass_permissions，详见第 11 章。

排错指南

命令和工具使用中的高频问题

斜杠命令报 not found

原因：命令名拼错，或版本太旧不支持。修复：输入 / 看补全列表；用 /status 查版本，必要时 qodercli update。

AI 说"我没有这个工具"

原因：启动时用 --tools 限制了可见工具，或该工具需要 MCP 配置（如浏览器工具）。修复：用 /tools 看可用清单；确认启动参数没有限制。

改文件时总弹确认，很烦

原因：默认权限模式对写入要确认。修复：用 accept_edits 模式（第 11 章），或 --allowed-tools 'Edit' 预先允许。

会话越聊越慢/越乱

原因：上下文堆积太多。修复：用 /compact 压缩，或 /clear 清空重来。

动手练习

把本章学的命令和工具都摸一遍

练习 1：体检与用量

  • 运行 /status，记录版本、模型、连通状态
  • 运行 /usage，看看 Credits 消耗

练习 2：体验 review

  • 在项目里改两个文件（加注释、改函数名都行）
  • 运行 /review，看 AI 怎么评审你的改动

练习 3：只读会话

  • 用 qodercli --tools Read Grep Glob 启动
  • 让 AI 试着改文件，观察它如何回应（应表示无法修改）
  • 体会"限制可见工具"的安全意义
