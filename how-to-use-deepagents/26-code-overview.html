Deep Agents Code 总览

基于 Deep Agents SDK 构建的终端编码 Agent

从"手动写代码"到"AI 自主编程"的生产力飞跃

编码工具链短

你有没有试过让 AI 帮你写代码，却发现工具链不够用？

普通 AI 编码助手

  • 只能生成代码片段，不能读取和编辑项目文件
  • 无法运行测试或构建命令，没有执行能力
  • 对话一长就忘记之前说的，没有持久记忆
  • 复杂任务无法拆分，一个 Agent 搞定所有
  • 想换个模型？重启重来，不能中途切换

Deep Agents Code 的解法

  • 内置 read_file、write_file、edit_file，直接操作项目文件
  • 内置 execute 工具，运行测试、构建、部署一条龙
  • 跨会话持久记忆 + 技能系统，越用越聪明
  • 内置 task 工具生成子 Agent，并行处理复杂任务
  • 对话中随时 /model 切换，一个会话用多个模型
问题核心：当你的编码需求从"问一段代码"升级到"帮我完成一整个功能模块"时，你需要一个拥有完整工具链的自主编码 Agent。它能读文件、写文件、跑测试、查文档、管理依赖。Deep Agents Code 就是这样的 Agent。

什么是 dcode

一个兼容任何 LLM、拥有持久记忆、可切换模型的终端编码 Agent

Deep Agents Code（dcode）是一个基于 Deep Agents SDK 构建的开源编码 Agent。它的核心特性是：

兼容任意 LLM

只要支持 tool calling，就能用。OpenAI、Anthropic、Google 默认内置，Ollama、Groq、xAI 等可选安装。

跨会话持久记忆

保留对话中学到的内容，下次启动时仍然记得你的项目约定和偏好。

可自定义技能

通过 Skills 系统扩展 Agent 能力——添加专业知识、工作流指令或自定义行为。

审批控制

敏感操作（写文件、执行命令）默认需要人工确认，安全可控。

# 脚本安装（推荐）
curl -LsSf https://langch.in/dcode | bash

# 或使用 uv 安装
uv tool install 'deepagents-code'

# 启动
dcode
可选附加组件：如果需要额外提供商（如 Fireworks、Nvidia），安装时指定： DEEPAGENTS_CODE_EXTRAS="fireworks,nvidia" curl -LsSf https://langch.in/dcode | bash 或 uv tool install 'deepagents-code[fireworks,nvidia]'

内置工具

dcode 附带的完整工具集——无需配置即可使用

工具描述审批要求
ls 列出文件和目录 不需要
read_file 读取文件内容（特定模型支持多模态） 不需要
write_file 创建或覆盖文件 必需
edit_file 对现有文件进行针对性编辑 必需
glob 查找匹配模式的文件 不需要
grep 跨文件搜索文本模式 不需要
execute 在本地或远程沙箱中执行 shell 命令 必需
web_search 使用 Tavily 搜索网络 必需
fetch_url 获取网页并转换为 markdown 必需
task 将工作委派给子 Agent 并行执行 必需
ask_user 向用户提出开放式或多选问题 不需要
compact_conversation 总结较早消息，将原始内容卸载到存储，在上下文中替换为摘要 混合
write_todos 创建和管理任务列表 不需要
跳过人工审批：使用 dcode -y 或 dcode --auto-approve 自动审批所有工具调用。交互模式中可用 Shift+Tab 切换。

上下文压缩

长对话自动压缩，上下文窗口永不溢出

dcode 内置 compact_conversation 机制，当 token 使用量超过阈值时自动触发：

压缩前

  • 对话越来越长，token 开销持续增长
  • 早期对话的完整内容占据大量上下文空间
  • 最终可能触及模型上下文窗口上限

压缩后

  • 较早的消息被 LLM 自动摘要
  • 原始内容卸载到 /conversation_history/{thread_id}.md
  • 上下文中替换为摘要占位符，释放窗口空间
  • Agent 仍可从卸载文件中检索完整历史
# 手动触发上下文压缩（在交互模式中）
> /offload     # 别名：/compact，将较早消息总结并卸载

# 或让 Agent 在 token 使用量超过阈值时自动触发 compact_conversation 工具
# 压缩流程：LLM 总结较早消息 → 原始内容写入文件 → 上下文中替换为摘要
# 这样即使对话很长，Agent 仍有足够的上下文窗口处理当前任务
核心机制：压缩过程通过 LLM 总结较早消息，将原始内容弹出至存储。这确保了长时间会话中 Agent 始终有足够的上下文窗口来处理当前任务。

命令行选项

dcode 提供丰富的命令行参数——从模型选择到沙箱配置

选项说明
-a NAME使用具名 Agent 及其独立记忆
-M MODEL使用特定模型（provider:model）
--model-params JSON传递给模型的额外参数（如 '{"temperature": 0.7}'）
--default-model [MODEL]设置默认模型
--clear-default-model清除默认模型
-r [ID]恢复会话（不传 ID 恢复最近）
-m TEXT启动时自动提交的初始提示
--skill NAME启动时调用技能
--startup-cmd CMD第一个提示之前运行的 shell 命令
-y自动审批所有工具调用（禁用人在回路）
-q / --quiet干净输出，仅输出 Agent 响应（适合管道）
--no-stream缓冲完整响应后一次性输出（非流式）
--stdin显式从 stdin 读取输入
选项说明
-n TEXT非交互模式，运行后退出
-S LISTShell 命令白名单（逗号分隔 / recommended / all）
--max-turns N限制 Agent 轮次（超出以代码 124 退出）
--sandbox TYPE远程沙箱类型
--sandbox-id ID复用现有沙箱
--sandbox-setup PATH沙箱创建后运行的设置脚本路径
--mcp-config PATH添加 MCP 配置（最高优先级）
--no-mcp禁用所有 MCP 工具加载
--trust-project-mcp信任项目级 MCP 配置（跳过审批）
--profile-override JSON覆盖模型配置文件字段
--acp作为 ACP 服务器通过 stdio 运行
--json管理子命令输出机器可读 JSON
-v / --version显示版本号
-h / --help显示帮助
 
# 常见用法
dcode --agent mybot                    # 使用特定 Agent
dcode --model anthropic:claude-opus-4-7  # 使用特定模型
dcode -y                               # 自动审批
dcode --startup-cmd "ls -la" -m "Summarize"  # 启动时先运行命令
dcode --startup-cmd "git diff --stat" -n "Review these changes"  # 非交互

配置结构

所有配置统一存储在 ~/.deepagents/ 目录下

路径用途
~/.deepagents/config.toml 模型和 Agent 默认设置、提供商配置、主题、更新设置

非交互模式

CI/CD 管道中的编码 Agent——单次运行，自动退出

交互模式

  • 启动 UI，持续对话
  • 人工审批敏感操作
  • 随时切换模型、Agent
  • 适合日常开发

非交互模式

  • -n 运行单个任务后退出
  • Shell 执行默认禁用
  • 使用 -S 白名单启用命令
  • 适合 CI/CD、脚本、自动化
# 基本非交互用法：-n 指定任务，运行完自动退出
dcode -n "Write a Python script that prints hello world"

# 管道输入：stdin 内容自动注入为上下文（自动进入非交互模式）
echo "Explain this code" | dcode
git diff | dcode -n "Review these changes"       # 让 Agent 审查代码差异
cat error.log | dcode -n "What's causing this error?"  # 分析错误日志

# 限制轮次防止 Agent 陷入无限循环（CI/CD 中强烈推荐）
dcode -n "fix the failing tests" --max-turns 10

# 干净输出 + 缓冲模式（适合管道处理和脚本集成）
dcode -n "Generate a .gitignore" -q > .gitignore        # -q 仅输出结果
dcode -n "List dependencies" -q --no-stream | sort       # --no-stream 等完整响应后输出
管道输入限制：最大大小为 10 MiB。非交互模式下 Agent 被指示自主推进而非提出澄清问题，倾向使用非交互式命令变体（如 npm init -y）。

Shell 白名单

在非交互模式中精确控制 Agent 能执行哪些命令

指定命令列表

只允许特定命令，按列表严格验证。

dcode -n "Run tests" -S "pytest,git,make"

推荐安全列表

使用 recommended 获取策划的安全命令集合。

dcode -n "Build project" -S recommended

允许所有命令

all 允许任意 shell 命令——请谨慎使用。

dcode -n "Fix the build" -S all
安全警告：-S all 允许 Agent 在无需人工确认的情况下执行任意 shell 命令。仅在你完全信任任务和环境的场景下使用。
环境变量方式：你也可以通过 DEEPAGENTS_CODE_SHELL_ALLOW_LIST 环境变量设置白名单，适合在 CI/CD 中统一配置。

LangSmith 追踪

启用追踪后在 LangSmith 中查看 Agent 的每一步操作和决策

# 方式一：写入 .env 文件（推荐，每次会话自动启用）
cat >> ~/.deepagents/.env << 'EOF'
LANGSMITH_TRACING=true                    # 开启追踪
LANGSMITH_API_KEY=lsv2_...               # LangSmith API 密钥
LANGSMITH_PROJECT=optional-project-name  # 项目名称，默认 "deepagents-code"
EOF

# 方式二：shell 环境变量（适合临时覆盖或 CI/CD）
export LANGSMITH_TRACING=false

# 配置后，dcode 启动时会显示追踪状态
# ✓ LangSmith tracing: 'my-project'

项目级覆盖

在项目目录的 .env 文件中设置相同变量，可覆盖全局设置。Shell 导出始终优先于 .env 值。

分离追踪

使用 DEEPAGENTS_CODE_LANGSMITH_PROJECT 将 dcode 追踪发送到专用项目，与应用追踪分离。也可用 DEEPAGENTS_CODE_ 前缀限定所有凭证。

# 将 dcode 的追踪发送到专用项目（与父应用追踪分离）
DEEPAGENTS_CODE_LANGSMITH_PROJECT=my-deep-agent-execution

# 父应用的追踪使用独立项目
LANGSMITH_PROJECT=my-app-traces

# 也可用 DEEPAGENTS_CODE_ 前缀限定凭证，避免与父应用凭证冲突
DEEPAGENTS_CODE_LANGSMITH_API_KEY=lsv2_...
典型场景：当你在 LangChain 应用中以编程方式调用 dcode（如非交互模式子进程）时，应用和 dcode 都会产生追踪。通过 DEEPAGENTS_CODE_LANGSMITH_PROJECT 将 Agent 追踪路由到独立项目，既保持应用级可观测性整洁，又能捕获 Agent 内部执行细节。
快速查看追踪：使用 /trace 命令在浏览器中打开当前线程的追踪。dcode 启动后会显示指向 LangSmith 项目的链接，支持的终端可直接点击。
