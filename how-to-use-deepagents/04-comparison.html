第 04 章

与 Claude Agent SDK 的对比

深入比较 LangChain Deep Agents 与 Claude Agent SDK 的架构差异

为你的用例选择合适的 Agent 框架

为什么要对比

两个框架都能构建自定义 Agent，但设计哲学截然不同

当你决定用框架构建生产级 Agent 时，Deep Agents 和 Claude Agent SDK 都在候选列表上。它们各自做了不同的权衡——理解这些差异，才能选对工具。

Claude Agent SDK

  • Agent 在沙箱内部运行，操作本地文件系统
  • 模型锁定在 Claude 生态（Anthropic / Bedrock / Vertex）
  • 自托管：需要自行构建服务器、认证和流式传输层
  • 多租户需自行实现 API 封装和沙箱管理

Deep Agents

  • Agent 可在沙箱内或外运行，两种模式都支持
  • 支持 100+ 家模型提供商，按需切换
  • 托管或自托管一键切换，无需改代码
  • 内置多租户：作用域线程、按用户沙箱、RBAC
核心问题：两者都是构建自定义 Agent 的 harness（框架），但在执行环境、部署方式和供应商耦合上做出了不同的权衡。没有"更好"的框架，只有"更适合你场景"的框架。

核心对比

六大维度一览：从运行位置到许可证

生产验证：Deep Agents 已被 OpenSWE 和 LangSmith Fleet 用于生产环境。Claude Agent SDK 的托管模型（Claude managed agents）是一个独立的产品。

执行环境

Agent 连接沙箱有两种模式，Deep Agents 两种都支持

Agent 与沙箱的连接方式决定了你的部署灵活性和扩展上限。理解这两种模式是做出正确选择的关键。

模式一：Agent 在沙箱内

Agent 直接运行在沙箱容器里，操作沙箱的本地文件系统。

  • 架构简单，Agent 与文件系统零延迟
  • Claude Agent SDK 仅支持此模式
  • 每个 Agent 需要独占一个沙箱容器

模式二：Agent 在沙箱外

Agent 运行在长期容器中，将远程沙箱作为工具使用。

  • Agent 可以同时管理多个沙箱
  • 通过网络执行命令，灵活性更高
  • Deep Agents 两种模式都支持
// Deep Agents：通过 backend 配置选择执行模式
import { createHarness } from "@langchain/deepagents";

const harness = createHarness({
  // 本地虚拟文件系统（测试用）—— 文件仅存在于内存中
  // backend: "local",

  // 远程沙箱（生产用）—— Agent 在隔离容器中执行代码
  backend: "remote",

  // 自定义后端（自有基础设施）—— 实现自己的存储和执行逻辑
  // backend: customBackend,
});
实际意义：在测试时切换虚拟文件系统，在生产时用远程沙箱，在自有基础设施上用自定义后端——同一个 Agent 代码，三种执行环境。

多租户设计

当你的应用需要服务多个终端用户时，环境隔离是硬需求

把 Agent 投入生产，几乎必然要面对多用户隔离。两个框架在这方面的差距很大。

Claude Agent SDK：需自行构建

SDK 将 Agent 绑定到其沙箱。要实现多租户，你必须：

  • 编写 API 封装层，为每个用户启动沙箱
  • 自行跟踪每个沙箱的归属关系
  • 在使用后销毁沙箱回收资源
  • 自行实现认证和权限控制

工作量大

Deep Agents：内置支持

框架直接处理了这些问题：

  • 按用户或按助手自动配置沙箱
  • 内置作用域线程和运行历史
  • 内置 RBAC 团队访问控制
  • LangSmith Sandbox 提供认证代理，用户可直接调第三方 API

开箱即用

容易忽视的点：Claude Agent SDK 的认证代理意味着你需要为每个用户单独配置第三方 API 凭证。而 Deep Agents + LangSmith Sandbox 让终端用户直接在沙箱中调用第三方 API，你不需要替用户管凭证。

生产级服务

从"能跑的 Agent"到"能对外提供服务的 Agent 服务器"

写好 Agent 只是第一步。要把它暴露给终端用户，你需要一个完整的服务器基础设施。

Claude Agent SDK：自己造轮子

你需要自己编写并运维：

  • HTTP / WebSocket / SSE 服务器
  • Agent 调用和 token 流式传输
  • 对话线程管理
  • 认证和安全加固

全部由你构建、运维和安全加固。

Deep Agents：开箱即用

部署自带完整的 Agent 服务器：

  • 流式传输端点（SSE / streaming）
  • 线程管理和运行历史
  • Webhook 通知
  • 内置认证（LangSmith Auth）

从开发到生产，零额外工作。

// Deep Agents：部署即包含完整 Agent 服务器
// 流式传输、线程管理、认证——全部开箱即用

// 自托管：一行命令生成独立 Docker 镜像
// $ langgraph build

// 托管模式：在 LangSmith 中一键创建
// 无需修改任何 Agent 代码
省下的不只是时间：自己构建服务器意味着你要持续维护它——处理连接中断、流式重连、线程清理、安全补丁。这些是"看不见"但持续消耗工程资源的部分。

部署方式

托管还是自托管？Deep Agents 无需改代码即可切换

部署方式直接影响你的运维成本和上线速度。两个框架在这方面差异显著。

Deep Agents：双模部署

托管模式：在 LangSmith 中使用 Managed Deep Agents，创建、运行和管理——零运维。

自托管模式：运行 langgraph build 生成独立 Docker 镜像，部署到任何地方。

两种模式共享同一份 Agent 代码，随时可以切换。

灵活切换

Claude Agent SDK：仅自托管

SDK 和 Claude managed agents 是独立的产品。

针对 SDK 编写的代码不能直接部署到托管服务上。

你需要自行搭建基础设施：服务器、容器编排、负载均衡、监控。

自行运维

扩展选择：如果你需要一个跨任意模型提供商的托管 Agent 平台，可以使用 LangSmith Fleet。Claude managed agents 仅限于 Anthropic 生态系统。

模型与生态

模型选择自由度 vs 深度集成优化——不同的设计哲学

Claude Agent SDK：深度捆绑

模型、后端和部署三者捆绑在一起，优化三者之间的协同支持。

  • 专为 Claude 模型优化
  • 绑定 Anthropic 产品体系
  • 深度集成意味着更好的开箱体验
  • 但切换模型 = 切换框架

Deep Agents：按需组合

模型提供商、执行后端和部署目标三者独立选择。

  • 支持 100+ 家模型提供商
  • 通过 profiles 按提供商调优提示词和工具
  • 与 LangChain 生态深度集成（LangSmith 可观测性、评估、部署）
  • 切换模型不改架构，只改配置
// Deep Agents：通过 profiles 按提供商调优
// 不同模型可以有不同的系统提示词、工具集和中间件
// 这样切换模型时，Agent 代码不需要任何改动

// profile 配置示例（概念性代码）
{
  profiles: {
    "anthropic/claude-4": {
      systemPrompt: "...",         // 针对 Claude 优化的提示词
      tools: [...],                // Claude 可用的工具集
      middleware: [...]            // Claude 专用的中间件（如提示缓存）
    },
    "openai/gpt-5": {
      systemPrompt: "...",         // 针对 GPT 优化的提示词
      tools: [...],                // GPT 可用的工具集
    }
  }
}
选哪个：如果你已经深入 Anthropic 生态且不打算换模型，Claude Agent SDK 的深度集成可能更顺手。如果你需要模型灵活性、或团队使用多个模型提供商，Deep Agents 保留了最大的选择空间。

如何选择

没有"更好"的框架，只有"更适合你场景"的框架

选 Deep Agents，如果你需要：

  • 模型灵活性——支持 100+ 家提供商，随时切换
  • 内置多租户——作用域线程、按用户沙箱、RBAC 开箱即用
  • 双模部署——托管和自托管无需改代码即可切换
  • 生产级 Agent 服务器——流式传输、线程管理、认证全包含
  • 多后端支持——沙箱内/外两种执行模式
  • LangChain 生态——LangSmith 可观测性、评估、部署一体化

选 Claude Agent SDK，如果你：

  • 已经深入使用 Anthropic 生态系统
  • 不需要多模型支持，Claude 够用
  • 愿意自行构建 API 层、认证和多租户
  • 偏好深度集成的开箱体验
  • 团队有足够资源自行运维基础设施
决策关键：问自己三个问题——你需要多模型吗？你需要多租户吗？你想自己管基础设施吗？如果前两个答案是"是"、第三个是"否"，Deep Agents 更适合你。如果你只在 Anthropic 生态内运作且愿意自建基础设施，Claude Agent SDK 也能胜任。
文档时效：本文基于 2026 年 4 月 16 日的对比。产品可能已有更新，建议同时查阅两个框架的最新文档。
