真相：问题不在 AI 不够聪明，而是你没有提供足够清晰的指引。一句话包含不了你的全部期望。

语义鸿沟

当你说"现代简约"时，AI 可能想到 Apple 的极简黑白，也可能是 Medium 的宽松排版——同一个词，100 种理解

你可能想说的

"现代简约" =
  浅灰蓝背景
  深灰文字
  适量留白
  轻微阴影
  蓝色强调色

AI 可能理解的

"现代简约" 可能是：
  → Apple 极简黑白
  → Medium 宽松排版
  → Notion 柔和色彩
  → 某个模板的默认样式
设计是五维度的：颜色、间距、布局、响应式、视觉特征。一句话无法涵盖所有维度，必然导致理解偏差。

表达差距

你想说"看起来干净"，设计师会说"8px 基准系统，最小间距 0.5rem"——差距在这

你的表达设计师的表达
"要看起来干净""8px 基准系统，最小间距 0.5rem，最大宽度 75ch"
"颜色要协调""HSL 色彩空间，主色饱和度 60-80%，辅助色同色系"
"要有现代感""box-shadow: 0 4px 6px，圆角 0.375rem，无衬线字体"
模糊描述 → 模糊结果，这是必然的。但好消息是：你不需要学会设计师的语言——AI 可以帮你翻译。

渐进式提示

一种分阶段、结构化的 AI 沟通方法：从模糊感受出发，通过关键问题引导，逐步细化，最终生成精准提示词。

一句话 vs 渐进式

一次性输入模糊描述 → 反复修改。分阶段澄清需求 → 一次到位。

核心理念

不是要求 AI 读懂你的心思，而是引导 AI 与你共同澄清需求。

方法对比

传统一句话提示 vs 渐进式提示，差别在哪？

一句话提示

  • 一次性输入模糊描述
  • 需提前知道所有技术细节
  • 结果常偏离真实意图
  • 学习曲线低，但效果差

渐进式提示

  • 分阶段澄清需求
  • 从感觉出发，逐步细化
  • 结果精准匹配期望
  • 学习曲线稍高，但回报大
核心理念：不是要求 AI 读懂你的心思，而是引导 AI 与你共同澄清需求。

四阶段详解

直觉描述 → 需求澄清 → 确认原则 → 精准输出。每一步都在缩小"你想要的"和"AI 理解的"之间的差距。

前两步：输入

直觉描述 — 用日常语言说出感觉。需求澄清 — AI 问你选择题，你选 + 补充。

后两步：输出

确认原则 — AI 总结设计规范，你检查修正。精准输出 — 转化为可执行的专业提示词。

四阶段是个逐渐收窄的漏斗

理解偏差  高 │ ███████   ██████   █████   ████     低
                 ↓   ①       ②       ③       ④
                ┌──────┬──────┬──────┬──────┐
                │直觉描述│需求澄清│确认原则│精准输出│
                └──────┴──────┴──────┴──────┘
精准度     低 │                             │     高

每往前一步，你和 AI 的理解偏差就缩小一截，提示词的精准度同步上升——所以越往后越省事。

直觉描述

从最模糊的感受开始，用日常语言描述——就像跟设计师朋友聊天

你 "我想要一个现代简约的博客页面，看起来干净清爽，但具体细节我不太确定。请你问我一些问题，帮我把想法梳理清楚。"

三个要点

  • 用日常语言描述感受，不必担心不够专业
  • 诚实说"不太确定"，这是正常的
  • 主动请求 AI 问你问题，而不是自己想

初始提示模板

"我想要一个 [风格] 的 [页面类型]，
看起来 [感觉描述]，
但具体细节我不太确定。
请你问我一些问题，
通过我的回答逐步细化。"

需求澄清

AI 用选择题帮你把模糊感受转化为可操作的维度——你只需要选，不需要想

AI 为了精准匹配你的"现代简约"期望，请帮我澄清几个维度： 
1. 颜色系统（"简约"的配色方案）：
   [ ] 极简黑白灰（如 Apple 风格）
   [ ] 单色系 + 1 个强调色（如深蓝 + 浅蓝）
   [ ] 自然中性色（米白、浅灰、木色）
   [ ] 其他：_________

2. 间距与留白（"干净清爽"的量化）：
   [ ] 紧凑型（信息密度高）
   [ ] 宽松型（大量留白，突出内容）
   [ ] 混合型（标题紧凑，内容宽松）

3. 布局结构：单栏？双栏？网格？
4. 响应式策略：移动优先？桌面优先？
5. 视觉特征：阴影？动画？字体？
为什么用选择题：降低决策难度。你只需选最接近的选项，再补充一两句自己的想法就够了。不确定的维度可以先跳过。

确认原则

AI 把你的选择总结成具体设计原则，你来确认或修正

AI 根据你的选择，我总结出以下设计原则： 
颜色系统：单色系 + 1 个强调色
           深灰文字(#1e293b) + 浅灰蓝背景(#f8fafc)
           蓝色强调色(#2563eb)

间距系统：宽松型，8px 基准
           最小间距 0.5rem，最大宽度 75ch

布局结构：单栏居中，内容宽度适中

响应式：  移动优先，小屏单列 → 大屏增加宽度

视觉特征：轻微阴影 + 简单悬停动画 + 无衬线字体

确认三步

  • 检查 AI 的总结是否符合预期
  • 修正不准确的部分
  • 补充遗漏的细节

精准输出

设计原则转化为 AI 可执行的专业提示词——直接拿来用

创建现代简约博客的 CSS 样式，遵循以下规范：

1. 设计系统：
   - 颜色：主色 #2563eb，文字 #1e293b，背景 #f8fafc
   - 间距：8px 基准，最大宽度 75ch，段落间距 1.5rem
   - 字体：Inter/系统字体，正文 1rem/行高 1.6

2. 布局系统：
   - 单栏居中，max-width: 75ch，padding: 2rem 1rem
   - 响应式：<768px 基础单栏，768-1024px 可加侧边栏

3. 组件规范：
   - 文章卡片：box-shadow 0 4px 6px，悬停 translateY(-2px)
   - 标题：h1 字体 2.5rem，底部边框 1px solid #e2e8f0
   - 代码块：背景 #f1f5f9，圆角 0.375rem

4. 代码规范：
   - 避免 !important，禁止 float/table 布局
   - 目标浏览器：现代浏览器最新 2 个版本
这份提示词本身就是一份微型设计规范，值得保存。你可以直接用它生成 CSS，也可以要求 AI 调整特定部分。

实战：确认

第三阶段：AI 总结设计原则，你检查并修正

AI 感谢您的详细反馈！我总结出以下设计原则：

AI 的总结

  • 颜色：深灰文字 + 浅灰蓝背景 + 蓝色强调色
  • 间距：宽松型，大量留白确保阅读舒适
  • 布局：单栏居中，约 75 字符/行

你的检查

  • 颜色方向对吗？需要调整吗？
  • 留白程度符合预期吗？
  • 有没有遗漏的需求？
  • 有没有互相矛盾的地方？
想象这是设计师给你的方案确认邮件——认真思考每一项，发现不对就立刻修正，比事后改代码成本低得多。

为何有效

四个原因解释为什么渐进式提示比一句话效果好得多

降低认知门槛

你不需要知道 minmax() 或 aspect-ratio，只需描述你的感觉和期望。AI 帮你翻译成专业术语。

捕捉隐性需求

通过专业问题引导，发现你没意识到的需求——比如"最大内容宽度 75ch"对可读性的重要性。

建立共同语言

逐步将模糊感受转化为专业术语，减少你和 AI 之间的误解。

提高结果质量

每个决策点都经过确认，结果更精准。从"反复修改 5 次"变成"几乎不用改"。

一句话总结：渐进式提示不是更复杂的提示，而是更智能的对话流程。

Open Design 登场

把前面学的"渐进式四步曲"交给一个工具去自动执行——这就是 Open Design

一句话定义：Open Design（简称 OD）是一个开源、本地优先的 AI 设计引擎。它把你电脑上已有的编程 Agent（Claude Code、Codex、Gemini CLI 等）接入一套"设计技能 + 设计系统"工作流，自动完成从模糊想法到可渲染 HTML 的全流程。

它为什么存在

2026 年 4 月 Anthropic 发布 Claude Design——LLM 不再写废话、直接交付设计成品。但它闭源、收费、云端、锁模型。OD 用同样的"产物优先"思路，但没有任何锁定。

核心反差点

OD 不内置 Agent——你笔记本上最强的 coding agent 已经装好了。OD 做的是把它接进 skill 驱动的设计工作流，每一层都 BYOK（自带密钥）。

别误用工具：工具不替代你思考，而是把你刚学的方法论固化成可复用的流程。先学会方法，再用工具放大效率。

站在四个开源肩膀上

OD 不是凭空发明的——它把四个开源项目的能力蒸馏成了一个统一工作流

技能库（31 个）

按 scenario 分组：design / marketing / operation / engineering / product / finance / hr / sale / personal。每个 Skill 是一份 SKILL.md，规定生成流程与输出规则。

设计系统（129 套）

2 套手写 starter + 70 套产品级（Linear、Stripe、Vercel、Notion、Apple、小红书…）+ 57 个 design skill。每套含确定性 OKLch 色板 + 字体栈 + 布局规则。

先跑一次 Design System Mode 生成 ./DESIGN.md；之后所有 Prototype / Deck / Template 都会自动读取它——这是 OD 的"一次定义、处处复用"模式。

如何选 Mode

不必手动选——直接打字。prompt 含"slide/deck/ppt"→Deck；含"design system/tokens/brand"→DS；含"template"+模板名→Template；其余默认 Prototype。

三种部署拓扑

同一套 UI，能以三种形态运行——从纯本地到纯云端，按需选择

拓扑构成适用场景权衡
A · 全本地
（默认）		浏览器 → Next.js → 本地 daemon → 本地 Agent CLI日常开发、隐私敏感零配置、零账户；最快、最完整
B · Vercel + 本地 daemon浏览器 → Vercel Web → ws 隧道 → 本地 daemon → Agent CLI团队共享 Web 层、跨设备访问密钥留在本地；Web 层仅是 UI
C · Vercel 直连 API浏览器 → Vercel → Anthropic/OpenAI API（BYOK 存浏览器）"先试一下"的体验路径降级：无 CLI、无文件 artifact、无 PPTX 导出
架构哲学：Web 应用 + 本地 daemon 的拆分，让同一套 UI 能从纯本地无缝切换到纯云端。daemon 持有所有敏感资源（密钥、文件系统、Agent）；Web 层可以零密钥部署到 Vercel。
安全模型：daemon 默认只绑定 localhost；预览 iframe 用 <iframe sandbox="allow-scripts">（不给 allow-same-origin）隔离 XSS；agent 的 cwd 锁定在 artifact 目录，继承 agent 自身的权限模型（如 Claude Code 的 --permission-mode）。

Prompt 三层组合机制

每次按下 Send，OD 都会从三层构建 system prompt——这是"共同语言"的工程化

三层叠加顺序

① BASE_SYSTEM_PROMPT
   输出契约：用 <artifact> 包裹
   不使用 code fence

② + DESIGN.md 正文
   色板 / 字体 / 布局规则
   (当前激活的设计系统)

③ + SKILL.md 正文
   工作流 / 输出规则 / 自检清单
   (当前激活的技能)

然后才是你的输入

user: 你的 prompt
   "做一个杂志风格的
    种子轮 pitch deck"

→ Agent 看到的完整上下文 =
   基础契约 + 品牌视觉 + 技能流程
   + 你的具体需求
对应本章概念：BASE 是"输出格式约定"；DESIGN.md 是"专业术语翻译"（风格维度表的具体值）；SKILL.md 是"四步曲的流程脚本"。三层组合 = 把你手动拼提示词的过程，固化成可复用的模板。

会话内缓存

正文按 session 在内存中缓存，切换 Skill 或 DS 只需从 daemon 获取一次，后续 send 复用同一份组合。

热重载

dev 模式下 DESIGN.md / SKILL.md 文件变化会被监听，下次 send 自动用新版本——方便迭代设计系统。

四步曲被自动化了

你刚学的渐进式方法，在 OD 里对应着具体的内置机制

手动渐进式（本章所学）

1. 直觉描述（自己写）
2. 需求澄清（自己问自己）
3. 确认原则（自己查风格表）
4. 精准输出（自己拼提示词）

OD 自动化（工具代劳）

1. Discovery 提问表单（自动弹出）
2. 5 个视觉方向（自动可选）
3. Skill + Design System（下拉切换）
4. <artifact> 实时渲染（沙箱预览）
对应关系：Discovery 表单 = 需求澄清；视觉方向选择器 = 确认原则；Skill 与 Design System 组合 = "专业术语翻译"；五维自我批评（self-critique）= 质量保证层。
工具出错怎么办：正因为 OD 把流程藏起来了，你更要先学会手动方法——否则工具出错时，你完全不知道哪一步坏了。

五步生成回路

从你按下 Send 到看到渲染结果，OD 内部走了这五步

步骤动作发生了什么
① 提问Discovery 表单交互式表单先弹出，澄清 surface / 受众 / 调性 / 品牌上下文 / 规模——不让模型乱猜一个像素
② 选向视觉方向选择从 5 个策展方向选一个（Editorial Monocle / Modern Minimal / Warm Soft / Tech Utility / Brutalist），每个带确定性 OKLch 色板 + 字体栈
③ 规划TodoWrite 流式实时计划以活卡片形式流入 UI，in_progress → completed 实时切换，你能中途介入纠偏
④ 落盘真实项目目录daemon 在磁盘建真实文件夹（种子模板 + 布局库 + 自检清单），Agent 拥有真实 Read/Write/Bash/WebFetch
⑤ 批评五维自评 + artifact对照自己的产出做五维自评，最终输出 <artifact> 在沙箱 iframe 秒级渲染
设计哲学：这不是"AI 试着设计点东西"，而是被提示栈训练得像资深设计师的 AI——有真实文件系统、确定性调色库、清单文化。
沙箱安全：每个 artifact 都在 <iframe sandbox="allow-scripts"> 里渲染（无 allow-same-origin），与宿主应用完全隔离；JSX artifact 注入 vendored React 18 + Babel standalone 动态求值；agent 写文件触发 100ms 防抖重建。

快速上手：三命令跑起来

本地优先——三条命令启动完整产品，无需账户、无需配置

环境要求

Node.js 24 + pnpm 10.33。建议提前装好任一 Agent CLI（Claude Code / Codex / Gemini CLI 等）；一个都没装也能用 BYOK API 模式兜底。

三条命令

corepack enable
pnpm install
pnpm tools-dev run web

然后打开终端输出的本地 URL（默认 localhost:3000）。

首次启动自动发生

→ 扫描 PATH 上的 agent CLI
→ 自动选择第一个可用的
→ 默认 Skill：web-prototype
→ 默认 DS：Neutral Modern
→ SQLite 初始化在 .od/

输入第一句

"做一个杂志风格的
 种子轮 pitch deck"

→ Discovery 表单弹出
→ 选 5 个视觉方向之一
→ Agent 流式生成
→ 右侧实时渲染
仓库地址：github.com/nexu-io/open-design。本地优先，数据存 .od/app.sqlite——明天打开 todo 和文件还在原地。

三种精修方式

生成只是第一步——OD 提供三种粒度的精修，对应不同的纠偏成本

方式粒度典型用法是否重新生成
Chat 自由对话整页/整段"把 CTA 移到首屏上方"、"加一个关于定价的章节"是（局部）
Comment 元素评论单个元素点元素 → 弹窗 → "把这张卡片改成毛玻璃效果"否（外科手术式编辑）
Slider 参数滑块单个参数调 accent_hue、spacing_scale——只发送参数值否（极快）

Comment 模式的条件

只在 Agent adapter 支持 surgicalEdit === true 时可用（如 Claude Code 的原生 tool loop）。点击捕获 [data-od-id]，生成精确到元素的编辑指令。

Slider 的条件

由 Skill 在 frontmatter 声明 od.parameters。滑块拖动只重发参数值，不走完整 chat——交互成本最低、响应最快。

选择策略：大改用 Chat，小改用 Comment，微调用 Slider。三者可以混用——Comment 标注问题 → Chat 描述新方向 → Slider 微调参数。

导出与持久化

OD 把所有产物都当作真实文件——可 git 跟踪、可 PR review、可明天继续

五种导出格式

HTML  内联 CSS，资源转 data: URI
PDF   puppeteer → page.pdf()
PPTX  slides.json → pptxgenjs
ZIP   归档整个 artifact 目录
MD    原样复制（若产物是 .md）

磁盘上的产物布局

.od/
├── app.sqlite          # 持久化数据
├── artifacts/
│   └── <时间戳>-<slug>/
│       ├── artifact.json  # 元数据
│       ├── index.html     # 主产物
│       └── assets/        # 图片/字体
└── projects/<id>/      # Agent 的 cwd

为什么用文件而非数据库

artifact.json 元数据 + history.jsonl 操作日志 → OD 能不用数据库就重建 artifact 树。可直接 git add ./.od/artifacts/，在 PR 里 review 设计。

SQLite 持久化的内容

projects / conversations / messages / tabs / 用户 templates。明天再开应用，todo 卡片和打开的文件都还在原位——会话状态不丢。

导入 Claude Design：把 Claude Design 导出的 ZIP 拖到欢迎弹窗 → POST /api/import/claude-design 解析成真实项目，agent 接着 Anthropic 停下的地方继续编辑。
