标签未闭合

HTML 错误一：标签未闭合或嵌套出错——这类错误最隐蔽，往往不影响渲染但埋下灾难种子

<!-- ❌ 错误：div 未闭合 → 后续内容全被吞进这个 div -->
<div class="content">
  <p>第一段</p>
  <p>第二段</p>
<!-- </div> 忘了写！ -->

<!-- ✅ 正确写法 -->
<div class="content">
  <p>第一段</p>
  <p>第二段</p>
</div>

嵌套错误（交叉嵌套）

<p>一段<strong>加粗</p>文字</strong>
<!-- ❌ 交叉嵌套 -->

正确嵌套

<p>一段<strong>加粗</strong>文字</p>
<!-- ✅ 像括号一样层层闭合 -->
注意 DevTools 诊断法：在 Elements 面板看缩进层级——如果某个元素的子元素缩进比预期深很多，很可能是少了一个闭合标签。

属性与路径

HTML 错误二：属性拼写错误与资源路径——href vs src、class vs for、相对 vs 绝对路径

错误写法正确写法说明
<img href="..."><img src="...">img 用 src，不要用 href
<a src="..."><a href="...">a 用 href
<div class="box">HTML 正确class 是给 CSS 选择器用的
class="btn" 但 CSS 写 .Btnclass="btn" + CSS .btn大小写敏感
 
<!-- ❌ 路径常见错误 -->
<img src="Photo.png">              <!-- ❌ 大小写不一致：实际文件是 photo.png，Windows 能开但服务器 404 -->
<img src="image/photo.png">        <!-- ❌ 文件夹名拼错：实际是 images（复数）-->

<!-- ✅ 推荐写法：路径与文件名完全一致 -->
<img src="images/photo.png">
终极诊断法 Network 面板 → 筛选 Img / CSS 文件 → 红色 = 404 → 右键 Open in new tab 看实际请求路径

语义化滥用

HTML 错误三：语义化反模式——你的 HTML 应是一首有结构的散文，而不是一罐压缩饼干

div 包一切 (div soup)

<div class="header">...</div>
<div class="nav">...</div>
<div class="main-content">...</div>
<div class="footer">...</div>

语义化结构

<header>...</header>
<nav>...</nav>
<main>...</main>
<footer>...</footer>
习惯用法更好的写法为什么更好
<br><br> 换行</p><p> 自然段落间距结构清晰，样式可控
<hr> 做分割线border-bottom 或 CSS gap装饰与结构分离
&nbsp;&nbsp; 缩进padding-left 或 text-indent语义化间距更灵活

section vs article

section 是'主题分区'，article 是'独立可分发内容'

nav 怎么用

只包裹主导航链接组，不是所有链接的容器

找错练习一

练习：找出下面 HTML 中的 3 个错误——涉及标签闭合、属性拼写、结构嵌套

<!DOCTYPE html>
<html>
<head>
  <title>我的博客</title>
  <link ref="stylesheet" href="style.css">     <!-- ❓ 这里有错 -->
</head>
<body>
  <div class="post">
    <h2>学习笔记</h2>
    <p>今天学了 <strong>HTML 语义化</p>            <!-- ❓ 这里有问题 -->
    <p>感觉收获很大！</p>
  </div>
  <img scr="images/photo.jpg" alt="照片">         <!-- ❓ 第三处 -->
</body>
</html>
参考答案 ① ref → rel (link 标签) ② <strong> 应在 </p> 内闭合 ③ scr → src (img 标签)

权重覆盖

CSS 错误一：选择器权重（Specificity）——为什么你写的样式"不生效"？大概率是被覆盖了

/* 你的样式 */
.card { background: white; }

/* 但又写了更具体的 */
.project-list .card { background: blue; }
/* .project-list .card 权重更高 → 蓝色生效 */
/* 你在 .card 这里怎么改都没用！ */
选择器类型权重分量例子
内联 style1,0,0,0style="color: red"
#id0,1,0,0#main-nav
.class / :pseudo0,0,1,0.card:hover
元素 / ::pseudo-element0,0,0,1p::before
DevTools 诊断法：Styles 面板 → 你会发现被覆盖的样式有一条横线划掉 → 这就是源头！不要加 !important，先检查权重。

盒模型溢出

CSS 错误二：盒模型困惑——width: 100% 的盒子加了 padding 后溢出了，谁的问题？

content-box（默认）

/* CSS 默认盒模型 */
.box {
  width: 100%;
  padding: 20px;
  border: 1px solid #ddd;
}
/* 实际宽度 = 100% + 40px + 2px → 溢出！ */

border-box（推荐）

/* 全局重置为 border-box */
*, *::before, *::after {
  box-sizing: border-box;
}
.box {
  width: 100%;
  padding: 20px;     /* width 包含 padding 和 border */
}
/* 实际宽度 = 100% → 不会溢出！ */
DevTools 诊断法：Computed 面板的盒模型图示 → 一眼看出 width / padding / border / margin 各占多少

Flex 不缩小

CSS 错误三：Flex 与 Grid 奇怪的队列行为——最常见的坑是子项不缩小、内容溢出

/* ❌ 经典 flex 问题：子项内容太长时不缩小 */
.container { display: flex; }
.item { /* 默认 min-width: auto → 内容再长也不缩小 */ }

/* ✅ 解决方案 */
.item {
  min-width: 0;            /* 允许 flex 子项缩小到 0 */
  overflow: hidden;        /* 防止内容溢出 */
  text-overflow: ellipsis; /* 过长显示省略号 */
}
注意 Grid 的坑：如果 grid 轨道依赖内容高度，内容为空时轨道会坍缩消失。解决方案：用 min-height 或 grid-auto-rows: minmax(100px, auto)
调试器神技 Chrome DevTools Layout 面板 → 打开 Flex/Grid 徽章 → 直接在页面上看到 flex-direction、grid-template 等关键信息

断点遗漏

CSS 错误四：响应式断点遗漏——电脑上看一切正常，平板/手机上一塌糊涂

/* ❌ 只在 1024px 以内设计了响应式 */
@media (max-width: 768px) {
  .nav { flex-direction: column; }
}
/* → 768px~1024px 之间没有覆盖，iPad 上可能崩 */

/* ✅ 多断点全覆盖 */
.container { max-width: 1200px; margin: 0 auto; }

@media (max-width: 1024px) { /* 平板 */ }
@media (max-width: 768px)  { /* 大屏手机 */ }
@media (max-width: 480px)  { /* 小屏手机 */ }
DevTools 设备模拟器 → 顶部工具栏 Toggle device toolbar → 拖拽视口宽度 → 实时查看各断点下的效果

继承与层叠

CSS 错误五：继承与层叠的意外——为什么 color 能继承，border 却不能？!important 真的是解药？

可继承属性不可继承属性
color, font-family, line-height, text-alignborder, margin, padding, background
visibility, letter-spacing, cursorwidth, height, position, opacity
 
/* 疑问：为什么 a 标签不继承父元素的 color？ */
a { color: inherit; }   /* ← 这就是为什么需要显式写 */
/* 原因：浏览器默认给 a 设置了蓝色 user-agent 样式 */

/* !important 不是解药，而是后遗症 */
.title { color: red !important; }
/* → 后续任何 .title { color: blue } 都会失效 */
/* → 需要再加 !important 去覆盖 → !important 军备竞赛 → 删不掉的样式炸弹 */
注意 !important 的合法用途：仅用于工具类（如 .hidden { display: none !important; }）、覆盖第三方库样式。其他地方一律不用。

找错练习二

练习：找出下面 CSS 中的 4 个错误——涉及权重、盒模型、属性名、颜色格式

#main .btn {              /* ❓ 这条规则让 .btn 的样式被覆盖了 */
  background: gray;
}

.card {
  width: 100%;
  padding: 20px;            /* ❓ 盒子比父容器还宽 */
}

.btn {
  color: white;
  backround-color: #D06519;  /* ❓ 背景色没出现 */
  border: 1pz solid #ccc;    /* ❓ 边框没显示 */
}
参考答案 ① #main .btn 权重 (1,1,0)，远高于 .btn 的 (0,1,0)，会把 .btn 的背景色覆盖成 gray。在 DevTools 的 Styles 面板里，.btn 的 background 会被划掉。② 缺 box-sizing: border-box，width: 100% 不含 padding，实际占宽超过 100%（见盒模型幻灯片）。③ backround-color 拼写错误，应为 background-color。④ 1pz 是错别字，应为 1px——单位拼错时整条 border 声明失效，边框不显示。

修复崩坏布局

实战：一个"崩坏"的布局是如何被修复的——完整演示诊断与修复的思维过程

症状描述

现象：三个卡片应该在手机上一行三个
      但第三个掉到下一行
      并且在 800px ~ 1024px 之间样式忽大忽小

修复过程

Step 1: 打开 DevTools → 选中第三个卡片
        → 看 Computed 宽度
        → 原来 width: 33.3% 包含父容器的 padding
        → 第三张挤不下了
Step 2: 全局添加 box-sizing: border-box
        → 现在 33.3% 不溢出了
Step 3: Network 面板 → 发现漏写了
        768px ~ 1024px 的媒体查询
Step 4: 补充 @media (max-width: 1024px)
        → 1024px 以下两列
done!
调试心法 每次只改一处 → 刷新确认 → 再改下一处。如果一次改了 5 处还是修不好，你已经不知道是哪一处生效的了。
