MCP 外部工具

给 Codex 装上第三只眼——调用外部 API、数据库和自定义工具

从"只能聊天"到"连接一切"

反复切换的痛苦

你正在用 Codex 写代码，却需要不断跳出终端去查外部信息

查文档要切浏览器

Codex 不知道最新的 API 参数，你只能打开官网查完再粘回来——来回切换 20 次。

查数据库要开客户端

你需要确认表结构、字段类型，只能切到 DBeaver 或 pgAdmin，复制粘贴结果。

查日志要登服务器

你想让 Codex 分析线上报错，但它访问不了你的日志平台。每次都要你手动喂数据。

核心矛盾：Codex 模型本身无法联网、无法访问私有系统。它需要一个"手"来触碰外部世界——这就是 MCP。

MCP 是什么

Model Context Protocol——让 AI 模型调用外部工具的标准化协议

一句话解释

MCP 就像 USB 接口——定义了模型与外部工具之间插拔的统一标准。只要 tool 实现 MCP 协议，任何兼容的 AI client 都能调用它。

三个核心概念

  • MCP Server：提供外部能力的程序
  • MCP Client：消费 server 能力的程序（Codex CLI）
  • Transport：通信方式（stdio 或 HTTP）

MCP 架构示意

画面：左侧 Codex CLI (Client) 方块，右侧多个 MCP Server 方块（GitHub、Database、Docs）。

关系：Client 与 Server 双向箭头连线，标注 stdio 或 HTTP。

标注：连线标注"MCP Protocol (JSON-RPC 2.0)"。

三种配置方式

告诉 Codex 去哪里找 MCP server，有三种等价途径

方式一：.mcp.json

放在项目根目录的 JSON 文件。可提交到 Git，团队共享。

my-project/
+-- .mcp.json      <- MCP 配置
+-- AGENTS.md
+-- src/

方式二：config.toml

写在 Codex 配置文件的 [mcp_servers] 段。适合个人全局配置。

方式三：CLI 动态

用 codex mcp add 命令临时添加。不写文件，即时生效，适合快速试用。

.mcp.json 格式

最常用的配置方式——项目级 JSON 文件

{
  "servers": {
    "github": {
      "transport": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"]
    },
    "openai-docs": {
      "transport": "http",
      "url": "https://developers.openai.com/mcp"
    }
  }
}

顶层结构

servers 是一个对象，key 就是 server 名称，value 是 transport 配置。Codex 启动时自动读取。

stdio 模式

Codex 启动子进程，通过标准输入输出通信

适用场景

  • 本地安装的工具（npm/pip/apt 安装）
  • 需要访问本机文件系统的 tool
  • 需要环境变量注入的私有 API

配置字段

  • "transport": "stdio"
  • "command"：可执行文件路径
  • "args"：命令行参数数组
  • "env"：（可选）环境变量
"my-server": {
  "transport": "stdio",
  "command": "node",
  "args": ["./my-mcp-server.js"],
  "env": { "API_KEY": "sk-..." }
}

HTTP 模式

通过网络 URL 连接远程 MCP server

适用场景

  • 公开托管的 MCP 服务（如 OpenAI Docs MCP）
  • 需要在多机器间共享的 server
  • 不想安装本地依赖的场景

配置字段

  • "transport": "http"
  • "url"：MCP server 的 HTTPS 端点
  • "headers"：（可选）自定义请求头
"openai-docs": {
  "transport": "http",
  "url": "https://developers.openai.com/mcp",
  "headers": {
    "Authorization": "Bearer your-token"
  }
}

config.toml 内联

在全局配置中直接声明 MCP server

Codex 支持在 config.toml 中使用 [mcp_servers] 段：

[mcp_servers.github]
transport = "stdio"
command = "npx"
args = ["-y", "@modelcontextprotocol/server-github"]

[mcp_servers.openai-docs]
transport = "http"
url = "https://developers.openai.com/mcp"
何时选用：Toml 内联适合不想新增 .mcp.json 的场景；.mcp.json 更适合团队共享。两种等价，可同时使用。

CLI 管理命令

用 codex mcp 子命令动态管理 server

命令 作用
codex mcp add <name> -- <cmd> [args...]添加 stdio server
codex mcp add <name> --url <url>添加 HTTP server
codex mcp list列出所有 server
codex mcp remove <name>移除 server
小贴士：-- 是分隔符——之前是 MCP 参数，之后是命令原文透传。

实战：OpenAI Docs

用一个命令让 Codex 实时查阅开发者文档

$ codex mcp add openaiDeveloperDocs --url https://developers.openai.com/mcp

这行做了什么

  1. 注册名为 openaiDeveloperDocs 的 MCP server
  2. 使用 HTTP transport 连接官方端点
  3. Codex 启动后自动加载 server 的所有工具

如何使用

启动 Codex 后直接问：

用户：response_format 参数支持哪些类型？

Codex 自动调用 MCP 工具查询最新文档，而非依赖训练数据。

验证已添加

用 list 命令确认 server 注册成功

$ codex mcp list
  openaiDeveloperDocs (http)  connected
    url: https://developers.openai.com/mcp
    tools: query_docs, search_docs

输出解读

  • connected：server 可达，工具已加载
  • tools：server 暴露的所有可调用工具

移除不需要的

$ codex mcp remove openaiDeveloperDocs
Removed MCP server: openaiDeveloperDocs

实战：GitHub MCP

让 Codex 直接操作你的 GitHub 仓库

Server 级别配置

除了 transport，还有 env、timeout 等字段

"my-server": {
  "transport": "stdio",
  "command": "python",
  "args": ["./server.py"],
  "env": {
    "DATABASE_URL": "postgresql://localhost/mydb"
  },
  "timeout": 30,
  "enabled": true
}

env

注入子进程的环境变量。不共享父进程——只写在这里 server 才能读到。

timeout

单次调用超时秒数，默认 30 秒。复杂查询可调高。

enabled

false 可临时禁用 server 而不删除配置。

过滤生效 Server

只启用当前任务需要的 server

enabled_mcpjson_servers = ["github", "openaiDeveloperDocs"]
# 或排除特定 server
disabled_mcpjson_servers = ["database"]
为什么？工具越多，上下文窗口占用越大，响应越慢。

网络访问权限

HTTP 模式的 server 需要开启网络权限

沙箱环境下

Codex 启用沙箱时默认不开放网络。需要显式允许：

[sandbox_workspace_write]
network_access = true

stdio 不需要

stdio server 在本地执行，网络调用不受沙箱限制。

反向操作：暴露 Codex

把 Codex 自身作为 MCP server 给其他 agent 调用

这是什么

Codex 不仅能当 client，还能反向作为 MCP server——让其他 AI agent 把代码生成当作工具调用。

协议

JSON-RPC 2.0 over stdio。标准协议，任何 MCP client 都能对接。

状态

实验性功能。API 可能变更，适合尝鲜和原型开发。

mcp-server 命令

一行命令启动 Codex MCP server

$ codex mcp-server

输出

通过 stdio 以 JSON-RPC 2.0 帧通信。可管道传给 client：

$ codex mcp-server | your_mcp_client

暴露的工具

  • codex/exec——执行自然语言任务
  • codex/status——查询当前会话状态

Python 连接示例

用 Python SDK 连接 Codex MCP server

import asyncio

async def main():
    process = await asyncio.create_subprocess_exec(
        "codex", "mcp-server",
        stdin=asyncio.subprocess.PIPE,
        stdout=asyncio.subprocess.PIPE,
    )
    reader = process.stdout
    # 初始化握手、调用工具...
    response = await reader.read()
    print(f"Codex 暴露的工具: {response}")

asyncio.run(main())
关键思路：Codex 变成另一个 agent 手里的"工具"——这就是 agent 编排的常见模式。

编排场景

把 Codex 嵌入更大的 agent 工作流

代码审查流水线

主 agent 调用 Codex MCP 生成代码，再调用 linter MCP 检查。

自动化运维

编排 agent 调用 Codex MCP 生成修复脚本，经审批后执行。

CI/CD 管道

CI 服务器运行轻量 MCP client，测试失败时调用 Codex 生成修复 PR。

安全注意

MCP server 能做的事，Codex 就能做——谨慎授权

信任已知来源

只添加来自官方库、知名厂商或自己编写的 MCP server。

审查配置

提交 PR 前人工 review server 地址和命令。

最小权限

给 server 的 token 只授予最小必要权限。

红线：永远不要将 admin 密钥放进 .mcp.json 并提交 Git。

连接更稳了

0.146：认证变化时刷新，健康连接不中断

认证变了自动刷新

当你重新登录、token 轮换或切换账号时，MCP 连接和 Apps 工具会自动刷新，不用手动重启每个 server。

健康连接不断

重连机制现在不中断仍在健康的连接——只重建出问题的那部分，避免"一个 server 抖动，全部重连"。

实际影响：长会话里偶尔的认证过期、网络波动，不再让所有 MCP 工具集体掉线。你大概率感知不到这次改进——因为本来该报错的地方，现在静默恢复了。

常见错误

server 启动失败？先排查这些

启动失败

原因：command 路径错误或依赖未安装。

修复：终端直接运行 command + args。

$ npx -y @modelcontextprotocol/server-github

transport 错误

原因：写了 tcp 或其他无效值。

修复：只允许 stdio 或 http。JSON key 不要拼错。

常见错误 (2)

PATH 环境问题

原因：子进程找不到 npx / node / python。

修复：在 env 中显式指定 PATH。

HTTP 连接超时

原因：URL 不可达、网络受限。

修复：先用 curl -I 测试。确认是否要 network_access = true。

综合示例

多 server 混合配置

{
  "servers": {
    "github": {
      "transport": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "$GH_TOKEN" }
    },
    "openai-docs": {
      "transport": "http",
      "url": "https://developers.openai.com/mcp"
    },
    "notion": {
      "transport": "stdio",
      "command": "npx",
      "args": ["-y", "@mcp/server-notion"],
      "enabled": false
    }
  }
}
要点：混合 stdio + HTTP；用 enabled: false 临时禁用；$GH_TOKEN 引用环境变量。
