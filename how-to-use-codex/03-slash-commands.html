什么是 Slash Command

一句话：以 / 开头的输入被解析为内置命令，不是发送给 AI 的提示词

核心区别

普通输入 → 发送给 LLM 推理 → 消耗 token
/model → CLI 直接执行 → 不消耗 AI token（除非命令本身触发 AI 动作）

触发方式

在 TUI 中输入 / 打开命令弹窗，支持 Tab 自动补全。输入 /m 按 Tab 即可补全为 /model。

数量规模

Codex CLI 内置 50+ 个 slash command，覆盖会话管理、模型配置、权限控制、信息查询、IDE 集成等场景。

记住这个规则：看到 / 开头，想到的是"操作 CLI"，不是"跟 AI 说话"。这能帮你省大量 token。

怎么触发

TUI 中的命令弹窗与补全机制

触发流程：/ → 弹窗 → 补全 → 执行

┌─────────────────────────────────────────────────────┐ │ Codex CLI TUI │ │ ┌─────────────┐ ┌──────────────┐ │ │ │ 输入 / │───▶│ 命令弹窗展开 │ │ │ └─────────────┘ └──────┬───────┘ │ │ │ │ │ ┌─────────────┐ ┌──────▼───────┐ │ │ │ Tab 补全 │◀───│ 输入前缀过滤 │ │ │ └──────┬──────┘ └──────────────┘ │ │ │ │ │ ┌──────▼──────┐ ┌──────────────┐ │ │ │ Enter 执行 │───▶│ CLI 直接处理 │ │ │ └─────────────┘ └──────────────┘ │ └─────────────────────────────────────────────────────┘ 底部标注：输入 / → 看到列表 → Tab 补全 → Enter 执行。整个过程不经过 LLM。

弹窗排序规则：命令按使用频率排列（高频在前），不是字母序。源码注释："DO NOT ALPHA-SORT! More frequently used commands should be listed first."

会话管理

9 个命令，掌控你的对话生命周期

命令作用使用场景
/new新建会话（可命名）开个新话题并随手起名，历史仍可查
/clear清空并新建（可命名）清掉旧上下文重新开始，顺带给新会话命名
/resume恢复历史会话回到昨天没做完的工作
/fork分叉当前会话A/B 测试两套方案，互不干扰
/archive归档并退出这个话题结束了，标记完成
/delete永久删除并退出彻底清理不需要的会话
/compact压缩上下文对话太长，总结历史释放 token
/rename重命名会话给会话起个有意义的名字
/title设置终端标题在终端标签页中识别当前会话
最常用：/new、/resume、/compact——这三个覆盖了 80% 的会话管理需求。

给会话起名

0.146：/new 和 /clear 现在能直接命名新会话

> /new 用户登录模块
# 新建一个名为「用户登录模块」的会话，旧的保留在历史里

> /clear 调试内存泄漏
# 清空当前上下文，开启名为「调试内存泄漏」的新会话

为什么重要

以前新建会话只有自动编号，翻历史时一片"会话 1、2、3"分不清。现在能固定关键线程、命名后快速检索，多任务并行也不乱。

/new vs /clear

/new 保留旧会话另起一个；/clear 则清掉当前上下文再开始。两者现在都能带名字。

配合分页历史：命名的会话会出现在分页历史里，支持搜索、固定（pin）。会话管理细节见第 10 章。

/import 迁移

0.145：从 Cursor / Claude Code 一键搬设置

> /import
# 选择来源 → 扫描可迁移项 → 确认写入

能搬什么

  • 设置项（审批策略、模型偏好）
  • MCP servers 配置
  • 已装的 Plugins
  • Memories（长期记忆 / 规则）

为什么放在这

迁移本质上是"批量改配置"，和会话/命令管理同属工作流配置范畴。详细实战见第 05 章。

换工具的最大阻力是重配。/import 把"重配一天"压成一条命令。

/compact：上下文压缩

对话太长记不住了？让 Codex 帮你"总结过去"

它做了什么

将当前对话历史总结为一段精简摘要，替换原始消息。释放 token 空间，让 Codex 继续工作而不丢失关键上下文。

什么时候用

  • 用 /status 查看 token 用量偏高时
  • Codex 回应质量下降，疑似上下文饱和
  • 切换子任务前，压缩已完成部分的上下文

注意事项

压缩是有损的——细节会被丢弃。压缩前先把重要代码片段或决策手动复制到笔记中。

注意：压缩后无法恢复原始对话。如果后续需要引用早期细节，先 /fork 备份当前状态。

模型与配置

4 个命令，切换模型、设定目标、调整人格

命令作用示例
/model切换模型和推理力度（选模型时会一并让你选 reasoning effort）/model gpt-5.6-terra → 再选 low / high / max
/plan进入计划模式先列计划再动手，适合复杂任务
/goal设置长期任务目标/goal 完成用户模块的单元测试
/personality设置沟通风格正式 / 简洁 / 教学式
/model 的强度：推理力度在弹窗中一并选择——复杂任务切 high/max，简单问答切 low 省钱。常规可用sol-medium 规划，用luna-xhigh编码

/plan：计划模式

让 Codex 先想清楚再动手

工作机制

切换到 Plan 模式后，Codex 只输出执行计划，不修改任何文件。你确认计划无误后，再让它执行。

适合场景

  • 涉及多文件修改的重构
  • 不确定实现方案，想先看思路
  • 团队协作，需要 review 计划再动手

黄金组合

/plan → 确认计划 → 执行 → /review
计划 → 执行 → 检查，三步闭环。

权限与安全

3 个命令，控制 Codex 能做什么

命令作用使用场景
/permissions权限设置控制 Codex 是否需要确认才能执行命令
/setup-default-sandbox提升沙箱权限 Windows 专用仅 Windows + 降级版受限令牌沙盒时可用
/approve批准重试批准一次最近被拒绝的 auto-review 重试
关于 /setup-default-sandbox：这是 Windows 专用命令，仅当 Codex 在 Windows 上运行降级版的受限令牌沙盒时才会出现。它通常不会出现在 / 自动补全列表里。

IDE 集成

让 Codex 看到你编辑器里的上下文

/ide

包含当前编辑器中的选中内容、打开的文件和其他 IDE 上下文。让 Codex 不需要你复制粘贴就能理解你在看什么。

典型场景

  • 在 VS Code 里选中一段代码，切到 Codex 输入 /ide
  • Codex 自动获取你的选中文件和光标位置
  • 无需手动描述"这个文件第 30 行的函数"
  • 测试：在IDE中选择一段话，在codex中输入“我在ide中选中了哪些文字？”
前提条件：需要在 IDE 中安装 Codex 插件并连接。

效率技巧

老用户才知道的 4 个窍门

切换前先判断：同任务还是新任务

同一大任务的阶段切换（重构→测试）用 /compact，保留因果链；完全不同的任务用 /new，零上下文污染最省 token。别无脑 /compact。

Fork 比 New 更安全

不确定新思路是否可行？先 /fork 再尝试。不满意就删掉 fork，主线毫发无伤。比 /new 更可控。

/plan + /review 黄金组合

复杂任务：/plan 列计划 → 执行 → /review 检查。三步闭环，代码质量提升一个档次。

Slash Commands 回顾

四句话记住这一章

Slash Command 是什么

以 / 开头的命令直接控制 CLI，不消耗 AI token（除非触发 AI 动作）。50+ 内置命令覆盖 6 大类。

高频命令

怎么触发

输入 / 打开命令弹窗，Tab 自动补全，Enter 执行。按使用频率排序，高频命令在前。

效率心法

切换前判断同任务还是新任务、先 fork 再实验、plan + review 闭环、用 /status 查 token。
