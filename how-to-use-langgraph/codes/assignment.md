# 综合性大型作业：智能文档审核发布系统

## 项目背景

你是一家科技公司的 AI 工程师，需要构建一个**智能文档审核发布系统**。该系统能够自动接收用户提交的技术文档，进行多维度质量检查、自动润色、人工审核，最终发布到知识库。系统还需要管理用户的长期偏好，支持时间旅行调试，并能通过流式输出实时展示处理进度。

## 功能需求

### 核心流程

```
用户提交文档 → 格式检查 → 多维度并行评审 → 自动润色 → 人工审核 → 发布
                ↓                                          ↓
            格式不通过 → 通知用户修改                    驳回 → 标记问题 → 退回修改
```

### 功能列表

| # | 功能 | 对应章节 | 说明 |
|---|------|---------|------|
| 1 | **StateGraph 基本构建** | 第1章 | 定义包含多字段的 State，构建多节点图 |
| 2 | **Prompt Chaining 串联处理** | 第2章 | 格式检查 → 内容分析 → 质量评分的串行链 |
| 3 | **并行化多维度评审** | 第2章 | 同时进行技术准确性、可读性、完整性三维度评审 |
| 4 | **路由分发** | 第2章 | 根据文档类型（教程/API文档/博客）路由到不同处理流程 |
| 5 | **Orchestrator-Worker 分段审核** | 第3章 | 编排者将文档分段，多个 Worker 并行审核各段 |
| 6 | **Evaluator-Optimizer 润色循环** | 第3章 | 自动润色 → 质量评估 → 不达标则重新润色 |
| 7 | **工具调用（查重、统计）** | 第4章 | 定义文档查重工具、字数统计工具、关键词提取工具 |
| 8 | **MemorySaver 持久化** | 第5章 | 保存审核流程的状态，支持中断后恢复 |
| 9 | **InMemoryStore 长期记忆** | 第5章 | 存储用户偏好（常用术语、风格偏好）|
| 10 | **task() 包裹副作用** | 第6章 | 发布操作用 task() 包裹，确保崩溃恢复时不重复发布 |
| 11 | **流式输出进度** | 第7章 | 实时展示审核进度（custom 模式）和状态更新（updates 模式）|
| 12 | **人工审核中断** | 第8章 | 润色完成后暂停，等待人工审核确认或编辑 |
| 13 | **时间旅行调试** | 第9章 | 支持回放到任意审核步骤，或 fork 出不同润色方案 |
| 14 | **消息摘要管理** | 第10章 | 长文档审核时自动摘要历史消息 |
| 15 | **子图组合** | 第11章 | 将"评审"和"润色"分别封装为子图 |

## 技术要求

### 必须包含的知识点

1. **StateGraph + StateSchema**（第1章）
   - 定义 `DocumentReviewState`，至少包含：`document`, `docType`, `reviews`, `polishedContent`, `status`, `messages` 字段
   - 使用 `MessagesValue` 和 `ReducedValue`

2. **工作流模式**（第2-3章）
   - 使用 Prompt Chaining 完成格式检查 → 内容分析的串联
   - 使用并行化完成三维度评审
   - 使用路由根据 docType 分发
   - 使用 Orchestrator-Worker 完成分段审核
   - 使用 Evaluator-Optimizer 完成润色循环（最多 3 次）

3. **工具调用**（第4章）
   - 定义至少 3 个工具：`wordCount`, `checkPlagiarism`, `extractKeywords`
   - 实现 `shouldContinue` 条件边
   - 使用 `toolsByName` 字典

4. **持久化**（第5章）
   - 使用 `MemorySaver` 保存审核流程状态
   - 使用 `InMemoryStore` 存储用户偏好
   - 在节点中通过 `runtime.store` 访问 Store

5. **持久执行**（第6章）
   - 发布节点中的 API 调用用 `task()` 包裹
   - 实现幂等的发布操作

6. **流式输出**（第7章）
   - 使用 `streamMode: ["updates", "custom"]` 组合模式
   - 通过 `config.writer()` 推送审核进度

7. **中断与人机交互**（第8章）
   - 润色完成后 `interrupt()` 暂停，等待人工审核
   - 人工可以编辑内容或批准/驳回

8. **时间旅行**（第9章）
   - 实现 `getStateHistory()` 查看审核历史
   - 支持从任意步骤 Replay
   - 支持从润色步骤 Fork 出不同版本

9. **记忆管理**（第10章）
   - 使用 `RemoveMessage` 清理过长的历史消息
   - 使用 `InMemoryStore` 管理用户偏好

10. **子图**（第11章）
    - 将"评审模块"封装为子图
    - 将"润色模块"封装为子图
    - 在主图中通过节点内调用方式使用子图

## 提示与引导

### 第一步：设计 State
思考整个流程中需要哪些状态字段。建议先画出流程图，再对照流程图定义 State。

### 第二步：从核心流程开始
先实现最简单的流程：提交 → 格式检查 → 发布。确保基本框架能运行。

### 第三步：逐步添加模式
在基本框架上依次添加并行评审、路由、Evaluator-Optimizer 等模式。

### 第四步：添加持久化和中断
在框架稳定后，添加 MemorySaver、InMemoryStore 和 interrupt。

### 第五步：封装子图
将评审和润色功能分别封装为子图，替换原来的扁平节点。

### 调试技巧
- 使用 `getState()` 和 `getStateHistory()` 检查每步的 State 变化
- 使用 `streamMode: "updates"` 观察每步的增量更新
- 遇到问题时，用 Time Travel 回溯到出错步骤
