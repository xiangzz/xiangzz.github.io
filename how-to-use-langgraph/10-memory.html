第 10 章

记忆管理

短期记忆 + 长期记忆——让智能体真正"记住"用户

线程内对话不丢失，跨会话偏好永久保存

每次都陌生

智能体和用户聊了 20 分钟，关掉重开就全忘了——每次都像第一次见面。

对话断了

用户说"我喜欢深色模式"。下一轮对话时，智能体推荐了亮色主题。短期记忆丢失——同一线程内的上下文没能保留。

换线程就忘

用户在对话 A 中说了"我对花生过敏"。开了新对话 B，智能体推荐了花生酱。长期记忆缺失——跨线程的信息没有保存。

上下文爆炸

聊了 100 轮后，把全部消息历史丢给模型——超出 token 限制。记忆需要管理——不是越多越好。

LangGraph 的记忆方案：短期记忆（MemorySaver + thread_id）解决对话内记忆，长期记忆（InMemoryStore + 语义搜索）解决跨会话记忆。两者组合，智能体才能真正"认识"用户。

短期记忆

MemorySaver + thread_id = 多轮对话

import { MemorySaver, StateGraph } from "@langchain/langgraph";

const checkpointer = new MemorySaver();
const graph = builder.compile({ checkpointer });

// 第一轮
await graph.invoke(
  { messages: [{ role: "user", content: "hi! i am Bob" }] },
  { configurable: { thread_id: "1" } }
);

// 第二轮 — 同一个 thread_id，保留上一轮的上下文
await graph.invoke(
  { messages: [{ role: "user", content: "what is my name?" }] },
  { configurable: { thread_id: "1" } }
);
// 模型知道你是 Bob！
关键：同一个 thread_id 下，每轮对话都会保留之前的消息历史。MessagesValue 的 reducer 自动把新消息拼到已有消息后面。

生产环境

MemorySaver 是内存存储，重启就丢。生产用 PostgresSaver。

import { PostgresSaver } from "@langchain/langgraph-checkpoint-postgres";

const DB_URI = "postgresql://postgres:postgres@localhost:5442/postgres?sslmode=disable";
const checkpointer = PostgresSaver.fromConnString(DB_URI);
const graph = builder.compile({ checkpointer });

子图中使用

只需在编译父图时提供 checkpointer，LangGraph 会自动传播给子图：

const subgraph = subgraphBuilder.compile(); // 不需要单独指定
const graph = builder.compile({ checkpointer }); // 父图指定即可

长期记忆

InMemoryStore + namespace = 跨线程的用户数据

import { InMemoryStore, StateGraph } from "@langchain/langgraph";

const store = new InMemoryStore();
const graph = builder.compile({ store });
import { v4 as uuidv4 } from "uuid";

// 在节点中访问 store
const callModel: GraphNode<typeof State> = async (state, runtime) => {
  const userId = runtime.context?.userId;
  const namespace = [userId, "memories"];

  // 搜索相关记忆
  const memories = await runtime.store?.search(namespace, {
    query: state.messages.at(-1)?.content,
    limit: 3,
  });
  const info = memories?.map((d) => d.value.data).join("\n") || "";

  // 存储新记忆
  await runtime.store?.put(namespace, uuidv4(), { data: "User prefers dark mode" });

  // 使用记忆增强模型调用...
};
调用时传入 context：await graph.invoke({ messages: [...] }, { configurable: { thread_id: "1" }, context: { userId: "1" } })。节点通过 runtime.context 获取。

语义搜索

用嵌入模型实现"模糊匹配"记忆

import { OpenAIEmbeddings } from "@langchain/openai";

const store = new InMemoryStore({
  index: {
    embeddings: new OpenAIEmbeddings({ model: "text-embedding-3-small" }),
    dims: 1536,
  },
});

// 存入记忆
await store.put(["user_123", "memories"], "1", { text: "I love pizza" });
await store.put(["user_123", "memories"], "2", { text: "I am a plumber" });

// 语义搜索——"我饿了" 匹配到 "I love pizza"
const items = await store.search(["user_123", "memories"], {
  query: "I'm hungry",
  limit: 1,
});
语义搜索 vs 精确匹配：没有嵌入模型时，search 只能精确匹配。加上嵌入模型后，"我饿了"也能找到"我爱吃披萨"——因为它们的语义相近。

管理短期记忆

消息越来越多时要控制——裁剪、删除、总结

裁剪消息

import { trimMessages } from "@langchain/core/messages";

const messages = trimMessages(state.messages, {
  strategy: "last",
  maxTokens: 128,
  startOn: "human",
  endOn: ["human", "tool"],
});

删除消息

import { RemoveMessage } from "@langchain/core/messages";

if (messages.length > 2) {
  return {
    messages: messages
      .slice(0, 2)
      .map((m) => new RemoveMessage({ id: m.id })),
  };
}

总结消息

把旧消息压缩成摘要，删除原始消息。保留最近几条 + 摘要作为上下文。

管理检查点

查看、遍历、清理线程数据

// 查看线程当前状态
await graph.getState({ configurable: { thread_id: "1" } });

// 遍历线程历史
for await (const state of graph.getStateHistory({ configurable: { thread_id: "1" } })) {
  console.log(state);
}

// 删除线程的所有检查点
await checkpointer.deleteThread("1");
注意：MemorySaver 的数据存在内存中。进程重启后所有检查点都会丢失。生产环境务必使用 PostgresSaver 等持久化后端。

排错指南

第二轮对话忘了上一轮

症状：换了 thread_id，之前的对话内容全没了。

修复：确保多轮对话使用同一个 thread_id。thread_id 不同 = 不同对话。

Store 搜索没有结果

症状：store.search() 返回空数组。

修复：检查 namespace 是否一致。put 和 search 必须用相同的 namespace 路径。

token 超限

症状：对话很长后报 context_length_exceeded。

修复：用 trimMessages 或 RemoveMessage 裁剪历史消息。别把所有消息都丢给模型。

动手练习

构建一个有记忆的聊天机器人

任务：基于 Ch04 的计算器智能体，添加记忆功能。
  • 加上 MemorySaver，让多轮计算能保持上下文
  • 加上 InMemoryStore，在节点中存储用户的计算偏好（比如"总是返回整数"）
  • 用 trimMessages 限制最多保留最近 10 条消息

参考答案

// 1. 添加 MemorySaver
const checkpointer = new MemorySaver();

// 2. 添加 InMemoryStore
const store = new InMemoryStore();

// 3. 编译时同时传入
const graph = builder.compile({ checkpointer, store });

// 4. 在 llmCall 节点中管理记忆
const llmCall: GraphNode<typeof State> = async (state, runtime) => {
  // 裁剪消息
  const messages = trimMessages(state.messages, {
    strategy: "last",
    maxTokens: 2000,
    startOn: "human",
  });

  // 读取用户偏好
  const userId = runtime.context?.userId;
  const prefs = await runtime.store?.search([userId, "prefs"], { limit: 3 });

  // ... 使用偏好增强模型调用
};
模式：checkpointer 管线程内记忆（对话历史），store 管跨线程记忆（用户偏好）。两者互不干扰，组合使用。
